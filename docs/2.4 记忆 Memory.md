## 1. 定位

Agent 核心层第 4 个知识点，属于“状态与经验管理”。  
它回答锚点核心问题：**状态如何持久化、检索与更新？**——Agent 在长任务、多步骤、跨会话运行中，如何保存、检索、更新与遗忘信息，保证决策的连贯与一致。

直接前置：1.5 记忆与上下文管理（窗口/摘要/压缩入门）、2.1 Agent 定义与范式（四件套公式里 Memory 的位置）。  
后续承接：2.5 执行循环（记忆的读写发生在每轮循环里）、2.8 多 Agent 协作（共享记忆）。  
与 1.5 的分工：1.5 解决“对话历史怎么塞进上下文窗口”；2.4 解决“Agent 的记忆系统怎么设计、怎么管”——多出写入/更新/遗忘一整条管线和跨会话持久化。

## 2. 一句话定义

Agent 记忆（Agent Memory），是 Agent 在运行过程中对状态、经验、知识进行编码、存储、检索、更新和遗忘的系统机制，使其具备跨步骤、跨会话、跨任务的信息保持与复用能力。

简化公式：

```text
Agent = LLM + Tools + Memory + Loop + Goal    （四件套见 2.1）
                  ↑
      没有记忆 = 每轮循环都换一位失忆症患者接班
```

## 3. 为什么需要

没有记忆的 Agent：

- **多步任务失忆**：第 3 步忘了第 1 步查到的订单号。
- **重复劳动**：已经查过的数据又查一遍，浪费成本。
- **无法从错误中学习**：上次工具失败，这次还犯。
- **跨会话无个性**：用户每次都要重新自我介绍。
- **状态不可恢复**：任务中断后，无法从断点继续。
- **无法积累经验**：做了 100 次任务，第 101 次还是新手。
- **冲突不自知**：用户说“我搬到上海了”，Agent 还在用北京地址。

三种方案的能力边界：

| 方案 | 多步任务 | 跨会话 | 经验积累 | 说明 |
|---|---|---|---|---|
| 只靠上下文窗口 | 容易丢中间结果 | 不行 | 不行 | 窗口一满就截断（见 1.5） |
| 窗口 + 摘要压缩 | 基本连贯 | 不行 | 不行 | 摘要只保住当前会话（见 1.5） |
| 完整记忆系统 | 连贯 | 可以 | 可以 | 写入/检索/更新/遗忘四机制齐备 |

**类比**：

```text
LLM        = 一个聪明的顾问，但每次见面前都失忆
LLM + 记忆 = 一个了解你历史、记得你偏好的长期助理
```

## 4. 核心原理

锚点问题“状态如何持久化、检索与更新”，正面答案落在记忆管理器的四个机制上：

| 机制 | 回答的问题 | 生产常用默认 |
|---|---|---|
| 写入（Write） | 何时记、记什么 | LLM 判断值得记才写，结构化落库 |
| 检索（Retrieve） | 何时取、取多少 | 每轮决策前按当前任务检索，分层注入 |
| 更新（Update） | 新旧冲突怎么办 | 置信度 + 时间戳定新旧，LLM 仲裁兜底 |
| 遗忘（Forget） | 何时删 | 衰减 + TTL + 容量上限 + 合规删除 |

下面先讲四类记忆（存什么），再逐个展开四个机制（怎么管）。

### 4.1 四类记忆：先借认知科学建立直觉

这组术语借自认知心理学，对应到日常经验很直观：

- **工作记忆**：心算 37 × 24 时脑子里暂存的中间数——容量极小，算完就忘。
- **情节记忆**：“上周三在那家湘菜馆吃饭被辣到”——记得事件本身，按时间线回忆。
- **语义记忆**：“成都是四川省会”——只记得事实，早忘了是哪次学会的。
- **程序记忆**：会骑自行车、会走退款流程——做过几次后不假思索。

统一对比（合并“按时间跨度”与“按内容类型”两个视角）：

| 类型 | 存什么 | 例子 | 存储位置 | 生命周期 | 读写方式 |
|---|---|---|---|---|---|
| 工作记忆 | 当前任务状态 | “已查到订单 12345” | 内存/Redis | 任务结束即清 | 程序直读直写，低延迟 |
| 情节记忆 | 具体事件经历 | “上周用户投诉过物流” | 向量库 | 长期 | 向量检索（见 0.7） |
| 语义记忆 | 事实与偏好 | “用户是 VIP 会员” | 关系数据库 | 长期 | 按 key 覆盖更新，常驻注入 |
| 程序记忆 | 技能与流程 | “退款要先验证订单” | 文件/代码 | 长期 | 很少写，按需加载 |

四者的沉淀关系：

```text
┌──────────────────────────────────────────┐
│  工作记忆（当前任务）                     │
│  ├─ 当前目标 / 已执行步骤                │
│  ├─ 中间结果 / 待办事项                  │
└──────────────────────────────────────────┘
              ↓ 沉淀
┌──────────────────────────────────────────┐
│  短期记忆（当前会话）                     │
│  ├─ 对话历史 / 用户意图变化 / 临时偏好   │
└──────────────────────────────────────────┘
              ↓ 提炼
┌──────────────────────────────────────────┐
│  长期记忆（跨会话）                       │
│  ├─ 情节记忆：历史事件                   │
│  ├─ 语义记忆：事实知识                   │
│  └─ 程序记忆：技能流程                   │
└──────────────────────────────────────────┘
```

### 4.2 工作记忆（Working Memory）

**定义**：当前任务执行过程中临时保存的信息。它就是 2.5 中 AgentState 的任务部分（goal/plan/step_results）；把工作记忆每步序列化保存，就是检查点（Checkpoint）——“状态如何持久化”最直接的答案。

**结构化表示**：

```json
{
  "goal": "分析销售下降原因",
  "plan": ["加载数据", "按月聚合", "按地区聚合", "对比", "生成报告"],
  "current_step": 2,
  "step_results": {
    "1": {"file": "sales.csv", "rows": 1000},
    "2": {"monthly": {"1月": 100, "2月": 80, "3月": 70}}
  },
  "constraints": {"max_budget": 5.0, "deadline": "5min"},
  "pending": ["按地区聚合", "对比", "生成报告"]
}
```

**特点**：

- 生命周期短，任务结束即清。
- 容量小，只保留当前任务相关。
- 读写频繁，要求低延迟。
- 结构化，便于程序处理。

**工程建议**：用结构化状态而不是自然语言存；每步执行后更新；持久化以支持中断恢复（见 2.5）。

### 4.3 情节记忆（Episodic Memory）

**定义**：具体事件和经历的记忆，按时间追加、按语义检索。

```json
[
  {
    "timestamp": "2024-01-15T10:30:00",
    "event": "用户投诉物流延迟",
    "context": {"order_id": "12345", "delay_days": 3},
    "outcome": "已补偿优惠券",
    "user_id": "u1"
  },
  {
    "timestamp": "2024-02-20T14:00:00",
    "event": "用户咨询退款",
    "context": {"order_id": "12346"},
    "outcome": "已退款",
    "user_id": "u1"
  }
]
```

**用途**：用户历史行为回顾、相似场景复用、冲突检测、个性化服务。

**检索**：向量查询 + 用户过滤，完整实现见 6.1 的 `retrieve_episodes`：

```python
def retrieve_episodes(query: str, user_id: str, top_k: int = 3):
    query_vec = embed(query)
    results = episode_collection.query(
        query_embeddings=[query_vec],
        n_results=top_k,
        where={"user_id": user_id},   # 用户隔离，防串号
    )
    return results["documents"][0]
```

### 4.4 语义记忆（Semantic Memory）

**定义**：事实和知识的记忆——用户画像、偏好、关系。

```json
{
  "facts": {
    "name": "张三",
    "city": "上海",
    "member_level": "VIP",
    "join_date": "2023-01-01"
  },
  "preferences": {
    "language": "中文",
    "response_style": "简洁",
    "contact_time": "晚上"
  },
  "relations": [
    {"subject": "张三", "predicate": "喜欢", "object": "咖啡"},
    {"subject": "张三", "predicate": "住在", "object": "上海"}
  ]
}
```

**特点**：结构化、可更新、跨会话持久化、支持冲突检测和基于关系的推理。

**更新必须留痕**（冲突处理的基础）：

```python
def update_fact(key: str, new_value: str):
    old_value = semantic.facts.get(key)
    if old_value and old_value != new_value:
        semantic.history.append({       # 变更历史，供回溯与审计
            "key": key, "old": old_value, "new": new_value,
            "timestamp": now(),
        })
    semantic.facts[key] = new_value
```

### 4.5 程序记忆（Procedural Memory）

**定义**：技能和流程的记忆——做过且验证有效的做法。

```json
{
  "skills": {
    "退款处理": [
      "验证订单存在",
      "检查退款时效",
      "计算退款金额",
      "发起退款",
      "通知用户"
    ]
  },
  "workflows": {
    "VIP 用户投诉": {
      "trigger": "用户等级 = VIP 且 投诉",
      "steps": ["优先处理", "升级主管", "24 小时内回复"]
    }
  }
}
```

**用途**：复用成功流程、避免重复规划（见 2.2）、保证一致性、加速执行。  
与 2.6 反思的关系：反思的结论只有沉淀为程序记忆，才会“下次不再犯”——否则同一个错会犯第三次。

### 4.6 写入机制：何时记、记什么

不是所有信息都值得记。写入按**触发时机**分四种：

| 触发时机 | 说明 | 成本 | 可见时延 | 适用 |
|---|---|---|---|---|
| 即时写入 | 每轮对话后立即提取 | 高（每轮一次 LLM 调用） | 秒级 | 高价值会话 |
| 批量写入 | 每 N 轮或定时汇总提取 | 低（调用摊薄） | 分钟级 | 长对话、日志类 |
| 会话结束写入 | 收尾时一次性提取 | 中 | 下次会话 | 通用默认 |
| 反思触发写入 | 任务复盘时写入经验 | 中 | 事件驱动 | 程序记忆（见 2.6） |

两个低成本替身：规则写入（“记住”“我喜欢”等关键词触发）与显式写入（用户主动要求记/忘）。

判断“值不值得记”交给 LLM（生产推荐）：

```python
EXTRACT_PROMPT = """从以下对话中提取值得长期记住的信息。

只提取：
- 用户偏好（喜欢/不喜欢什么）
- 重要事实（姓名、地址、会员等级）
- 长期目标（正在做什么）
- 关键事件（投诉、购买）

不要提取：
- 临时信息（今天天气）
- 无关闲聊
- 已经知道的信息

输出 JSON 数组：
[{"type": "preference|fact|goal|event", "content": "...", "confidence": 0.0-1.0}]

对话：
{conversation}
"""

async def extract_memories(conversation: str) -> list[dict]:
    response = await call_llm(EXTRACT_PROMPT.format(conversation=conversation), temperature=0)
    return json.loads(response)
```

**面试高频问法**：“多轮任务中 Agent 该记住什么、忘掉什么？怎么实现？”——共识口径：记“稳定、可复用、影响未来决策”的（偏好、关键事实、长期目标、关键事件、成功流程）；忘“临时、过期、与未来无关”的（闲聊、一次性中间值、过期事实）。实现上是三层组合：LLM 判断提取写入 + 语义记忆结构化存储 + TTL/衰减遗忘，缺一层都会退化（只写不删变噪音库，只删不判变失忆症）。

### 4.7 检索机制：何时取、取多少

| 策略 | 说明 | 适用 |
|---|---|---|
| 全量注入 | 所有记忆放 Prompt | 记忆极少时 |
| 检索注入 | 按当前问题检索 | 生产推荐 |
| 分层注入 | 画像常驻 + 事件检索 + 任务当前 | 复杂场景 |
| 摘要注入 | 长历史压成摘要 | 入门做法，见 1.5 |

检索触发时机：**每轮 LLM 决策前**，用“当前目标 + 最近一轮用户输入”作查询；不要等用户显式提起历史才检索。分层注入的组装顺序：

```text
System Prompt
  ↓ 追加：语义记忆（常驻，量小且总是相关）
  ↓ 追加：情节记忆（向量检索 top 3，按当前问题）
  ↓ 追加：工作记忆（当前任务状态，JSON）
  ↓ 追加：短期记忆（最近 N 轮原文）
完整代码见 6.1 的 build_context
```

**面试高频问法**：“Agent 记忆和 RAG 有什么区别？”——共识口径三点：

1. 服务对象不同：RAG 面向知识（全局共享的文档库，回答“世界是什么”，见 1.4）；记忆面向个体（按用户/会话/Agent 隔离，回答“我们之间发生过什么”）。
2. 数据生命周期不同：RAG 离线批量建索引、低频更新；内存在线增量写入，还要处理更新冲突与遗忘。
3. 架构不同：RAG = 索引 + 检索；记忆 = 写入/检索/更新/遗忘四机制 + 持久化。向量检索底座两边通用（见 0.7）。

### 4.8 更新机制：冲突怎么办

**更新场景**：用户搬家 → 更新地址；偏好变化 → 更新偏好；事件完成 → 标记完成。

**冲突处理三级策略**：

```python
def resolve_conflict(old: dict, new: dict) -> dict:
    # 策略 1：置信度优先
    if new["confidence"] > old["confidence"]:
        return new
    # 策略 2：时间优先（新的覆盖旧的）
    if new["timestamp"] > old["timestamp"]:
        return new
    # 策略 3：LLM 仲裁（两条都可信时判断语义）
    return llm_resolve(old, new)
```

```text
旧记忆：用户住在北京
新信息：用户说“我搬到上海了”
处理：更新为上海，记录变更历史（见 4.4 的 update_fact）
```

### 4.9 遗忘机制：何时删

**为什么遗忘**：容量限制、隐私合规（GDPR 被遗忘权）、过期信息、降低检索噪音。

| 策略 | 机制 | 典型参数（示意） |
|---|---|---|
| 时间衰减（Time Decay） | 分数随年龄指数下降，低于阈值不参与检索 | 半衰期 30 天 |
| 生存时间（TTL）到期 | 到期直接删除或归档 | 会话记忆 7-30 天 |
| 容量淘汰 | 超上限淘汰最低分（近似最近最少使用 LRU） | 每用户 1000 条 |
| 相关性衰减 | 检索命中加分、长期不命中降权 | 命中一次 +0.1 |
| 合规删除 | 用户要求删除含 PII 的记忆 | 即时、留审计日志 |

时间衰减实现：

```python
def decay_score(memory: dict, now: float) -> float:
    age_days = (now - memory["timestamp"]) / 86400
    importance = memory.get("importance", 1.0)
    return importance * (0.99 ** age_days)   # 半衰期约 69 天
```

### 4.10 记忆与 Agent 其他组件的关系

```text
┌──────────────────────────────────────────┐
│                 记忆                      │
│  ┌────────────────────────────────────┐  │
│  │  工作记忆  │  情节  │  语义  │  程序 │  │
│  └────────────────────────────────────┘  │
└──────────────────────────────────────────┘
       ↑            ↑           ↑
       │            │           │
   ┌───┴───┐   ┌───┴───┐   ┌───┴───┐
   │ 规划  │   │ 工具  │   │ 反思  │
   └───────┘   └───────┘   └───────┘
       │            │           │
       └────────────┴───────────┘
                    ↓
              ┌───────────┐
              │    LLM    │
              └───────────┘
```

- **规划**：从程序记忆读取技能，把计划写入工作记忆。
- **工具**：工具结果写入工作记忆和情节记忆。
- **反思**：从情节记忆读取失败案例，结论沉淀为程序记忆。
- **LLM**：从所有记忆读取，生成决策。

## 5. 架构 / 流程

一个生产级 Agent 记忆系统的读写路径（四机制全部落位）：

```text
┌──────────────────────────────────────────┐
│  写入路径（机制一：何时记）               │
│  对话/工具结果 → 值得记？→ 提取           │
│       ├─ 工作记忆：结构化状态             │
│       ├─ 短期记忆：对话历史               │
│       ├─ 情节记忆：事件向量               │
│       ├─ 语义记忆：事实库                 │
│       └─ 程序记忆：技能库                 │
└──────────────────────────────────────────┘
                  ↓
┌──────────────────────────────────────────┐
│  存储层（跨会话持久化）                   │
│  ├─ 工作记忆：内存/Redis（+检查点落盘）   │
│  ├─ 短期记忆：Redis                       │
│  ├─ 情节记忆：向量库                      │
│  ├─ 语义记忆：PostgreSQL                  │
│  └─ 程序记忆：文件/数据库                 │
└──────────────────────────────────────────┘
                  ↓
┌──────────────────────────────────────────┐
│  读取路径（机制二：何时取）               │
│  当前查询 → 分层检索 → 组装上下文         │
│       ├─ 语义记忆（常驻）                 │
│       ├─ 情节记忆（检索）                 │
│       ├─ 工作记忆（当前）                 │
│       └─ 程序记忆（按需）                 │
└──────────────────────────────────────────┘
                  ↓
┌──────────────────────────────────────────┐
│  LLM 决策 → 行动（回到 2.5 的执行循环）   │
└──────────────────────────────────────────┘
                  ↓
┌──────────────────────────────────────────┐
│  更新与遗忘（机制三、四）                 │
│  ├─ 新信息写入 / 冲突处理                 │
│  ├─ 时间衰减 / TTL / 容量淘汰             │
│  └─ 合规删除                             │
└──────────────────────────────────────────┘
```

## 6. 代码 / 工具

### 6.1 记忆管理器最小实现

四类记忆 + 四机制的落位（写入/检索/更新各留钩子，遗忘见 4.9）：

```python
import json
import uuid
from datetime import datetime
from openai import AsyncOpenAI
import chromadb

client = AsyncOpenAI(api_key="YOUR_KEY")

class AgentMemory:
    def __init__(self, user_id: str):
        self.user_id = user_id
        self.working = {"goal": None, "plan": [], "current_step": 0,
                        "step_results": {}, "pending": []}   # 工作记忆
        self.short_term = []                                  # 短期记忆
        self.facts = {}                                       # 语义记忆
        self.preferences = {}
        self.history = []                                     # 变更历史（更新机制）
        self.episode_collection = chromadb.Client().get_or_create_collection("episodes")

    # ========== 写入：工作记忆 ==========
    def set_goal(self, goal: str):
        self.working["goal"] = goal

    def set_plan(self, plan: list):
        self.working["plan"] = plan
        self.working["pending"] = plan.copy()

    def record_step(self, step_id: str, result):
        self.working["step_results"][step_id] = result
        if step_id in self.working["pending"]:
            self.working["pending"].remove(step_id)
        self.working["current_step"] += 1

    # ========== 写入：短期 / 情节 ==========
    def add_turn(self, role: str, content: str):
        self.short_term.append({"role": role, "content": content,
                                "timestamp": datetime.now().isoformat()})

    def add_episode(self, event: str, context: dict, outcome: str):
        self.episode_collection.add(
            documents=[event],
            metadatas=[{"user_id": self.user_id,
                        "context": json.dumps(context),
                        "outcome": outcome,
                        "timestamp": datetime.now().isoformat()}],
            ids=[str(uuid.uuid4())],
        )

    # ========== 更新：覆盖前留痕（见 4.8）==========
    def set_fact(self, key: str, value: str):
        old = self.facts.get(key, {}).get("value")
        if old and old != value:
            self.history.append({"key": key, "old": old, "new": value,
                                 "timestamp": datetime.now().isoformat()})
        self.facts[key] = {"value": value,
                           "timestamp": datetime.now().isoformat()}

    # ========== 检索：情节记忆（用户隔离）==========
    def retrieve_episodes(self, query: str, top_k: int = 3) -> list:
        results = self.episode_collection.query(
            query_texts=[query], n_results=top_k,
            where={"user_id": self.user_id},
        )
        return results["documents"][0] if results["documents"] else []

    # ========== 读取：分层注入（见 4.7）==========
    def build_context(self, query: str, system_prompt: str) -> list[dict]:
        messages = [{"role": "system", "content": system_prompt}]

        # 1. 语义记忆（常驻）
        if self.facts or self.preferences:
            facts_text = "\n".join(f"- {k}: {v['value']}" for k, v in self.facts.items())
            prefs_text = "\n".join(f"- {k}: {v}" for k, v in self.preferences.items())
            messages.append({"role": "system",
                             "content": f"用户信息：\n{facts_text}\n偏好：\n{prefs_text}"})

        # 2. 情节记忆（检索）
        episodes = self.retrieve_episodes(query)
        if episodes:
            messages.append({"role": "system",
                             "content": "相关历史事件：\n" + "\n".join(f"- {e}" for e in episodes)})

        # 3. 工作记忆（当前任务）
        if self.working["goal"]:
            messages.append({"role": "system",
                             "content": f"当前任务：\n{json.dumps(self.working, ensure_ascii=False)}"})

        # 4. 短期记忆（最近 10 轮）
        messages.extend(self.short_term[-10:])
        return messages

    # ========== 写入：LLM 提取（提示词见 4.6）==========
    async def extract_and_store(self, conversation: str):
        prompt = f"""提取值得长期记住的信息，输出 JSON：
{{"facts": [{{"key": "...", "value": "..."}}],
 "preferences": [{{"key": "...", "value": "..."}}],
 "episodes": [{{"event": "...", "outcome": "..."}}]}}

对话：
{conversation}
"""
        response = await client.chat.completions.create(
            model="gpt-4o-mini",
            messages=[{"role": "user", "content": prompt}],
            response_format={"type": "json_object"},
            temperature=0,
        )
        data = json.loads(response.choices[0].message.content)
        for fact in data.get("facts", []):
            self.set_fact(fact["key"], fact["value"])
        for pref in data.get("preferences", []):
            self.preferences[pref["key"]] = pref["value"]
        for ep in data.get("episodes", []):
            self.add_episode(ep["event"], {}, ep.get("outcome", ""))
```

### 6.2 使用示例

```python
async def main():
    memory = AgentMemory(user_id="u1")

    # 会话 1：用户自我介绍
    memory.add_turn("user", "我叫张三，是 VIP 会员，喜欢简洁回答")
    memory.add_turn("assistant", "你好张三！")
    await memory.extract_and_store("用户：我叫张三，是 VIP 会员，喜欢简洁回答")

    # 会话 2（新会话，记忆保留）
    memory.add_turn("user", "帮我查一下我的订单")
    messages = memory.build_context("查订单", "你是客服助手")
    # messages 中已包含：用户信息（张三、VIP）、偏好（简洁）
```

### 6.3 记忆框架：Mem0

截至 2026 年，社区常用的专用记忆框架是 Mem0（开源，2024 年发布后持续演进）：把“提取 → 去重 → 冲突更新 → 检索”四个机制打包，省去手写 6.1 的管线。

```python
from mem0 import Memory

m = Memory()

# 自动提取和存储（内置写入判断与冲突更新）
m.add("我叫张三，喜欢简洁回答", user_id="u1")

# 检索
results = m.search("用户偏好", user_id="u1")

# 全量导出（合规审计用）
all_memories = m.get_all(user_id="u1")
```

### 6.4 用 LangGraph 的 Checkpointer 做持久化

工作记忆/会话状态的持久化与中断恢复，编排框架已内置（见 2.5、3.3）：

```python
from langgraph.checkpoint.sqlite import SqliteSaver
from langgraph.graph import StateGraph

# 持久化工作记忆（生产用 Postgres/Redis 后端）
memory = SqliteSaver.from_connstring("checkpoints.db")

graph = StateGraph(AgentState)

app = graph.compile(checkpointer=memory)

config = {"configurable": {"thread_id": "user-123"}}
result = app.invoke({"messages": [...]}, config)
# 进程重启后用同一 thread_id 恢复，从断点继续
```

## 7. 案例

### 案例 A：多步数据分析的工作记忆

**任务**：“分析销售下降原因。”

**工作记忆演变**：

```text
Step 1 后：
{"goal": "分析销售下降", "step_results": {"1": {"file": "sales.csv", "rows": 1000}}}

Step 2 后：
{"step_results": {"1": {...}, "2": {"monthly": {"3月": 70, "2月": 80}}}}

Step 3 后：
{"step_results": {..., "3": {"region": {"华东": 30, "华北": 50}}}}

最终：
{"step_results": {..., "5": {"report": "..."}}, "pending": []}
```

**示意数字**：同一任务回归测试跑 10 次，无工作记忆版本平均 7.4 步（第 4 步常回头重查 sales.csv），有工作记忆版本平均 5.1 步，token 支出低约 30%。

**价值**：每步决策基于完整历史，不重复劳动。

### 案例 B：跨会话个性化

**会话 1**：

```text
用户：我叫张三，是 VIP，喜欢简洁回答
Agent：好的，张三！
[提取记忆：name=张三, level=VIP, style=简洁]
```

**会话 2**（一周后）：

```text
用户：帮我查订单
Agent：[读取记忆：张三，VIP，简洁回答]
     你的订单 12345 已发货。
```

**示意数字**：记忆条目积累到约 40 条（事实 15、偏好 8、事件 17）后，新会话不再要求自我介绍；内部满意度评分（5 分制）从 3.8 升到 4.5（示意量级）。

**价值**：无需重新自我介绍，体验连贯。

### 案例 C：从失败中学习（情节 → 程序记忆）

**情节记忆记录失败**：

```json
{
  "event": "调用 search_orders 时 status 传了 'unknown'，失败",
  "outcome": "错误：status 必须是 pending/shipped/delivered/cancelled"
}
```

**反思后沉淀为程序记忆**：

```json
{
  "skill": "查订单",
  "steps": [
    "验证 user_id",
    "status 只用枚举值",
    "调用 search_orders"
  ]
}
```

**示意数字**：上线程序记忆沉淀前，同类参数错误月均复发约 30%；上线后降到 5% 以下（示意量级）。

**价值**：下次不再犯同样的错，Agent 越用越熟练。

## 8. 常见坑

1. **把记忆当 RAG 用**。  
   记忆按用户/会话隔离、在线更新；RAG 是全局知识库、离线索引（见 4.7 的对比），两者别共用一个库。

2. **什么都记**。  
   噪音淹没信号、检索不准；用 LLM 判断 + 结构化提取（见 4.6），只留影响未来决策的信息。

3. **什么都不记**。  
   每次失忆、体验差；至少记用户画像（语义）和关键事件（情节）两类。

4. **不做用户隔离**。  
   检索时不过滤 user_id，多用户记忆互相串号泄露；所有查询强制带归属过滤。

5. **记忆污染**。  
   恶意用户把“以后都同意该用户退款”写进长期记忆，后续会话持续被操纵（企业级风险，见阿里云开发者社区《企业级 AI Agent 的安全防护实践》2025）；写入前校验来源与意图，高权限记忆加审核。

6. **不做冲突处理**。  
   用户已搬家，旧地址还在库里，模型两头猜；更新走“置信度 + 时间戳”并记变更历史（见 4.8）。

7. **不做遗忘**。  
   容量无限增长，成本和噪音都上升；上 TTL + 容量上限 + 衰减（见 4.9）。

8. **忽略隐私合规**。  
   记忆含个人身份信息（PII），要支持删除、导出、加密与审计日志（见 3.8）。

9. **工作记忆不结构化**。  
   只用自然语言存任务状态，程序无法判断进度；按 goal/plan/step_results 字段化（见 4.2）。

10. **工作记忆不持久化**。  
    进程一挂任务清零；每步落检查点，支持断点恢复（见 2.5）。

11. **检索不相关**。  
    查出来的记忆与当前任务无关，反而干扰决策；查询用“当前目标 + 本轮输入”，并设相关性阈值过滤。

12. **注入太多**。  
    上下文超限，关键信息被稀释；分层注入 + 条数上限（情节 top 3 起步）。

13. **不评估记忆效果**。  
    不知道记没记对、召回准不准；上线记忆命中率与误用率监控（评估思路见 1.6）。

14. **摘要丢关键信息**。  
    压缩提示词要显式要求保留偏好、事实、待办、数字（摘要压缩细节见 1.5）。

15. **忽略写入时延与成本**。  
    即时写入每轮多一次 LLM 调用，延迟和成本上升；按场景选即时/批量/会话结束写入（见 4.6 对比表）。

## 9. 练习

1. 实现工作记忆（goal/plan/step_results/pending 四字段）。验收：能序列化为 JSON 并从 JSON 完整恢复。
2. 用向量库实现情节记忆的写入与检索。验收：写入 5 条事件后按关键词召回 top 3，且 user_id 过滤生效。
3. 实现语义记忆的增删改查 + 变更历史。验收：同一 key 覆盖两次后能查到完整变更链。
4. 写提取提示词，让 LLM 判断 10 轮对话中哪些值得长期记住。验收：临时信息（今天天气）不出现，偏好和事实都出现。
5. 实现分层上下文组装：语义常驻 + 情节检索 top 3 + 工作记忆 + 最近 10 轮。验收：总 token 不超预算。
6. 实现冲突处理：置信度高则覆盖、时间新则覆盖、都不可靠则 LLM 仲裁。验收：搬家场景正确更新并留痕。
7. 实现时间衰减打分（半衰期 30 天）。验收：90 天前的记忆分数低于 30 天前的。
8. 给记忆系统加用户隔离与“一键删除该用户全部记忆”。验收：删除后检索为空且留审计日志。
9. 用 SQLite 给工作记忆做检查点持久化。验收：进程重启后从断点步骤继续，不重复已完成步骤。
10. 对比有/无记忆 Agent 在同一 5 轮任务上的工具调用次数与 token 花费，输出对比表。

## 10. 小结

- Agent 记忆 = **工作记忆 + 短期记忆 + 长期记忆（情节/语义/程序）**，四类分工见 4.1 对比表。
- 工作记忆：**当前任务状态，结构化、低延迟、每步持久化为检查点**。
- 情节记忆：**事件流水，向量化存储、按当前问题检索**。
- 语义记忆：**事实与偏好，按 key 覆盖更新、常驻注入**。
- 程序记忆：**技能与流程，复用成功经验、承接反思产出**。
- 四机制回答锚点问题：**写入看时机（即时/批量/会话结束/反思触发），检索看触发（每轮决策前分层取），更新看冲突（置信度 + 时间戳 + LLM 仲裁），遗忘看策略（衰减/TTL/容量/合规）**。
- 读取口诀：**语义常驻、情节检索、工作记忆当前、短期窗口兜底**。
- 记忆与 RAG 一句话区分：**RAG 管全局知识，记忆管个体经历；记忆多一套写入/更新/遗忘管线**。
- 核心原则：**记忆为决策服务，不是越多越好——每条记忆都要能回答“它让哪个决策变好了”**。
- 这些能力直接支撑：2.5 执行循环与状态机、2.7 单 Agent 架构模式、2.8 多 Agent 协作（共享记忆）。
