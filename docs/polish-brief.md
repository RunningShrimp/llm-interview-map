## 2. 标准 10 节结构（节名与顺序，一字不改）

```markdown
# 讲解 <编号> <锚点名>

> 说明：<2-3 行，交代前置是什么、本篇聚焦什么、后续在哪展开，用编号指路>

---

## 1. 定位          ← 本锚点解决的核心问题 + 在层中的角色 + 直接前置/后续编号
## 2. 一句话定义     ← 一句严密的定义；可选「简化公式」text 块
## 3. 为什么需要     ← 痛点清单（加粗短语+箭头解释）+ 对比表或类比块
## 4. 核心原理       ← 4.1/4.2… 小节，机制讲透：推导步骤、对比表、text 示意
## 5. 架构 / 流程    ← 至少 1 个 text 或 mermaid 结构/流程图（box-drawing 风格）
## 6. 代码 / 工具    ← ≥2 段代码（Python/JSON/YAML/bash/text 均可），注释用中文
## 7. 案例          ≥2 个（建议 3 个）：场景 + 做法 + 示意性数字效果
## 8. 常见坑         8-16 条编号列表：**加粗现象一句** + 对策一句
## 9. 练习          6-10 条动手练习（由易到难）
## 10. 小结         8-12 条要点 bullets，末条为「这些能力直接支撑：<编号+名>」
```

例外：`0.0 roadmap.md` 保持自身三节结构（文本大纲 / Mermaid 导图 / 知识卡片），仅做纠错与一致性维护，不套 10 节。

## 3. 风格基准（以 1.4 / 2.5 / 3.7 为范文）

1. 语气：直接、密度高、面向面试与工程实战的教学口吻；深入浅出；**禁止**「我们可以」「接下来让我们」「值得注意的是」等口水话；禁止 emoji；禁止感叹号营销腔。
2. 术语：中文为主，**术语首次出现给英文**（如：重排（Rerank））；全篇同一概念用同一词（不混用「大模型/基座模型/LLM」除非刻意区分）。统一用词：提示词（Prompt）、检索增强生成（RAG）、工具调用（Function Calling / Tool Use 并列出现时保留原文）、智能体不使用——一律用 Agent。
3. 类比密度：每篇 ≥2 个生活类比，**具体到场景**（如「没有状态机 = 没有工序卡的工厂，工人凭感觉干活；有状态机 = 每道工序有质检点」），拒绝空泛类比。
4. 配比：表格 ≥3 个（对比表/参数表/指标表/失败模式表）；代码块 ≥2 个；正文行数与代码行数比例约 1:1 上下；机制讲解处「能上表就上表」。
5. 数字口径：案例中的数字是**示意性量级**（写成真实工程复盘口吻），不得虚构公司真名（用「某电商」「一家金融科技公司」）；不得编造论文编号、面试原题出处。
6. 链接：不放裸 URL 外链；来源以文字标注（框架/论文/官方文档名 + 年份）。存疑新趋势标注「趋势观察」，无法核实的标注「未核实」，禁止把趋势写成定论。

## 4. 深度优化清单（各节常见问题 → 改进手法）

| 节 | 常见问题 | 改进手法 |
|---|---|---|
| 说明/1.定位 | 缺衔接、未提依赖 | 按 rodmap 卡片补「前置 X.Y → 本篇 → 后续 X.Y」 |
| 2.一句话定义 | 定义含糊或过长 | 压到一句；补「简化公式」text 块 |
| 3.为什么需要 | 只有清单无对比 | 补「不做会怎样」反例 + 微调/RAG 式对比表 |
| 4.核心原理 | 只列概念不讲机制 | 每个机制补：输入→处理→输出推导、或双栏对比表、或 text 示意 |
| 5.架构/流程 | 纯文字 | 画 box-drawing 分层图或 mermaid（flowchart/stateDiagram） |
| 6.代码/工具 | 伪代码不可运行感 | 补关键 import、参数默认值、中文注释；示例贴近生产 |
| 7.案例 | 只有 1 个或无数字 | 补到 ≥2 个；每个有 场景→做法→示意数字效果 三段 |
| 8.常见坑 | 条目缺对策 | 统一「现象 + 对策」两句式；补足到 ≥8 条 |
| 9.练习 | 太笼统 | 改成可动手、可验收的具体任务（「实现 X，对比 Y」） |
| 10.小结 | 罗列无提炼 | 每条是可带走的结论；末条挂前向支撑编号 |

补充：**面试视角**——在 §4 或 §8 适当位置补 1-2 处「面试高频问法」表述（如「面试常问：X 与 Y 的取舍」），以业界共识口径陈述，不虚构面经来源。
