## 3. 为什么需要

跳过阶段 0 直接学 Agent 开发，会遇到：

- **看不懂文档**：词元（token）、上下文窗口（Context Window）、嵌入（Embedding）、温度（temperature）全是黑话。
- **调不通 API**：不会处理异常、超时、限流（Rate Limit，典型如 429）、环境变量（Environment Variable）。
- **写不出工程代码**：所有逻辑堆在一个文件，改一处坏三处，无法维护。
- **不理解模型行为**：为什么会有幻觉（Hallucination）？为什么同一问题两次回答不一样？
- **不会评估**：不知道回答好不好，只能凭感觉。
- **进不了下一阶段**：检索增强生成（RAG，Retrieval-Augmented Generation）、Agent、工程化全部建在 0 层之上。

“跳过 vs 先过”对比：

| 维度 | 跳过阶段 0 直接学 Agent | 先过阶段 0 再进阶 |
|---|---|---|
| 读文档 | 每个术语现场查，读 2 层各篇举步维艰 | 术语是母语，直接吸收方案层内容 |
| 写代码 | 一个脚本跑到底，无类型无测试 | 有配置、日志、测试、项目结构 |
| 排查错误 | 只会 print，429 一脸懵 | 看日志定位，知道限流要退避重试 |
| 成本意识 | 不知 token 怎么计费，账单失控 | 发请求前能估 token 与成本 |
| 整体速度 | 前两周快，之后处处卡壳、反复返工 | 慢启动两三周，之后越走越快 |

两个类比，具体到场景：

```text
考驾照：阶段 0 = 交规 + 认仪表盘 + 空场地练打方向盘；直接学 Agent = 无证上路，
        短期能挪车，一遇复杂路况（限流、幻觉、超长上下文）就出事故。
做菜：  0.1–0.7 = 认食材 + 练刀工 + 掌火候；问答 CLI = 第一道完整的菜（蛋炒饭）。
        没练过刀工也能炒到“能吃”，练过之后才做得出“能上桌”。
```

### 4.5 里程碑自检表：本阶段学完能做什么

把里程碑“能解释 token、上下文、温度、幻觉；能发请求并处理返回”拆成可逐项打分的自检表，全部达到合格口径才算通过：

| 自检项 | 合格口径 | 不合格信号 | 对应锚点 |
|---|---|---|---|
| 解释 token | 文本被切成子词单元、按 token 计费；能举例说明中文通常比英文费 token | 只会说“一个字就是一个 token” | 0.5 |
| 解释上下文窗口 | 输入与输出共享窗口；超限会被截断或直接报错 | 以为窗口只算输入不算输出 | 0.5 |
| 解释温度 | 温度控制采样随机性：事实问答与工具调用用低温，创作用高温 | 只会说“调创造力的旋钮” | 0.5 |
| 解释幻觉 | 自回归（Autoregressive）生成只保证“像”，不保证“真”；模型还有知识截止时间 | 以为模型联网、什么都知道 | 0.5 |
| 发请求 | 能用官方 SDK 发一次对话请求并取回正文 | 只会用网页版聊天 | 1.1 |
| 处理返回 | 能区分 429、超时、401 并分类处理（可重试才重试） | 遇错一律 try/except 全吞 | 0.2、1.1 |

配套的 10 个关键问题（口头全部答清即达标）：

1. token 是什么？为什么中文比英文费 token？
2. 上下文窗口是什么？超了会怎样？
3. 温度是什么？什么时候用 0，什么时候用 1？
4. 幻觉是什么？为什么会产生？
5. 嵌入是什么？余弦相似度怎么算？
6. RAG 的基本流程是什么？
7. 如何调用 LLM API？如何处理 429？
8. 如何写一个可维护的 Python 项目？
9. 如何评估提示词的好坏？
10. 如何防止基础提示注入（Prompt Injection）？

**面试高频问法**：阶段 0 学完，以下三问应能给出共识口径的回答——“温度设 0 输出就完全确定吗？”（温度 0 近似贪心解码（Greedy Decoding），输出基本稳定，但仍受采样实现与浮点影响，不承诺逐字节一致）；“中文为什么比英文费 token？”（分词器（Tokenizer）词表以英文子词为主，中文常被切成单字甚至多字节，同义内容的 token 数更高）；“幻觉能根除吗？”（不能根除，只能降低：检索增强、约束提示、事实校验与引用是主要手段，系统方案见 1.4 与 2.6）。

### 4.6 高频卡点与解法速查

| 卡点 | 典型症状 | 第一时间解法 | 深入锚点 |
|---|---|---|---|
| 环境混乱 | 装包冲突、pip 报版本互相覆盖 | 每个项目独立虚拟环境（venv/uv），不污染全局 | 0.2 |
| API Key 管理不当 | Key 硬编码、误提交到仓库 | 环境变量 + .env + .gitignore，泄露立即吊销重建 | 0.2 |
| 429 限流 | 连续调用报 Too Many Requests | 指数退避（Exponential Backoff）重试，必要时降并发 | 0.2、1.1 |
| 回答不稳定 | 同一问题两次答案不同 | 事实类任务温度设 0，提示词写清“只依据给定信息” | 0.5、0.6 |
| 输出格式失控 | 拿不到预期的结构 | 提示词中给显式格式约束 + 少样本（Few-shot）示例 | 0.6 |
| token 账单恐慌 | 不知道一次对话花多少 | 发请求前用分词器数 token，给自己设日预算上限 | 0.5 |
| 数学劝退 | Softmax、梯度看不懂就弃学 | 先跳过继续往前走，回填时只学与 LLM 直接相关的部分 | 0.1 |
| 学完就忘 | 看懂了但动手就不会 | 每个知识点强制配一个可运行产出，用项目串联 | 本篇 §9 |

### 6.3 迭代二：配置收离 + 可重试的调用封装

配置不再硬编码；调用封装区分“可重试”与“不可重试”。

```python
# config.py —— 缺 Key 时启动即报错，而不是运行到一半才炸
from pydantic_settings import BaseSettings, SettingsConfigDict

class Settings(BaseSettings):
    model_config = SettingsConfigDict(env_file=".env")

    openai_api_key: str          # 必填：从 .env 的 OPENAI_API_KEY 读取
    base_url: str | None = None  # 可选：兼容 OpenAI 接口规范的中转/其他服务商
    model: str = "gpt-4o-mini"   # 示例值，选型见 1.1
    temperature: float = 0.7
    max_tokens: int = 1024
    max_retries: int = 3
    timeout: float = 30.0

settings = Settings()
```

```python
# llm.py —— 指数退避重试：429/超时/5xx 重试，401 等立刻失败
import asyncio
from openai import AsyncOpenAI, APIStatusError, APITimeoutError, APIConnectionError
from config import settings

client = AsyncOpenAI(
    api_key=settings.openai_api_key,
    timeout=settings.timeout,
    **({"base_url": settings.base_url} if settings.base_url else {}),
)

async def chat(messages: list[dict]) -> str:
    """发一次对话请求，返回模型正文；可重试错误退避后重试，最多 max_retries 次。"""
    for attempt in range(settings.max_retries):
        try:
            response = await client.chat.completions.create(
                model=settings.model,
                messages=messages,
                temperature=settings.temperature,
                max_tokens=settings.max_tokens,
            )
            return response.choices[0].message.content
        except (APITimeoutError, APIConnectionError, asyncio.TimeoutError):
            if attempt == settings.max_retries - 1:
                raise
            await asyncio.sleep(2 ** attempt)  # 退避：1s → 2s → 4s
        except APIStatusError as e:
            retryable = e.status_code == 429 or e.status_code >= 500
            if retryable and attempt < settings.max_retries - 1:
                await asyncio.sleep(2 ** attempt)  # 限流/服务端错误：可重试
            else:
                raise  # 401/403/400 等：重试无意义，立刻暴露真实错误
```

### 6.4 迭代三：多轮记忆 + 日志 + 主循环

```python
# memory.py —— 滑动窗口记忆：只保留最近 max_turns 轮，防止撑爆上下文窗口
class Memory:
    def __init__(self, max_turns: int = 5):
        self.max_turns = max_turns
        self._messages: list[dict] = []

    def add(self, role: str, content: str) -> None:
        self._messages.append({"role": role, "content": content})

    def get_messages(self) -> list[dict]:
        # 一轮 = user + assistant 两条消息
        return self._messages[-self.max_turns * 2:]
```

```python
# cli.py —— 主循环：把配置、客户端、记忆、日志拼成完整 CLI
import asyncio
from llm import chat
from memory import Memory
from logger import get_logger

logger = get_logger()
SYSTEM_PROMPT = "你是一个简洁、准确的中文助手；不确定的内容要明确说不确定。"  # 写法见 0.6

async def main() -> None:
    memory = Memory(max_turns=5)
    print("LLM 问答 CLI（输入 quit 退出，输入 reset 清空记忆）")

    while True:
        user_input = input("\n你: ").strip()
        if user_input.lower() == "quit":
            break
        if user_input.lower() == "reset":
            memory = Memory(max_turns=5)
            print("（已清空对话记忆）")
            continue
        if not user_input:
            continue

        memory.add("user", user_input)
        messages = [{"role": "system", "content": SYSTEM_PROMPT}] + memory.get_messages()
        logger.info("发送 %d 条消息", len(messages))

        try:
            answer = await chat(messages)
            memory.add("assistant", answer)
            print(f"\n助手: {answer}")
        except Exception as e:
            logger.error("调用失败: %s", type(e).__name__)
            print(f"\n[出错] {type(e).__name__}: {e}（详见 qa.log）")

if __name__ == "__main__":
    asyncio.run(main())
```

## 8. 常见坑

1. **只学不练**。对策：每个知识点强制配一个可运行产出，看课时间不超过编码时间。
2. **跳过 Python 工程**。对策：0.2 的类型、配置、异常、测试至少过一遍再写项目，否则后面 Agent 代码无法维护。
3. **追求最新工具**。对策：先把 token、上下文、温度、重试这些稳定概念打牢，工具选型交给 1.1，换工具不换概念。
4. **不理解 token 和成本**。对策：发请求前先用分词器数 token、按单价估算，给自己设日预算上限。
5. **不理解温度**。对策：事实问答与工具调用场景温度用 0 或接近 0，创作场景再调高。
6. **不理解幻觉**。对策：把模型输出当“待验证的草稿”，关键事实要求给出处；系统性缓解见 1.4。
7. **API Key 硬编码**。对策：一律环境变量 + .env + .gitignore；一旦泄露立即吊销重建。
8. **重试不分类型**。对策：区分可重试（429/超时/5xx）与不可重试（401/400），可重试的用指数退避，见 0.2。
9. **不写 README**。对策：按“环境—安装—运行—测试”四段写清，别人克隆后 10 分钟内跑起来才算合格。
10. **不做验收**。对策：对照 §4.5 自检表逐项打分，不合格项回到对应锚点补课。
11. **不记录问题**。对策：建一个 blockers.md 记“现象/原因/解法”，复习时优先过它，避免同一个坑踩两遍。
12. **过早进入 Agent**。对策：里程碑未达标不进 5.2——能解释、能写、能跑、能复现，四项齐了再走。
13. **忽略测试**。对策：至少给 chat 封装与 Memory 写单元测试，每次改代码后跑一遍。
14. **忽略日志**。对策：每次请求记模型、消息数、结果状态，出问题先看 qa.log 再改代码。

## 10. 小结

- 阶段 0 = **理解 LLM + 能调 API + 能写工程代码 + 能跑通项目**，对应知识地图 0.1–0.7。
- 组队顺序：**0.2 → 0.5 → 0.6 → 1.1（首次调用）→ 0.7**，数学与 ML/DL 按需回填——先会用再理解，先工程后理论。
- 里程碑口径：**能解释 token、上下文、温度、幻觉；能发请求并处理返回**，逐项对照 §4.5 自检表打分。
- 最小项目：**LLM 问答 CLI**，按四个迭代交付——跑通调用、配置与重试、记忆与主循环、测试与 README。
- 时间预算：**零基础 6–8 周，有 Python 基础 1–2 周**；每天 1–2 小时、每 2 周一个可运行产出的节奏最稳。
- 高频卡点集中在**环境、Key 管理、429 限流、输出不稳定**四类，解法见 §4.6 速查表。
- 学完即具备三道高频面试题的共识口径：温度 0 是否完全确定、中文为何费 token、幻觉能否根除。
- 验收不合格不硬闯：**能解释、能写、能跑、能复现**，四项齐了才进下一阶段。
- 这些能力直接支撑：**5.2 阶段 1：LLM 应用入门**（稳定调用、结构化输出、基础评估）。
