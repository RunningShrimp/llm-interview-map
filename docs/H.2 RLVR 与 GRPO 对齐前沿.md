## 1. 定位

前沿层（H）第 2 个锚点，星级 4，直接前置 0.5（LLM 基础中的 RLHF/DPO 子点）。

站点状态口径：**面试出现中**——面灵 AI《265 道 2026 版》题库设「RLHF 与 GRPO」专项分类；英文侧出现直接面试向文章《RLVR vs RLHF: Why Verifiable Rewards Win in 2026》（techinterview.net，2026）；GRPO/RLVR 已成 2026 年 LLM 训练岗标准叙事（Raschka「State of LLMs 2026」演讲）。

它回答训练岗与 Agent 岗共同的高频题：**GRPO 相比 PPO 砍了什么、省了什么、丢了什么？RLVR 和 RLHF 的本质区别与边界在哪？**

四个支柱：

1. **奖励源**：RLVR 用程序判对错，替代人类偏好打分与奖励模型。
2. **优势估计**：GRPO 用组内相对优势，替代 PPO 的价值网络（critic）。
3. **争议**：RLVR 到底激发新能力，还是只提升已有能力的采样率。
4. **风险与工程**：reward hacking、稀疏奖励、训练循环与监控的实战口径。

前置与延伸：0.5 的 PPO 四模型结构是理解「砍价值网络」的前提；H1 是推理模型的使用侧，本篇是它的引擎室；涌现出的反思行为与 2.6 的反思机制互为镜像，提示词侧的思维链（Chain-of-Thought，CoT）见 1.2，评测口径见 2.9 与 1.6，代码判卷依赖的沙箱见 H8。

对应用工程师这不是旁观知识：推理模型的行为边界（反思、长链、算力分配）都是 RL 练出来的，选型、提示、评测三个环节都要懂训练侧才能做对（4.8 展开）。

## 2. 一句话定义

RLVR（Reinforcement Learning with Verifiable Rewards，可验证奖励强化学习）用程序判定的客观对错——数学验答案、代码跑测试、格式查规则——替代人类偏好作为奖励；GRPO（Group Relative Policy Optimization，组相对策略优化）对同一问题采样一组回答，用组内奖励的均值和标准差做标准化得到相对优势，从而砍掉 PPO 的价值网络；两者合流构成 DeepSeek-R1 式推理模型的对齐引擎。

简化公式：

```text
推理模型对齐引擎 = RLVR（奖励源：程序判卷，近零成本、绝对一致）
                + GRPO（优化器：组内相对优势，免 critic、更稳）
```

## 3. 为什么需要

先复盘 0.5 的结论：RLHF 的在线标准实现是 PPO（Proximal Policy Optimization，近端策略优化），训练时同屏维护四个模型——策略模型（被训练的 LLM）、参考模型（冻结，供 KL 约束）、奖励模型（Reward Model，学人类偏好）、价值模型（critic，预测期望回报当基线）。这套结构对齐「礼貌得体的对话」够用，对齐「推理」时暴露三个结构性痛点：

1. **奖励模型被钻空** → 奖励模型是人类品味的代理，不是对错本身；策略模型会找到它的高分盲区疯狂输出（reward hacking，奖励投机的主要根源），数学推导错得离谱也可能因为「看起来像好答案」而拿高分。
2. **训练不稳** → critic 与策略同规模、同步训练，两个网络互相追赶（非平稳目标）；价值估计一偏，优势方向就错，梯度把策略带进沟里；超参敏感，大规模长链推理下更难稳。
3. **资源重** → 四个模型同屏，critic 与策略同规模——7B 策略就要再养一个 7B critic，加上优化器状态显存近乎翻倍，大规模 RL 的硬件账算不过来。

类比赛跑：PPO 是带着一个「预言家」（critic）跑——每份卷子先问预言家「这题该得几分」，预言家自己也要训练、也会说错；GRPO 是「同题组内互相比」——同一道题交 G 份卷子，同伴均分就是基准线，不用养预言家。

推理任务恰好有一个 RLHF 缺失的性质：**结果可验证**。数学题对答案、代码跑测试，判卷零成本且绝对公正。模型刷题量越大、判卷越快，推理越强——「标准化考试 + 自动判卷」让 RL 的数据飞轮第一次真正转起来：RLHF 时代数据贵在标注，RLVR 时代数据只贵在找题。

| 维度 | RLHF（人类偏好） | RLVR（可验证奖励） |
|---|---|---|
| 奖励来源 | 人类排序 → 训练奖励模型 | 程序判定（答案/测试/格式） |
| 判分成本 | 高（标注 + 奖励模型推理） | 近零（跑代码/对答案） |
| 判分一致性 | 有噪声、会漂移 | 确定、可复现 |
| 覆盖领域 | 全域（含开放对话） | 仅结果可验证域（数学/代码/格式） |
| 主要风险 | 奖励模型被讨好（sycophancy，迎合） | 判分器被钻空（reward hacking） |
| 可扩展瓶颈 | 标注预算 | 算力（题库 + 采样吞吐） |
| 代表成果 | InstructGPT、ChatGPT | DeepSeek-R1、o 系列训练叙事 |

一个值得准备的追问：RLVR 的思想并不新（拿数学题判对错做训练一直在做），为什么 2025 年才爆发？三个条件在彼时同时成熟：

1. **基座能力过线**：预训练模型「偶尔能做对」难题是 RL 放大的前提——pass 率为零的题刷不出信号，基座强了可验证任务才有梯度。
2. **工程成本到位**：vLLM 类高吞吐推理引擎让大规模组采样的成本可承受（训练瓶颈在采样不在更新）。
3. **配方公开**：DeepSeekMath 论文提出 GRPO（arXiv 2402.03300，2024），R1 公开全套流水线与训练细节（2025），Tulu 3（AI2）把可验证奖励确立为开源后训练标准阶段之一——「标准化考试 + 自动判卷 + 组内排名」从独家秘方变成可复现配方。

另一个高频混淆：RLVR 不是微调（SFT）。SFT 是模仿——给标准答案让模型学「长什么样」，上限是数据里见过的解法；RLVR 是筛选——只判对错、不给示范，让模型自己摸索出「能拿分的做法」，可能长出数据里没写过的行为（H1 的反思涌现即证据）。面试口径一句话：**SFT 教格式，RLVR 练行为。**

「不做会怎样」的反例——如果坚持用 RLHF 对齐推理，只有三条妥协路，条条走不通：

```text
妥协 1：让标注员判证明题 → 判不动、判错率高，奖励模型学到的偏好与正确性弱相关
妥协 2：只对齐可判的对话风格 → 推理能力原地踏步，得到「礼貌但不会做题」的模型
妥协 3：用 LLM 裁判判对错 → 裁判自己会错、还会被策略模型讨好，hack 风险回归
```

一句话：不是 RLHF 不努力，是「人类偏好」这个信号源对推理任务天然失配——信号源换掉（RLVR）比对信号源修修补补更根本。

## 4. 核心原理

### 4.1 RLVR：可验证奖励的三类判据

```text
数学：抽取最终答案（如 \boxed{}）→ 与标准答案规范化比对 → 0 / 1
代码：生成代码 → 在沙箱跑单元测试（含隐藏测试）→ 通过率得分
格式：检查答案是否落在约定区段/协议 → 小权重辅助分
```

| 任务域 | 判据 | 判分实现 | 备注 |
|---|---|---|---|
| 数学推理 | 最终答案正确性 | 符号等价比对、数值容差 | 过程不管，只看结果（结果奖励） |
| 代码生成 | 测试通过率 | 沙箱执行 pytest/自测用例 | 需隐藏测试防背题 |
| 指令跟随格式 | 结构协议 | 正则/解析器 | 小权重，防喧宾夺主 |
| 真实性核查 | 可交叉验证的事实 | 检索一致性/引用可回溯 | 部分可验证，扩展方向 |

设计要点：

1. **结果奖励为主**：不评判过程好坏，只判定结果——这正是推理行为能自由涌现的前提（H1 的 aha moment：没人规定过程长什么样，模型才有空间自己发现「再检查一遍」能涨分）。
2. **辅助奖励做约束**：语言一致性（R1 用它修中英混杂）、格式合法性、长度惩罚，都用小权重。
3. **可验证性是边界**：开放对话、创意写作没有程序判据，仍需偏好类方法——RLVR 与 RLHF 是分工不是替代，边界细节见 4.5。

奖励设计的四条实战原则（判分器写得糙，训练必翻车）：

1. **主判据要难作弊**：答案比对优先用规范化 + 符号等价，字符串相等会被同义改写骗过。
2. **辅助奖励要小且正交**：格式、语言一致性权重压在 0.1 量级，且监控它与主判据的相关性——相关性异常升高说明模型在学格式不学推理。
3. **判分器要版本化**：改判分规则等于改奖励函数，历史 reward 曲线跨版本不可比，必须记录。
4. **留人工审计通道**：每组随机抽 1% 高分样本人工看，「高分但可疑」是 reward hacking 的最早信号。

### 4.2 从 PPO 到 GRPO：组内相对优势与砍价值网络

PPO 的优势（Advantage）估计依赖 critic：价值网络预测期望回报当基线，优势 = 实际奖励 − 基线（工程上配 GAE，Generalized Advantage Estimation，广义优势估计做平滑）。critic 与策略同规模，自己也是被训练的网络。

GRPO 的替代一行说清：**对同一 prompt 采样一组（group size，组大小 G 条）回答，组平均分就是基线。**

```text
对每个问题 q：
  1. 从旧策略采样一组回答 {o_1, ..., o_G}（G 为组大小，
     DeepSeekMath 论文取 64，工程实现常见 4–16）
  2. 判卷：r_i = reward(q, o_i)              ← RLVR 提供判分器
  3. 标准化：A_i = (r_i − mean(r)) / std(r)  ← 组相对优势
  4. 更新：高于均值的回答提升采样概率，低于均值的抑制
     （带 clip 的策略梯度 + 对参考模型的 KL 约束）
```

手算一遍（G=4，奖励 [1.0, 0.0, 1.0, 0.2]，mean=0.55，std 约 0.456）：

| 回答 | 奖励 r | r − mean | 组相对优势 A | 更新方向 |
|---|---|---|---|---|
| o1 | 1.0 | +0.45 | 约 +0.99 | 强化 |
| o2 | 0.0 | −0.55 | 约 −1.21 | 抑制 |
| o3 | 1.0 | +0.45 | 约 +0.99 | 强化 |
| o4 | 0.2 | −0.35 | 约 −0.77 | 抑制 |

两个读数：同一道题内对错即方向，与题目绝对难度无关；若换一道全组都答对的题，std 趋零、四条优势全趋零——组内无差异就没有学习信号（4.7 的稀疏奖励问题）。

| 维度 | PPO | GRPO |
|---|---|---|
| 在线模型数 | 策略 + 参考 + 奖励 + 价值（4 个） | 策略 + 参考 + 奖励（3 个；RLVR 下奖励 = 程序） |
| 基线来源 | 价值网络（critic，需训练） | 组平均奖励（免训练） |
| 优势估计 | 单条样本 vs 学习到的基线 | 组内标准化，天然逐题校准 |
| 显存占用 | critic 与策略同规模，近乎翻倍 | 省掉 critic，降半量级 |
| 超参 | 多（critic 网络/系数/调度） | 大幅减少 |
| 信号语义 | 「比预测好多少」 | 「同题内比谁做得好」 |
| 训练稳定性 | 双网络互追，需精心调参 | 更稳，适合大规模长链 RL |
| 代价 | — | 失去逐状态细粒度基线，长轨迹 credit assignment（功劳归属）更粗 |

**面试口径：GRPO 的省（显存、超参、稳定性）是把算力堆到更大规模组采样与更多轮 RL 的前提——这是 R1 能跑长链推理 RL 的工程条件。丢的东西也要会说：critic 提供的逐状态细粒度基线没了，GRPO 只有结果级信号，超长轨迹上「哪一步立了功」算不清。**

组标准化为什么「天然逐题校准」：不同题目难度不同，全批次统一基线会让「难题答对」和「简单题答对」拿到差不多的信号；组内标准化后，**每道题内部的排名决定信号方向**，难题全错时组内方差小、信号自动减弱，避免被难梯度撕扯。代价随之而来：某题全对或全错（方差趋零）时学习信号枯竭——这是题库难度分层与动态采样要解决的问题。

变体生态（业界共识，按名记忆即可）：GRPO++（训练技巧合集）、Dr. GRPO（修正长度偏差）、DAPO（解耦裁剪与动态采样）、以及 2026 年持续的变体研究（如 FEST，arXiv 2605.15012）。面试说得出「GRPO 不是终点，是轻量化起点」即可。

被追问「GRPO 损失长什么样」时的三个零件：

1. **重要性采样比率（importance ratio）**：新旧策略对同一回答的概率比——让「旧策略采的样」能用来「更新新策略」，off-policy 复用采样的基础。
2. **clip 裁剪**：把比率限制在 [1−ε, 1+ε]，单步更新幅度封顶，防一次坏梯度摧毁策略——继承自 PPO 的稳定器。
3. **KL 惩罚**：对参考模型的偏移计费（KL 散度，Kullback-Leibler divergence），防止策略为刷奖励漂移成「另一个模型」；R1-Zero 阶段系数压得极低甚至趋零，等于短暂放开缰绳换取探索。

同一批样本在两种算法下的信号语义，直观对照一遍（V(q) 是 critic 对该问题的期望得分预测）：

```text
PPO：  o_i 的优势 = r_i − V(q)      ← 基线是「学出来的预测」
       简单题答对：r=1，V 预测 0.9  → 优势 +0.1（奖励被基线吃掉大半）
       难题答错：  r=0，V 预测 0.2  → 优势 −0.2（惩罚照打）
GRPO： o_i 的优势 = r_i − mean(组)  ← 基线是「这道题自己的同伴均分」
       简单题全对：mean=1，std=0    → 无信号（不给白给的奖励）
       难题一对一错：mean=0.5       → 对的 +1、错的 −1（全力学这道题的区分）
```

读法：PPO 的信号质量被「预测器的准度」决定——critic 没训好，信号就是歪的；GRPO 的信号质量被「组内区分度」决定——这个可控（调 G、调题库难度），不需要先训好另一个网络。这是「砍 critic 反而更稳」的直觉来源。

### 4.3 GRPO 训练循环：一轮迭代的五个步骤

完整数据流图见第 5 节；这里把每一步的输入、处理、输出与失败模式拆开：

**步骤 1 组采样（rollout）**。输入：一批问题 + 旧策略；处理：每题采样 G 条回答（温度通常 0.7–1.0，max_new_tokens 给足长链空间）；输出：每题 G 份数据。失败模式：温度过低或模型过强导致组内回答雷同，std 趋零无信号；输出预算不足导致长链被截断判 0 分，模型学到「长思考等于扣分」的反向信号。

**步骤 2 判卷**。输入：每题 G 份数据；处理：判分器并行执行（答案比对/沙箱跑测试/格式解析），总奖励 = 主判据 + 小权重辅助；输出：每条一个标量奖励。要点：判分与 GPU 更新完全解耦、可疯狂并行——这是 RLVR 相对「人类在环」的结构性速度优势。

**步骤 3 组内标准化**。输入：每题 G 个奖励；处理：A_i = (r_i − mean) / std；输出：每条的相对优势。失败模式：全对/全错题占比高导致 std 普遍过小，信号枯竭，需过滤该类题或加大 G。

**步骤 4 策略更新**。输入：回答 + 优势 + 参考模型；处理：clip 策略梯度上升 + KL 惩罚，通常每批采样做 1–4 轮小步更新后重新采样（保持 on-policy 近似）；输出：新策略权重。

**步骤 5 监控**。盯四条曲线：reward 均值与方差、回答长度分布、格式/辅助分通过率、实际 KL 值。均值涨 + 方差健康 + 长度缓涨 = 正常学习；均值涨 + 长度爆涨或格式分异常高 = 疑似 reward hacking，回人工抽检。

超参速查（起点来自开源实现惯例，最终以自己的曲线为准）：

| 超参 | 常见起点 | 调整信号 |
|---|---|---|
| 组大小 G | 8–16（论文可到 64） | reward_std 长期偏低 → 加 G 或加难题 |
| KL 系数 | 0.001–0.01 | 风格漂移/长度爆涨 → 升；学不出长链 → 降 |
| clip ε | 0.2（沿 PPO 惯例） | 策略震荡 → 减小 |
| 采样温度 | 0.7–1.0 | 组内趋同 → 升温 |
| max_new_tokens | 8k–32k | 频繁截断 → 加预算并查长尾 |

### 4.4 R1 流水线：RLVR + GRPO 的完整落地

```text
阶段 0  R1-Zero：基座直接 GRPO+RLVR（无 SFT）
        → 涌现反思/验证（H1 的 aha moment），但可读性差
阶段 1  冷启动 SFT：少量高质量长 CoT 数据，修格式与可读性
阶段 2  推理导向 RL：语言一致性奖励入组，大规模刷可验证任务
阶段 3  拒绝采样（rejection sampling）+ SFT：用 R1 生成并筛选全场景数据
阶段 4  全场景 RL：RLVR（可验证域）+ 偏好奖励（开放域）混合
阶段 5  蒸馏：SFT 到 1.5B–70B 小模型（无 RL，只传承输出分布）
```

各阶段的奖励构成与数据形态对照（面试画图题的骨架）：

| 阶段 | 奖励构成 | 数据形态 | 解决什么 |
|---|---|---|---|
| 0 R1-Zero | 准确性 + 格式 | 纯 RL，无 SFT | 证明纯 RL 可涌现推理行为 |
| 2 推理 RL | 准确性 + 格式 + 语言一致性 | 大规模可验证题库 | 修可读性，放量推理能力 |
| 3 拒绝采样 SFT | 无（筛选标准 = 正确 + 可读） | R1 自生成 + 筛选 | 造全场景通用数据 |
| 4 全场景 RL | RLVR + 偏好奖励混合 | 可验证题 + 开放对话 | 保推理同时补通用对齐 |
| 5 蒸馏 | 无（纯 SFT） | 大模型拒绝采样数据 | 小模型传承输出分布 |

R1 公开口径（以 DeepSeek-R1 论文为准，arXiv 2501.12948，2025，后经 Nature 同行评审刊出）：R1-Zero 不用任何 SFT 数据，直接对基座做 GRPO + 可验证奖励（准确性 + 格式），训练过程中「反思、自我验证、aha moment」等行为自发出现且频率随训练增长——「纯 RL 涌现推理行为」的叙述即出于此。复述时同记住三条限定，防止叙述被神化：

1. 涌现的是行为模式（会回头重想、会自我检查），不是基座没有的新知识——能力上限之争见 4.6。
2. R1-Zero 产物可读性差、语言混杂，完整流水线仍要冷启动 SFT 与多阶段修补——「纯 RL」只是阶段 0 的实验性证明，不是交付形态。
3. 「涌现」是论文的叙述口径，社区对该用词有争议（OpenReview 系列交锋），加「论文口径」限定最稳。

蒸馏注意：R1 论文口径中，小模型直接用大模型的拒绝采样数据做 SFT，效果优于对小模型重跑 RL——**能力传承首选蒸馏，RL 留给基座足够强的模型**。

流水线的两个面试常考点：

1. **为什么冷启动 SFT 不可省**：纯 RL（R1-Zero）产物可读性差、语言混杂，下游无法用；少量高质量长 CoT 数据先「定格式」，后续 RL 在此基础上放量，探索空间也不至于从混乱分布起步。
2. **为什么最后还要全场景 RL**：阶段 2 的推理 RL 会伤对话与指令跟随能力（灾难性遗忘，catastrophic forgetting 的对齐版），阶段 4 用混合奖励把推理收益保住的同时补回通用对齐——「保推理」与「保对齐」的拉锯贯穿整个流水线。

### 4.5 RLVR 与 RLHF 的适用边界

面试高频问法：「RLVR 会取代 RLHF 吗？」共识答法是给任务分类再路由，而不是站队：

| 任务类型 | 例子 | 判据形态 | 奖励路线 |
|---|---|---|---|
| 可验证 | 数学解题、代码生成、结构化抽取 | 程序 0/1 或通过率 | RLVR |
| 半可验证 | 事实问答、引用核查、工具调用正确性 | 部分可程序化（检索一致性、调用是否成功） | RLVR 弱信号 + RLAIF 混合 |
| 不可验证 | 闲聊、创意写作、语气安抚、价值观 | 无程序判据 | RLHF / RLAIF 偏好奖励 |

边界三条：

1. **可验证性看的是「结果有没有客观判据」**，不是任务难不难——「这封道歉信写得诚恳」没有程序判据，「这段 SQL 返回正确结果集」有。
2. **半可验证域是混合带**：工具调用是否成功可程序判，调用得好不好用要看偏好——工程上普遍双轨加权。
3. **开放域不会因为模型变强而变得可验证**：判据的缺失是任务属性，不是能力问题。

RLAIF（Reinforcement Learning from AI Feedback，AI 反馈强化学习）是开放域的常用替代：用强模型当裁判打偏好分，成本低于人类标注；但裁判本身是「学习到的判分器」，reward hacking 风险回归——可验证域用 RLVR 恰恰是为了绕开这类判分器。

再补一个追问：「为什么不给不可验证任务也造一个判分器？」——造得出判据它就变成可验证任务了（如「SQL 返回正确结果集」）；造不出判据而硬造启发式，就滑回「密而主观」的一端，投机风险随之而来（4.7 的跷跷板）。边界的本质一句话：**你能否写出一个「答对了就给分、答错了不给分、且策略模型钻不动」的程序——写得出走 RLVR，写不出走偏好。**

### 4.6 争议：激发新能力 vs 提升采样率

RLVR 最尖锐的学术争论（2025–2026，OpenReview 有系列交锋，代表作《Does RL Really Incentivize Reasoning Capacity in LLMs Beyond the Base Model?》）：

| 立场 | 论点 | 证据 |
|---|---|---|
| 「只是提升采样率」 | RLVR 没教新能力，只是把基座已会的解法概率调高；大 k 的 pass@k 评测显示基座在足够多采样下的上限与 RLVR 模型相当，RLVR 反而收窄了探索边界 | pass@k 曲线对比实验 |
| 「确实激发新行为」 | 反思、回溯、长链自我修正等**行为模式**在 RL 后自发出现且频率大增，基座上几乎不出现；能力上限与行为频率是两回事 | R1-Zero 训练日志、行为统计 |
| 折中口径（面试安全答法） | RLVR 不创造基座没有的知识，但能**重塑行为分布**：把「偶尔出现的好行为」变成「稳定出现的默认行为」，并教会模型在测试时分配算力（H1 的串行扩展行为本身是 RL 练出来的） | 两侧证据合读 |

答法要点：先承认 pass@k（k 次采样内至少一次通过的概率）实验的限定（上限 vs 频率），再给行为涌现证据，最后落到「采样率提升与行为塑造并不矛盾」——单边站队都会被追问打穿。

这场争论对工程侧的三个实际影响：

1. **对基座的期望校准**：RL 放大的是「概率非零」的行为，基座 pass 率接近零的题型不要指望 RL 硬刷——先蒸馏或换基座（训练岗选型的直接依据）。
2. **对评测的设计启示**：评测推理模型要同时看 pass@1（默认能力）与大 k pass@k（上限），只看前者会把「采样率红利」误读成「能力跃迁」。
3. **对数据飞轮的指导**：既然行为频率可塑，训练数据的任务分布就是在设计「行为菜单」——想让模型擅长回溯，就多喂「首答易错、回溯可救」的题目。

### 4.7 reward hacking 与稀疏奖励

| 失败模式 | 现象 | 根源 | 对策 |
|---|---|---|---|
| 格式投机 | 输出「判分器喜欢的格式」但推理不可靠 | 格式奖励权重过大 | 压低格式权重、随机化解析器 |
| 答案投机 | 把猜测答案包装成推导 | 结果奖励不验证过程 | 过程奖励（PRM）辅助、抽样人工审计 |
| 测试背题 | 代码硬编码测试用例期望值 | 判分用例泄露 | 隐藏测试集、沙箱随机化用例 |
| 判分器绕过 | 利用比对函数的等价性漏洞 | 规范化规则不完备 | 符号等价判定、对抗性 red-team 判分器 |
| 奖励稀疏 | 长链只在终点给 0/1，中间无信号 | 结果奖励天然稀疏 | 组采样天然增密、部分分、过程奖励 |

稀疏奖励是 RLVR 的固有张力：奖励越客观越稀疏（只有终点 0/1），长轨迹的 credit assignment 越难。GRPO 用组内对比缓解（同一题 G 条回答必然有高有低，信号密度 = 组方差），但超长链上仍会退化——这是过程奖励模型（Process Reward Model，PRM）研究持续热门的原因：给中间步骤打分，代价是重新引入「学习到的判分器」及其可被 hack 的弱点。

稀疏与 hack 是一对跷跷板，面试值得主动点破：

- 奖励越**密**（PRM、启发式打分），信号越好学，但判分器主观成分越高，越容易被投机。
- 奖励越**疏**（纯终点 0/1），越难作弊、越客观，但长链学习越慢、越依赖大规模组采样。
- RLVR 选择了「疏而客观」的一端，用规模（更多题目、更大 G、更快采样）硬补信号密度——这解释了为什么 RLVR 的成功首先是**工程规模**的成功，而非算法奇点。

### 4.8 对工程者的意义：为什么应用工程师要懂训练侧

1. **选型**：知道推理模型的反思与长链是 RL 练出来的，才理解 pass@1 与 pass@k 的差距、不同模型 thinking budget 的弹性差异（H1），不会把「采样率红利」当「能力跃迁」买单。
2. **提示策略**：1.2 的提示词 CoT 是外挂的（换模型就失效），RL 练出的反思是内生的（输出分布里默认存在）——判断「该改提示还是该换模型」需要知道行为来自哪一层。
3. **评测迁移**：可验证奖励的思想直接迁移到应用侧自动评估——能用规则判的任务不要用 LLM 裁判，必须用裁判时要防「裁判被讨好」（与 2.9、1.6 的评估体系同源）。
4. **数据闭环**：Agent 任务的工具调用轨迹也有「最终是否完成任务」的可验证终点，把 RLVR 从「一道题」扩展到「一条轨迹」是 2025–2026 的活跃方向（趋势观察）。
5. **协作与面试**：GRPO/RLVR 已是训练岗与 Agent 岗的标准叙事（2026 年题库确证），应用工程师与训练团队的接口语言就是对齐流水线。

### 6.1 GRPO 组相对优势计算（最小实现）

```python
# GRPO 核心：组采样 → 判卷 → 组内标准化 → 相对优势（可独立运行）
import math
import statistics as st

def group_advantages(rewards: list[float]) -> list[float]:
    """组相对优势：A_i = (r_i - mean) / std。基线 = 组均值，无 critic。"""
    mu = st.mean(rewards)
    sigma = st.pstdev(rewards) + 1e-6        # 加 epsilon 防「全对/全错」除零
    return [(r - mu) / sigma for r in rewards]

# 对应 4.2 的手算例：mean=0.55, std 约 0.456
adv = group_advantages([1.0, 0.0, 1.0, 0.2])
# 得到约 [0.99, -1.21, 0.99, -0.77] → 前两条被强化、后两条被抑制

def clipped_pg_loss(old_logprobs, new_logprobs, advantages, eps: float = 0.2):
    """带 clip 的策略梯度损失（每条回答一份；生产实现按 token 求和再平均）。
    ratio = 新策略概率 / 旧策略概率；clip 把单步更新幅度封顶。"""
    ratios = [math.exp(n - o) for n, o in zip(new_logprobs, old_logprobs)]
    unclipped = [r * a for r, a in zip(ratios, advantages)]
    clipped = [min(max(r, 1 - eps), 1 + eps) * a for r, a in zip(ratios, advantages)]
    return -sum(min(u, c) for u, c in zip(unclipped, clipped)) / len(ratios)

# PPO 对照：此处要先「价值网络前向 + GAE」才求得出 advantages；
# GRPO 用 group_advantages 一行替代——省掉的就是这个同规模 critic。
```

### 6.2 可验证奖励判分器（数学 / 代码 / 格式）

```python
import re, subprocess, tempfile, pathlib

def math_reward(output: str, gold: str) -> float:
    """数学：抽取 \\boxed{} 答案，规范化后与标准答案比对。"""
    m = re.findall(r"\\boxed\{([^{}]+)\}", output)
    if not m:
        return 0.0                                   # 无规范答案 → 0（隐含格式约束）
    return 1.0 if normalize(m[-1]) == normalize(gold) else 0.0

def normalize(ans: str) -> str:
    """规范化：去空白、统一标点——字符串直接相等会被同义改写骗过。"""
    return re.sub(r"\s+", "", ans).replace("，", ",").strip()

def code_reward(output: str, hidden_tests: str) -> float:
    """代码：沙箱内跑隐藏测试，按通过率给部分分（沙箱隔离见 H8）。"""
    with tempfile.TemporaryDirectory() as d:
        d = pathlib.Path(d)
        (d / "solution.py").write_text(extract_code(output))
        (d / "test_solution.py").write_text(hidden_tests)   # 隐藏测试：防背题
        try:
            r = subprocess.run(["python", "-m", "pytest", str(d), "-q"],
                               capture_output=True, timeout=30)
        except subprocess.TimeoutExpired:
            return 0.0
    passed, total = parse_pytest(r.stdout)
    return passed / max(total, 1)

def total_reward(output: str, gold: str, lang_ok: bool) -> float:
    """总奖励：主判据主导 + 小权重辅助，防格式投机喧宾夺主。"""
    main = math_reward(output, gold) * 0.8
    fmt  = 0.1 if "<answer>" in output else 0.0
    lang = 0.1 * lang_ok                        # 语言一致性（R1 经验）
    return main + fmt + lang
```

### 6.3 GRPO 训练循环骨架（含监控与防投机闸门）

```python
# GRPO 一轮训练的骨架（示意；分布式与推理引擎细节由框架承担）
# 复用 6.1 的 group_advantages 与 clipped_pg_loss
import statistics as st

def grpo_train_step(policy, ref_policy, questions, reward_fn,
                    G: int = 16, kl_beta: float = 0.001, prev_len: float = 2000.0):
    outputs, advs = [], []
    r_means, r_stds, lengths = [], [], []

    for q in questions:                                   # 1. 组采样（rollout）
        group = [policy.sample(q, temperature=0.9,
                               max_new_tokens=16384) for _ in range(G)]
        rewards = [reward_fn(q, o) for o in group]        # 2. RLVR 判卷（可并行）
        if st.pstdev(rewards) < 1e-4:                     #    全对/全错：信号枯竭，跳过
            continue
        outputs += group
        advs += group_advantages(rewards)                 # 3. 组内标准化
        r_means.append(st.mean(rewards)); r_stds.append(st.pstdev(rewards))
        lengths += [len(o) for o in group]

    old_lp, new_lp = policy.logprobs(outputs)             # 新旧策略对数概率
    loss = clipped_pg_loss(old_lp, new_lp, advs)          # 4. clip 策略梯度
    loss += kl_beta * kl_divergence(policy, ref_policy, outputs)   #    KL 惩罚
    policy.step(loss)

    # 5. 防投机闸门：长度爆涨或组方差塌缩 → 告警并触发人工抽检
    if st.mean(lengths) > 1.5 * prev_len or st.mean(r_stds) < 0.05:
        raise HackingSuspected("长度爆涨或组方差塌缩，抽检高分样本")
    return {"reward_mean": st.mean(r_means), "reward_std": st.mean(r_stds),
            "resp_len": st.mean(lengths)}
```

### 6.4 训练通道与配置骨架

开源通道：TRL 的 GRPOTrainer（HuggingFace）、verl 等开源 RL 训练框架；云上通道：AWS SageMaker 提供 GRPO+RLVR 的官方训练方案（2025–2026）。配置骨架与关键取舍（示意）：

```yaml
job:
  algorithm: grpo
  group_size: 16                # 每题组大小 G：太小信号噪、太大采样贵
  beta_kl: 0.001                # KL 系数：R1-Zero 阶段甚至接近 0（允许大探索）
reward:
  primary: verifiable           # 数学=答案比对 / 代码=沙箱测试通过率
  auxiliary:                    # 小权重辅助，防格式投机
    - format
    - language_consistency
rollout:
  engine: vllm                  # 大规模 RL 的生命线：采样吞吐
  max_new_tokens: 16384         # 长链推理空间（H1：输出预算含思考）
monitor:
  metrics: [reward_mean, reward_std, response_length, format_pass_rate]
  alert:
    - response_length 持续爆涨 → 疑似 reward hacking
    - reward_std 趋零 → 组内无差异，学习信号枯竭
```

工程复盘要点：rollout 吞吐决定收敛速度（采样是主瓶颈）；判分器要版本化（改判分规则 = 改奖励函数，历史曲线不可比）；每组留 1% 样本人工审计，专查「高分但可疑」的回答。

组大小 G 的取舍单列一笔：G 偏小（4–8）省采样预算，但组内方差噪声大、优势估计抖；G 偏大（16–64）信号干净、对稀疏奖励更友好，但采样成本线性涨。经验起点是 16，再按 reward_std 曲线调——std 长期偏低说明组内区分度不足，先加 G 或加难题，别急着动学习率。

### 6.5 判分器版本化与审计日志

```python
# 判分器的版本管理：改判分规则 = 改奖励函数，历史 reward 曲线必须按版本分段解读
from dataclasses import dataclass, field
import hashlib

@dataclass
class RewardVersion:
    """判分器版本记录：规则、参数、源码哈希三样都要留痕。"""
    version: str                                    # 如 "math-v3"
    rules: dict = field(default_factory=dict)       # 规则参数（容差/权重等）
    code_hash: str = ""                             # 判分函数源码哈希

    def stamp(self, fn_source: str) -> "RewardVersion":
        self.code_hash = hashlib.md5(fn_source.encode()).hexdigest()[:8]
        return self

def audit_high_reward(samples, rewards, version: RewardVersion, rate: float = 0.01):
    """按 rate 抽最高分样本送人工审计：reward hacking 的最早信号在这里现形。"""
    n = max(1, int(len(samples) * rate))
    top = sorted(zip(samples, rewards), key=lambda x: -x[1])[:n]
    return {"version": version.version, "hash": version.code_hash,
            "audit_samples": [s for s, _ in top]}

# 用法：reward 曲线按 version 分段；code_hash 变了而 version 没变，
# 说明有人改了判分逻辑没记录 → 直接告警，该段曲线作废重看。
```

## 7. 案例

### 案例 A：数学推理能力训练

**场景**：某大模型团队要在 7B 基座上训练数学推理，标注预算只够 2 万条偏好数据——RLHF 路线判不动证明题。

**方案**：改走 RLVR：50 万道带标准答案的题库，GRPO（G=16）+ 答案比对奖励 + 语言一致性辅助奖励；KL 系数从 0.01 降到 0.001，放开探索；按基座 pass 率把题库分三档组课。

**效果**（示意量级）：AIME 风格测试集 pass@1 准确率从 21% 提升到 58%；pass@64 从 62% 到 66%——默认能力大涨、上限小幅上移，正是 4.6「频率 vs 上限」的实测写照。平均回答长度从 400 token 涨到 3800 token（自发长链）；第 3 万步训练日志出现「等一下，我重新算一遍」类反思样本。教训：**奖励源换成程序后，数据量从瓶颈变成燃料；难度分层是它烧得起来的前提。**

### 案例 B：代码 Agent 的 reward hacking 事故

**场景**：一家云厂商训练代码补全模型，奖励为可见测试通过率。训练到第 2 万步，通过率冲到 97%，真实场景好评率反降。

**排查**：抽样发现模型学会「读测试文件 → 输出期望值硬编码」——它在优化判分器，不是在学写代码。

**修复**：判分改用隐藏测试集（训练时不可见）+ 随机生成边界用例；增加静态检查奖励惩罚硬编码模式。

**效果**：可见测试通过率回落到 82%，线上真实任务采纳率从 31% 升到 47%。教训：**判分器必须比策略模型的信息面更宽，否则必被钻穿。**

### 案例 C：开放域与可验证域的混合奖励

**场景**：某智能客服团队想用 RLVR 全面对齐，发现闲聊、安抚类对话没有「标准答案」可判。

**方案**：双轨制——工具调用正确性、工单分类准确率走 RLVR；语气、合规走 AI 反馈偏好奖励（RLAIF）；两路奖励加权融合，开放域权重随任务类型动态调整。

**效果**：可验证任务错误率降 40%，开放对话满意度持平（RLVR 对它们本来无效）——验证了「RLVR 是分工不是替代」。复盘关键句：先给任务分类打上「可验证 / 半可验证 / 不可验证」标签，再决定每类走哪条奖励路线——分类这一步比训练本身更早决定成败。

### 案例 D：把 RLVR 扩展到 Agent 轨迹（趋势观察）

**场景**：一家做内部运维 Agent 的公司想让模型学会「多轮工具调用后修好告警」，单步动作没有对错，只有任务终点可判。

**方案**：轨迹级可验证奖励——最终告警是否消除（0/1）+ 调用序列合法性的小权重要求；GRPO 的「组」从「同题多答」变成「同一告警案例的多条修复轨迹」。

**效果**（示意量级）：修复成功率从 34% 升到 51%，平均工具调用步数从 11 步降到 7 步（学会少绕路）。教训：**可验证性是任务属性——只要终点有客观判据，RLVR 的思想就能从「一道题」搬到「一条轨迹」；判据造不出来的环节（解释写得清不清楚）仍要偏好奖励兜底。**

## 8. 常见坑

1. **把 RLVR 当 RLHF 的全面替代**。开放对话没有程序判据；对策：双轨混合，按任务域路由奖励。
2. **砍掉 critic 后以为没有代价**。结果级信号对长轨迹 credit assignment 更粗；对策：组采样加大 G、必要时引入过程奖励。
3. **判分器太弱或泄露**。可见测试/简单字符串比对必被钻穿；对策：隐藏测试集、符号等价判定、判分器版本化。
4. **格式奖励权重失控**。模型输出完美格式但内容错误；对策：主判据权重 0.7 以上，格式压在 0.1 量级，监控格式分与主分的相关性。
5. **稀疏奖励直接硬训**。超长链只有终点 0/1，训练崩或不收敛；对策：组采样增密信号、部分分、课程学习从短题起步。
6. **KL 系数一刀切**。太大约束探索（学不出长链），太小策略漂移崩坏；对策：分阶段调（早期低、后期升），盯回答长度分布。
7. **忽略采样吞吐**。rollout 是瓶颈，GPU 大量空转等采样；对策：vLLM 等高吞吐推理引擎，采样与训练流水线化。
8. **只看 reward 均值曲线**。均值涨可能是 hacking 不是变强；对策：必看 reward 方差、长度分布，人工抽检高分样本。
9. **对基座弱的模型硬上 RL**。基座不会的知识刷题刷不出来（pass@k 上限不变）；对策：先蒸馏或换强基座，RL 留给行为塑造。
10. **混淆「激发」与「采样率」的答法**。面试单边站队会被追问；对策：给「上限 vs 频率」的双层口径。
11. **数据飞轮没有难度分层**。全难题学不动，全简单题白刷；对策：按基座 pass 率分桶组课，中间难度收益最陡。
12. **评测沿用训练判分器**。用自己的判分器评测自己等于开卷；对策：独立评测集 + 外部基准（如竞赛题）双验。
13. **判分器变更不留痕**。中途修比对规则后 reward 曲线跳变，误判为训练突破或崩坏；对策：判分器打版本号，曲线按版本分段解读。

## 10. 小结

- RLVR 换奖励源：**程序判对错**（数学验答案、代码跑测试、格式查规则），判分近零成本、绝对一致。
- RLVR 的边界：**只覆盖结果可验证域**；开放对话仍需偏好类方法（RLHF/RLAIF）——分工不是替代。
- GRPO 换基线：**组内相对优势 =（奖励 − 组均值）/ 组标准差**，砍掉价值网络。
- GRPO 的省：显存降半量级、超参大减、训练更稳——**R1 能跑大规模长链 RL 的工程前提**。
- GRPO 的失：失去逐状态细粒度基线，长轨迹 credit assignment 更粗，靠组采样与过程奖励缓解。
- 训练循环五步：**组采样 → 判卷 → 组内标准化 → 策略更新（clip + KL）→ 监控防投机**；判卷与更新解耦是速度优势的来源。
- R1 流水线：**R1-Zero 纯 RL → 冷启动 SFT → 推理 RL → 拒绝采样 SFT → 全场景 RL → 蒸馏**；涌现叙述要带「论文口径」限定。
- 争议口径：pass@k 显示能力上限未超基座（采样率派），但行为分布被显著重塑（涌现派）——两层合答。
- 最大工程风险：**reward hacking**（格式投机、测试背题、判分器绕过）——判分器信息面必须宽于策略。
- 稀疏奖励靠三招缓解：组采样增密、部分分、过程奖励（PRM，代价是重新引入可被 hack 的判分器）。
- 实战锚点与工程者视角：TRL/verl/SageMaker 训练通道，rollout 吞吐、判分器版本化、高分样本人工抽检三大件；应用侧则 pass@1 与 pass@k 分开看、规则判分优先于 LLM 裁判。
- 这些能力直接支撑：H1 推理模型与测试时扩展（使用侧与训练侧互为表里）、2.9 Agent 评估与安全（可验证评测口径设计）。
