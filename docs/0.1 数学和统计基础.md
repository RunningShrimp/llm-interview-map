## 2. 一句话定义

数学与统计基础，是理解 LLM 内部表示、生成随机性、检索相似度和工程评估指标的"最小必要数学工具箱"。

简化为一张总览：

```text
LLM 工程视角下的四大数学支柱：
  表示 = 向量 / 矩阵       → 嵌入（Embedding）与注意力（Attention）
  生成 = 概率分布 / 采样    → 输出多样性与幻觉
  学习 = 损失 / 梯度       → 预训练与微调
  决策 = 均值 / 分位数      → 评估、监控与 SLA
```

## 3. 为什么需要

做 AI Agent 工程，你不需要手推反向传播，但一定会遇到：

- **RAG 检索**：为什么用余弦相似度，而不是欧氏距离？
- **模型采样**：temperature、top_p 到底在调什么？
- **幻觉与不确定性**：模型输出本质是概率分布，不是事实数据库。
- **评估**：P50 / P95 / P99 延迟、平均成功率、置信区间。
- **成本估算**：期望 token 数 × 单价 = 预算。
- **嵌入**：文本变向量后，如何度量"语义接近"？
- **训练与微调**：为什么分类用交叉熵（Cross-Entropy）而不用均方误差（MSE）？做 LoRA 微调至少要能读懂损失曲线。

这些问题的共同底座就是：线性代数 + 概率 + 微积分 + 统计。

四大数学支柱与各自的工程落点（本锚点关键问题"向量、矩阵、概率、损失函数分别解决什么"的直接回答）：

| 数学支柱 | 解决什么问题 | 在 LLM/Agent 里对应什么 | 详细展开 |
|---|---|---|---|
| 向量 | 表示：一个对象的多维特征 | 嵌入、语义检索的坐标 | 0.7、1.4 |
| 矩阵 | 变换：批量表示与线性变换 | 注意力打分、权重层、批处理 | 0.4 |
| 概率 | 不确定性：各种取值的可能性 | 下一个 token 的分布、采样、幻觉 | 0.5 |
| 损失函数 | 学习目标：什么算"错" | 预训练与微调的优化目标 | 0.3 |

类比 1：这套数学之于 Agent 工程，像装修师傅之于电学——不需要会设计电路板，但要看得懂电压标识、知道哪根线不能剪。看不懂温度、概率、分位数就动手调参，等于拿着电钻在承重墙上乱戳。

没有这层底子会怎样（反面对照）：

| 场景 | 没有数学底子的做法 | 有最小数学底子的做法 |
|---|---|---|
| 检索效果差 | 换嵌入模型、重启、碰运气 | 先分清是相似度度量、切分还是召回环节的问题 |

## 4. 核心原理

按四大支柱分五小节：4.1 线性代数（表示与相似度）、4.2 矩阵乘法（注意力的骨架）、4.3 概率（生成与不确定性）、4.4 损失函数与梯度（模型怎么学）、4.5 评估统计（工程决策）。

### 4.1 线性代数：表示与相似度（向量 → 嵌入）

**基本对象**：

- **标量（Scalar）**：一个数，如 temperature = 0.7。
- **向量（Vector）**：一串数，如嵌入 `[0.12, -0.98, 0.33]`。一个 1536 维嵌入就是 1536 个数排成的向量；截至 2026 年，常见商用嵌入模型的输出维度多在 1024 到 3072 之间。
- **矩阵（Matrix）**：二维数组，如一批 token 的嵌入表：512 个 token、每个 1536 维，就是一张 512×1536 的表。
- **范数（Norm）**：向量的"长度"，最常用 L2 范数（各分量平方和开根号）。

**点积（Dot Product）**：两个向量对应相乘再求和，同时衡量方向与强度：

```text
a · b = a1*b1 + a2*b2 + ... + an*bn
```

**余弦相似度（Cosine Similarity）**：点积除以模长乘积，只看方向、不看长度：

```text
cos(a, b) = (a · b) / (||a|| * ||b||)
```

推导三步：

1. 点积的几何含义：`a · b = |a| * |b| * cos(θ)`，θ 是两向量夹角。
2. 两边同除 `|a| * |b|`，得到 `cos(θ) = (a · b) / (|a| * |b|)`。
3. 所以余弦相似度就是"夹角的余弦"：范围 `[-1, 1]`，越接近 1 方向越一致、越相似。

RAG 检索常用它，因为嵌入的"方向"承载语义，"长度"往往只反映文本长度等噪声因素。语义检索与向量库实践见 0.7、1.4。

三种相似度度量对比：

| 度量 | 看什么 | 受向量长度影响 | 典型用途 |
|---|---|---|---|
| 欧氏距离（Euclidean Distance） | 空间中两点的直线距离 | 是 | 低维特征、已归一化场景 |
| 点积 | 方向 + 长度 | 是 | 已归一化嵌入的内积检索（此时等价于余弦） |
| 余弦相似度 | 仅方向 | 否 | 嵌入语义检索的默认选择 |

类比 2：判断两个歌手是不是在唱同一首歌，应该只听旋律，不该被音量干扰——音量对应向量长度，旋律对应向量方向。余弦相似度做的正是"只听旋律"这件事。

面试高频问法（业界共识口径）：「RAG 检索为什么常用余弦相似度而不是欧氏距离？」答题线：嵌入方向承载语义，长度易受文本长度等因素干扰；若向量已做 L2 归一化（模长为 1），点积与余弦数值等价，所以不少向量库默认用内积即可。

### 4.2 矩阵乘法：注意力的骨架（矩阵 → 注意力）

**矩阵乘法（Matrix Multiplication）**：(m×k) 矩阵乘 (k×n) 矩阵得到 (m×n) 矩阵，本质是"批量做 k 维点积"——结果第 i 行第 j 列，就是左矩阵第 i 行与右矩阵第 j 列的点积。

在 Transformer（见 0.4）的注意力机制里：

```text
注意力分数 = Q · K^T / sqrt(d_k)   → 再经 softmax 归一化成权重
输出      = 权重 · V
```

直观读法：每个 token 都发一个"提问"向量（Query），与所有 token 的"名片"向量（Key）做点积打分，分数归一化后当作权重，去加权汇总"内容"向量（Value）。`Q · K^T` 就是一次矩阵乘法，"每个 token 该看哪些 token"完全由点积分数决定。本篇只需建立"矩阵乘法 = 批量点积打分"的直觉，完整推导在 0.4 展开。

除注意力外，嵌入查表、整个权重网络的前向传播，核心运算都是矩阵乘法；GPU 适合跑 LLM，正因为这是可高度并行的运算。

### 4.3 概率：生成与不确定性（概率 → 采样与幻觉）

**基本对象**：

- **随机变量（Random Variable）**：取值不确定的变量，如"下一个 token 是什么"。
- **概率分布（Probability Distribution）**：每个候选 token 的概率，如 `{"猫": 0.6, "狗": 0.3, "鱼": 0.1}`。
- **条件概率（Conditional Probability）**：`P(下一个词 | 前文)`——这正是语言模型建模的全部内容：给定前文，给词表上每个词打一个概率。
- **期望（Expectation）**：长期平均，如平均 token 消耗、平均延迟。
- **方差 / 标准差（Variance / Standard Deviation）**：波动大小，如延迟稳定性（分位数见 4.5）。

**Softmax**：把一组任意大小的实数（logits）变成总和为 1 的概率分布。

**温度（Temperature）**：调整 softmax 分布的"陡峭程度"：

```text
p_i = exp(logit_i / T) / sum(exp(logit_j / T))
```

- T 小 → 分布更尖锐 → 输出更确定（T 趋近 0 时退化为贪心，永远选最大概率项）。
- T 大 → 分布更平坦 → 输出更随机。

用 `logits = [2.0, 1.0, 0.1]` 看温度的效果（示意）：

```text
T=0.1 → [1.000, 0.000, 0.000]   近似 one-hot，只认最大项
T=1.0 → [0.659, 0.242, 0.099]   原始 softmax
T=5.0 → [0.400, 0.327, 0.273]   趋近均匀，谁都可能被选
```

采样三参数对比：

| 参数 | 作用位置 | 调大的效果 | 典型设置 |
|---|---|---|---|
| temperature | softmax 内部，重塑整个分布形状 | 分布变平，低概率词也有机会 | 创作场景高，工具调用 0 |
| top_k | 分布截断：只保留概率前 k 的候选 | 候选池变大 | 20-100 |
| top_p（核采样，Nucleus Sampling） | 按累计概率截断：保留累计概率达 p 的最小集合 | 候选池变大 | 0.9-0.95 |

类比 3：温度像一家餐厅的推荐策略。温度低 = 只推销量第一的那道菜，每次来都吃同一样；温度高 = 按销量比例轮换推荐，冷门菜也有机会被端上来。稳定性要求高的场景点"固定菜"，创意场景才"轮换"。

幻觉的概率视角：LLM 每一步都在"按概率抽签"，抽到低概率但错误的词，就是一次幻觉的种子。所以它不是数据库查询，而是"按概率生成最像答案的文本"——这也是需要 RAG、工具调用、验证器兜底的根本原因（见 0.5、1.4）。

**最大似然估计（MLE）与贝叶斯（Bayesian）**（概念级）：

- MLE：选让"已观察数据出现概率"最大的参数。语言模型的预训练目标，本质就是"最大化下一个 token 的似然"。
- 贝叶斯：把参数本身当随机变量，先验信念 + 数据证据 → 后验，即"看到证据后更新信念"。
- 连接点：MLE 的对数形式取负，就是训练里的损失函数——分类任务的交叉熵损失正是负对数似然。这一步把"概率"与"训练"接通了。

### 4.4 损失函数与梯度：模型怎么学（导数 / 梯度 → 训练）

**损失函数（Loss Function）**：量化"模型输出与正确答案差多远"，训练就是不断调整参数把损失降下去。

| 损失 | 公式（简化） | 适用 | 为什么 |
|---|---|---|---|
| 均方误差（Mean Squared Error, MSE） | (预测 - 真值)^2 的均值 | 回归 | 惩罚大偏差，梯度形式简单 |
| 交叉熵（Cross-Entropy） | -sum(真值 * log(预测)) | 分类 | 最大似然的标准形式，重罚"自信的错误" |

交叉熵的"重罚自信错误"用数字感受（真实标签为 1，模型预测正确概率为 p）：

```text
p=0.9 → 损失 = -log(0.9) ≈ 0.10   基本答对，轻罚
p=0.5 → 损失 = -log(0.5) ≈ 0.69   半信半疑
p=0.1 → 损失 = -log(0.1) ≈ 2.30   自信地错，重罚十倍以上
```

面试高频问法（业界共识口径）：「为什么分类任务用交叉熵而不用 MSE？」答题线：MSE 配合 sigmoid/softmax 时，梯度会带上导数衰减项，错得越离谱梯度反而可能越小、学习越慢；交叉熵是分类似然的负对数，梯度形式干净（正比于"预测 - 真值"），优化路径更稳。

**优化三件套**（了解即可）：

- **导数 / 梯度（Gradient）**：函数在该点变化最快的方向；梯度就是多维情形的导数。
- **链式法则（Chain Rule）**：复合函数的导数逐层相乘，深层网络反向传播（Backpropagation）的基础。
- **梯度下降（Gradient Descent）**：沿梯度反方向小步更新参数，直到损失收敛：

```text
参数更新：w = w - lr * dL/dw    （lr 为学习率）
```

**正则化（Regularization）**（概念级）：在损失上加惩罚项防过拟合——L1 倾向产生稀疏参数，L2 倾向把参数整体压小。过拟合 / 欠拟合的展开见 0.3。

作为 Agent 工程师，你主要"使用模型"，不"训练大模型"，所以这部分知道概念、能读懂损失曲线即可；做 LoRA 微调时，看懂 loss 是否收敛、是否过拟合是基本要求（见 0.3）。

### 4.5 评估统计：工程决策（统计 → 指标）

- **均值（Mean）**：平均成功率、平均成本。缺点：被极端值拉偏。
- **中位数（Median）**：一半样本在其下，抗极端值。
- **分位数（Quantile / Percentile）**：P50、P95、P99，工程上比平均值更能反映用户体验。
- **置信区间（Confidence Interval, CI）**：刻画小样本评估的不确定性。50 个测试样本得出成功率 80%，95% 置信区间可能宽到约 [0.69, 0.91]——这个宽度不足以支撑"B 版比 A 版好"的结论。
- **A/B 测试**：两个版本谁更好，本质是控制变量下的统计假设检验。

| 统计量 | 一句话 | 工程用途 | 陷阱 |
|---|---|---|---|
| 均值 | 平均水平 | 成本、token 消耗核算 | 被长尾拉偏 |
| 中位数 | 一半样本以下 | 偏态分布（如收入） | 丢失尾部信息 |
| P95 / P99 | 最差的那部分用户体验 | 延迟 SLA | 样本少时估计不稳 |
| 置信区间 | 结论的误差范围 | 小样本评估决策 | 样本小到无意义 |

类比 4：机场公告"平均取行李 10 分钟"对赶时间的旅客几乎没用，真正决定体验的是"最慢的 5% 旅客等了多久"——这就是 P95 的价值。平均值服务运营报表，分位数服务用户体验。

## 5. 架构 / 流程

四大数学支柱在 LLM/Agent 链路中的落点：

```text
┌────────────────────────────────────────────────────────────┐
│  用户输入（文本）                                            │
│    ↓ 分词（Tokenization）                                    │
│  [Token ID 序列]                                             │
│    ↓ 嵌入查表（Embedding，矩阵）                              │
│  [向量表示] ──────────── 线性代数：向量 / 矩阵 / 点积          │
│    ↓ 注意力打分 Q·K^T（矩阵乘法 + Softmax）                   │
│  [上下文融合后的表示] ── 概率：条件概率 P(下一个 token | 前文)   │
│    ↓ 采样：temperature / top_p ── 概率：分布重塑与截断          │
│  [生成的 token 流 → 文本]                                     │
│                                                              │
│  ← 训练侧（离线）：损失函数 + 梯度下降，更新参数                │
│                                                              │
│  工程侧（在线）：延迟 / 成本采样                               │
│      → 统计：均值 / 分位数 / 置信区间 → 监控、SLA 与预算        │
└────────────────────────────────────────────────────────────┘
```

读图要点：前向链路自上而下是"向量 → 矩阵 → 概率 → 采样"的流水线；训练侧与工程侧分别从"损失 / 梯度"与"统计指标"两个方向支撑这条流水线。本篇的每个数学概念都能在图中找到一格。

### 5.1 学习路径

```text
线性代数 ──> 向量/矩阵/点积/余弦相似度 ──> 嵌入与 RAG 检索（0.7、1.4）
概率统计 ──> 概率分布/Softmax/温度 ──> LLM 采样与幻觉（0.5）
微积分   ──> 梯度/反向传播 ──> 模型训练（了解，0.3）
评估统计 ──> 均值/分位数/置信区间 ──> 工程评估与 SLA
```

按此顺序，每个概念先在 NumPy 里跑一遍（见第 6 节），再去看对应的工程主题，遇到卡壳再回来补。

## 6. 代码 / 工具

### 6.1 余弦相似度与温度采样（NumPy）

```python
import numpy as np

# 1. 余弦相似度
def cosine_similarity(a, b):
    return np.dot(a, b) / (np.linalg.norm(a) * np.linalg.norm(b))

v1 = np.array([1, 2, 3])
v2 = np.array([2, 4, 6])    # 同方向，长度是 v1 的 2 倍
v3 = np.array([-1, -2, -3]) # 反方向
v4 = np.array([3, 2, 1])    # 分量相同但方向不同

print(cosine_similarity(v1, v2))  # 1.0   长度不影响方向判断
print(cosine_similarity(v1, v3))  # -1.0  完全相反
print(cosine_similarity(v1, v4))  # 0.71  同为正分量但方向不同
print(np.linalg.norm(v2 - v1))    # 3.74  欧氏距离却被长度差放大

# 2. 带温度的 softmax
def softmax_with_temperature(logits, T=1.0):
    logits = np.array(logits) / T
    exp = np.exp(logits - np.max(logits))  # 减最大值，数值稳定
    return exp / exp.sum()

logits = [2.0, 1.0, 0.1]
for t in (0.1, 1.0, 5.0):
    p = softmax_with_temperature(logits, t)
    print(f"T={t}: {np.round(p, 3)}  最大项占比 {p.max():.2f}")
```

预期观察：

- 同方向向量余弦相似度为 1，与长度无关；欧氏距离则随长度差变化。
- 温度越低，最大概率越集中（T=0.1 时接近 one-hot）；温度越高，分布越平（T=5 时三项接近均匀）。

### 6.2 矩阵乘法：迷你注意力打分

```python
import numpy as np

rng = np.random.default_rng(42)

d_k = 4  # 词向量维度（示意）
n = 3    # 句子长度：3 个 token
Q = rng.normal(size=(n, d_k))  # 3 个"提问"向量
K = rng.normal(size=(n, d_k))  # 3 个"名片"向量
V = rng.normal(size=(n, d_k))  # 3 个"内容"向量

# 注意力核心三步（完整推导见 0.4）
scores = Q @ K.T / np.sqrt(d_k)  # 3x3：一次矩阵乘法算出全部 9 对 token 的点积打分
weights = np.exp(scores - scores.max(axis=-1, keepdims=True))
weights = weights / weights.sum(axis=-1, keepdims=True)  # 按行做 softmax，每行和为 1
output = weights @ V  # 3x4：按权重加权融合内容向量

print("打分矩阵（谁看谁）：\n", np.round(scores, 2))
print("注意力权重（每行和=1）：\n", np.round(weights, 2))
```

读代码要点：`Q @ K.T` 一次矩阵乘法完成全部两两打分；除以 `sqrt(d_k)` 是防止维度大时点积过大、softmax 进饱和区（梯度消失）。这三行就是 0.4 注意力的最小骨架。

### 6.3 延迟分位数与小样本置信区间

```python
import numpy as np

rng = np.random.default_rng(7)

# 模拟 200 次 Agent 调用延迟（ms）：主体 100-200，长尾偶尔破秒
latencies = np.concatenate([
    rng.normal(150, 30, 190),
    rng.uniform(800, 3000, 10),
])

print(f"均值: {latencies.mean():.0f} ms")   # 约 230ms，被 10 个长尾拉高
print(f"P50 : {np.percentile(latencies, 50):.0f} ms")  # 约 150ms，主体体感
print(f"P95 : {np.percentile(latencies, 95):.0f} ms")  # 长尾开始暴露
print(f"P99 : {np.percentile(latencies, 99):.0f} ms")  # 最差体验，接近 3000ms

# 小样本成功率评估的置信区间（正态近似，示意）
def ci_for_accuracy(success: int, total: int, z: float = 1.96):
    p = success / total
    se = np.sqrt(p * (1 - p) / total)  # 标准误
    return p - z * se, p + z * se

lo, hi = ci_for_accuracy(success=40, total=50)
print(f"成功率 80%（n=50）的 95% 置信区间：[{lo:.2f}, {hi:.2f}]")
# 约 [0.69, 0.91]——区间太宽，不足以判定两个版本谁更好
```

预期观察：5% 的长尾样本把均值拉高近 80ms，而 P50 纹丝不动；只看均值会严重高估服务质量。n=50 的评估，结论要带着置信区间一起说。

## 7. 案例

### 案例 A：RAG 为什么用余弦相似度

场景：客服知识库检索。

用户问："如何退货？"
知识库有：

- 文档 A："退货流程是……"（短，约 120 token）
- 文档 B："退货政策有效期……"（长，约 800 token）

做法：问题与两篇文档分别嵌入后算相似度。示意数字：与 A 的余弦相似度 0.87，与 B 的 0.62，A 胜出被检索。

如果只看欧氏距离：长文档 B 的嵌入模长更大，与问题向量的距离被"长度"拉大，排序可能翻转——文档只是变长、语义没变，检索结果却变了，这不可接受。工程做法：入库前对嵌入做 L2 归一化，此后点积与余弦等价，向量库直接用内积加速（见 0.7、1.4）。

### 案例 B：Agent 工具调用为什么温度不能太高

场景：某电商客服 Agent，调用内部工单系统，工具调用要求输出严格 JSON。

温度与输出质量的复盘数据（示意量级）：

| temperature | JSON 解析失败率 | 幻觉参数率 |
|---|---|---|
| 1.0 | 约 8% | 约 5% |
| 0.3 | 约 1% | 约 1% |
| 0 | 约 0.2% | 接近 0 |

原因：温度高 → 低概率 token 也有机会被采样 → 格式错误、幻觉参数增多。对策：生产环境的工具调用与结构化输出常用 `temperature=0` 或很低的值；创作类场景才用高温。采样参数细节见 0.5、0.6。

### 案例 C：为什么平均延迟会骗人

场景：一家金融科技公司的问答 Agent，链路为"检索 → 重排 → 生成"三步。

- 平均延迟 200ms，看起来达标（SLA 500ms）。
- 实测 P95 = 1.2s，P99 = 3s。

1% 的请求（按每天 40 万次调用算约 4000 次）体验极差。更麻烦的是多步串联的方差叠加：每步各自的 P99 串成一条链，总 P99 比"各步 P99 之和"还差。对策：给中间步骤设超时与降级路径（如重排失败直接用粗排结果），监控与 SLA 只认 P95/P99。评估工具与指标体系见 1.4 的 RAG 评估一节。

### 案例 D：用期望做成本预算

场景：多轮 Agent，平均 6 轮对话，每轮输入约 3000 token、输出约 500 token。

```text
期望成本/次会话 = 6 × (3000 × 输入单价 + 500 × 输出单价)
```

代入示意单价（输入 0.15 美元/百万 token、输出 0.6 美元/百万 token）：单次会话约 6 × (0.00045 + 0.0003) = 0.0045 美元；日均 10 万次会话约 450 美元/天。多轮 Agent 的 token 消耗是复利式增长，不算期望值，预算必然事后爆。

## 8. 常见坑

1. **以为必须精通数学才能做 Agent**。  
   不需要。理解概念 + 会调用库即可，深入数学按需回填。

2. **混淆余弦相似度和欧氏距离**。  
   嵌入检索通常用余弦相似度；某些向量库默认内积或欧氏距离，要看清配置再上线。

3. **嵌入没归一化就切换度量方式**。  
   未归一化时点积不等于余弦；度量与索引类型不匹配，检索排序会悄悄漂移。入库前统一 L2 归一化。

4. **温度调太高导致输出不稳定**。  
   工具调用、结构化输出、评估场景建议低温。

5. **temperature 和 top_p 同时盲调**。  
   两者都作用于分布形状，同时调无法归因效果。先固定一个、只调另一个。

6. **只看平均值，不看长尾**。  
   Agent 多步调用会放大延迟，P99 很关键；均值只配做成本口径，不配做体验口径。

7. **把概率当事实**。  
   LLM 输出是概率采样，不是数据库查询，所以需要 RAG、工具、验证器。

8. **忽略 token 的期望成本**。  
   多轮 Agent 的 token 消耗是复利式增长，要估算期望值再定预算与限流。

9. **小样本评估就下结论**。  
   n=50 时成功率 80% 的置信区间约 [0.69, 0.91]，两个版本的差距落在这个宽度内都不算数。先按目标精度反推样本量。

10. **混淆相关与因果**。  
    没控制变量的一切"改了提示词（Prompt）后指标涨了"，可能只是波动或混杂因素。A/B 测试之外的对比只能当线索，不能当证据。

## 10. 小结

- 数学与统计基础是 Agent 工程的"底层词汇"，定位是背景支撑，不是数学专业课。
- 向量解决"怎么表示"：落点是嵌入与语义检索，核心工具是点积与余弦相似度。
- 矩阵解决"怎么变换"：矩阵乘法是批量点积，是注意力打分与前向传播的骨架。
- 概率解决"怎么生成"：LLM 每步都在按条件概率抽签，温度与 top_p 只是在重塑和截断这个分布。
- 损失函数解决"什么算错"：分类用交叉熵（负对数似然），回归用 MSE；梯度下降负责把损失降下来，交叉熵与最大似然的等价性把概率与训练接通。
- 统计解决"怎么决策"：均值看成本、分位数看体验、置信区间防小样本忽悠、A/B 测试防因果误判。
- 重点掌握：向量、点积、余弦相似度、Softmax、温度、期望、分位数；微积分和训练细节了解即可，能读懂损失曲线就够用。
- 这些概念会直接出现在 RAG、采样、评估、成本控制中：检索的每一次排序、采样的每一个参数、监控的每一条 SLA，背后都是本篇的某一行公式。
- 这些能力直接支撑：0.3 机器学习/深度学习基础、0.4 NLP 与 Transformer、0.5 LLM 基础。
