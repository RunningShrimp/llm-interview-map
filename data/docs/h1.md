# 讲解 H1 推理模型与测试时扩展（R1/o 系列）

> 说明：1.2 的思维链（CoT）是提示词版「打草稿」，0.5c 的 RLHF/DPO 是对齐机制地基——本篇讲两者的合流产物：推理模型（Reasoning Model，DeepSeek-R1、OpenAI o 系列），核心是把算力花在推理时，用思考 token 换准确率。  
> 这种深度思考能力从哪来？训练侧答案在 H2（RLVR 与 GRPO 对齐）；测试时算力的另一种花法见 H4（Agentic RAG）。

---

## 1. 定位

S4 前沿层开篇锚点（deps：1-2、0-5c）。站点状态口径：**面试出现中**——2026 中文题库持续覆盖推理模型模块，英文侧 RLVR/推理系列备考内容活跃，考点卡来源标注为「DeepSeek-R1（Nature 2025）/OpenAI 官方」。

它回答 2025 年以来最高频的前沿面试问题：**推理模型和普通模型差在哪？什么时候该用？成本怎么算？**

三个支柱：

1. **现象层**：测试时扩展（Test-Time Scaling）是什么，串行长 CoT 与并行采样两条路线怎么分。
2. **机制层**：R1-Zero 纯 RL 为什么能涌现反思行为（aha moment），R1 的 Nature 发表口径。
3. **工程层**：thinking budget / reasoning_effort 怎么权衡，「想更多未必更好」的极限与效率质疑。

前置关系：1.2 的提示词 CoT 是「请它写过程」，推理模型是被 RL 训练出内化的深度思考——后者质量高一个量级。0.5c 的 PPO/DPO 是理解 H2 训练机制的门槛。后续 H2 讲能力来源，H4 讲测试时算力的检索侧花法。

## 2. 一句话定义

测试时扩展（Test-Time Scaling，又称推理时扩展）：回答问题时给模型更多「思考算力」——推理模型先生成长思维链（验证、回溯、多路径尝试）再给答案，思考越久越准，本质是用推理成本换复杂任务的准确率，与训练时扩展互补的第二条扩展曲线。

## 3. 为什么需要

传统 Scaling Law（训练时扩展）在 2024 年后遇到三重挤压：

1. **数据墙**：高质量训练文本接近耗尽，堆数据的边际收益递减。
2. **算力墙**：预训练一次的成本量级太高，不可能频繁重训。
3. **能力墙**：有些任务（多步数学、代码调试、长程规划）不是「知道得更多」能解决的，是单次前向传播的计算量不够——一步算不出需要十步推导的答案。

直觉类比：普通模型像抢答选手，问题读完立刻作答；推理模型像允许打草稿的考生——先列已知、尝试思路、检查一遍再写答案。难题上草稿越多分越高，简单题草稿几行就够。测试时扩展研究的正是：**草稿纸给多少最划算。**

2024 年 OpenAI o1 发布、2025 年初 DeepSeek-R1 开源，业界确认了第二条扩展曲线：同一个模型，推理时多生成一个量级的思考 token，数学与代码成绩还能继续上涨。这条曲线把「智能」从一次性前向变成了**可分配预算的资源**——于是推理时扩展从研究话题变成工程问题：花多少、怎么花、何时停。

| 维度 | 训练时扩展 | 测试时扩展 |
|---|---|---|
| 扩展变量 | 参数量、数据量、训练 FLOPs | 思考 token 数、采样数 |
| 成本属性 | 一次性（训练完成即摊销） | 每次请求都付 |
| 交付形态 | 更好的权重 | 更长的推理过程 |
| 收益曲线 | 服从幂律，边际递减明显 | 随测试时计算量对数提升 |
| 代表节点 | GPT-4 时代的预训练竞赛 | o1（2024-09）、R1（2025-01） |
| 工程抓手 | 数据配比、分布式训练 | 难度路由、思考预算分档 |

**关键结论：两条曲线互补而非替代。测试时扩展的收益以模型基座能力为下限，堆推理算力不能弥补基座不会的知识。**

还要纠正一个面试常见混淆：测试时扩展不等于「把温度调高多试几次」。它的成立条件有三——任务答案可判定（否则无从谈「越想越准」）、模型基座具备潜在能力（概率非零，RL 或采样才能放大）、算力可分配（思考 token 是显式预算）。三者缺一，「多想」只是多花钱。

## 4. 核心原理

### 4.1 推理模型的本质：内化的长思维链

推理模型的输出分两段：先产出大量中间推理 token（self-check、回溯、换思路重试），再输出最终答案。与 1.2 提示词 CoT 的区别：

| 维度 | 提示词 CoT（1.2） | 推理模型 |
|---|---|---|
| 触发方式 | 人工写「请一步步思考」 | RL 训练出的自发行为 |
| 思考质量 | 浅、易跑偏、不回溯 | 长、带验证回溯、多路径尝试 |
| 稳定性 | 依赖提示词与模型心情 | 行为内化，跨任务稳定 |
| 可控性 | 只能靠措辞引导 | reasoning_effort / 思考预算旋钮 |

注意：推理痕迹越长的模型，输出里的「思考段」通常越不可直接信赖（中间结论可能自我推翻），**答案以最终结论为准，不要把思考过程当事实引用**。

### 4.2 测试时扩展的两条路线

```text
路线 A：串行长 CoT（Serial Long CoT）
  问题 → 思考 → 验证 → 发现疑点 → 回溯 → 换思路 → 再验证 → 答案
  一条链越走越长，算力花在「链的长度」上

路线 B：并行采样（Parallel Sampling）
  问题 → 采样 N 条独立回答 → 判分/投票/验证器挑选 → 答案
  算力花在「样本数量」上
```

| 维度 | 串行长 CoT | 并行采样 |
|---|---|---|
| 机制 | 链内反思、回溯，动态分配深度 | 独立多次生成，事后聚合 |
| 延迟形态 | 首 token 前/全程串行，延迟随预算线性涨 | 可并发，延迟≈单条最长链 |
| 成本曲线 | 思考 token 按链长计费 | N 倍输出 token |
| 增益来源 | 难题的深度探索 | 方差消除（对随机性错误有效） |
| 典型失效 | 过度思考：简单题绕远、答案漂移 | 多数投票在开放题上失效；N 条一起错 |
| 代表 | o 系列、R1 | self-consistency（1.2 的训练强化版）、verifier 重排 |
| 面试口径 | 推理模型默认路线 | o1 官方博客中与之并列的早期路线 |

两条路线可叠加：先长链思考、再对最终答案并行投票。2025 年已有系统研究分别刻画两条曲线的收益形状（「思考预算」方向的 arXiv 2507.02076 与「并行测试时扩展」方向的 arXiv 2507.14419，均 2025）：共同结论是**收益随算力对数增长，且强烈依赖任务难度**——太简单的任务加算力无收益，超出能力的任务加算力也无收益，中间带收益最陡。

路线选择的工程判断：

1. **错误来源判断法**：错误是「单条链推理深度不够」还是「采样方差太大」？前者选串行（加深），后者选并行（去方差）。同题多次采样答案高度分散 → 并行有效；答案一致但都错 → 只能靠加深或换模型。
2. **任务可聚合性判断法**：答案可机器判分/可多数投票（数学、选择题）→ 并行便宜有效；开放生成、代码大改 → 聚合困难，串行为主。
3. **延迟预算判断法**：交互场景无法接受串行长链的全程等待 → 并行并发压延迟，或流式输出思考摘要；离线批处理 → 串行深挖优先。

面试高频追问「既然并行采样更早就有（self-consistency），推理模型新在哪」——标准答法：并行路线靠的是事后聚合提示词技巧，串行长 CoT 是 RL 训练出的**内化行为**，能在线自我纠错而不必等 N 条跑完再挑；两者叠加才是完整的测试时扩展。

### 4.3 R1-Zero：纯 RL 涌现与 aha moment

DeepSeek-R1-Zero 是里程碑实验：**跳过 SFT 冷启动，直接在基座模型（V3）上做纯强化学习（GRPO + 可验证奖励，机制见 H2）**，只给「答案对不对」的奖励信号，不教任何推理格式。

训练中观察到的现象：

1. 推理痕迹自发变长——没人教，模型自己学会「多想几步」。
2. 自发出现反思、验证、回溯行为。R1 论文记录了著名的训练样本：
   > 「Wait, wait. Wait. That's an aha moment I can flag here. Let me reevaluate this step-by-step to figure out if I can optimize it further.」（等等，等等。这是一个我能标记的 aha moment。让我逐步重新评估……）
3. 代价：可读性差、中英文混杂、思考段格式混乱。

R1 生产版的流水线修正了这些问题（详见 5 节流程图）：先用少量长 CoT 数据做冷启动 SFT，再推理导向 RL，然后用拒绝采样造数据做全场景 SFT，最后做全场景 RL，并把能力蒸馏到 1.5B–70B 的小模型。

| 版本 | 训练方式 | 特点 | 适用 |
|---|---|---|---|
| R1-Zero | 纯 RL，无 SFT | 涌现反思行为；可读性差 | 研究验证：能力可从奖励信号涌现 |
| R1 | 冷启动 SFT + 多阶段 RL | 可读、对齐好、AIME 2024 pass@1 79.8% | 生产与后续研究的基线 |
| R1-Distill | R1 数据蒸馏 1.5B–70B | 小模型获得推理能力 | 端侧/低成本部署 |

**面试口径：R1-Zero 的意义不是性能最强，而是证明「推理行为可以不靠人类示范、纯从可验证奖励中涌现」——这是对「LLM 能力来自模仿人类」假设的直接冲击。**

### 4.4 thinking budget / reasoning_effort：预算旋钮与权衡

主流厂商把思考量做成 API 旋钮：

| 旋钮 | 提供方 | 取值 | 语义 |
|---|---|---|---|
| reasoning_effort | OpenAI o 系列（现役 o3 / o4-mini） | low / medium / high | 思考 token 预算档位 |
| thinking.budget_tokens | Anthropic（extended thinking） | 整数，最小 1024 | 显式思考 token 预算 |
| 生成上限（开源 R1 类） | 自部署 | max_tokens | 间接控制链长上限 |

三档 effort 的权衡（示意量级，随模型与任务浮动）：

| 档位 | 思考量 | 延迟 | 单次成本 | 收益特征 |
|---|---|---|---|---|
| low | 短链 | 低 | 1x | 简单任务足够；难题准确率掉 |
| medium | 中 | 中 | 3–5x | 默认档；多数中等难度任务收益/成本最优 |
| high | 长链 | 高 | 10x+ | 难题陡峭收益；简单任务纯浪费 |

工程关键认知：

1. **思考 token 不可见但计费**：API 返回的思考段通常被隐藏或摘要，但按输出 token 全额计费。必须单独监控 reasoning_tokens 指标。
2. **输出上限包含思考 token**：OpenAI 侧 max_output_tokens、Anthropic 侧 max_tokens 都覆盖思考段。预算设太小，思考还没写完答案就被截断，响应状态为 incomplete。
3. **思考段不是答案**：抽取最终答案要按协议（如答案区段标记）解析，不能拿思考段最后一句当结论。

静态分档之外，还有动态预算的进阶玩法——用首轮信号在线调档：

1. **难度后验信号**：思考段出现多次「等等，再验一遍」式自我修正 → 题目偏难，允许追加思考轮或升档重试；一步直答型输出 → 题目偏易，下一批同类请求降档。
2. **错误反馈回路**：线上 bad case 回流标注后，统计「哪些意图 × 哪些 effort 档位出错」，反向修路由规则——路由阈值是运营出来的，不是拍出来的。
3. **双测试集验证**：建「难题集 + 简单题集」两套回归集，路由策略的目标准确率就是「难题不降分、简单题不多花钱」，每次改阈值跑一遍。

### 4.5 极限与效率：想更多未必更好

2026 年研究焦点已从「能不能」转向「值不值、何时停」：

1. **Mirage 质疑**：OpenReview 论文《Does Thinking More Always Help? Mirage of Test-Time Scaling》指出：更多测试时计算并不总带来提升——长链在部分任务上引入更多错误路径，性能曲线存在峰值点，之后的「扩展」是幻象（mirage）。
2. **过度思考（overthinking）**：简单任务上推理模型走远路、反复验证本无歧义的步骤，不仅贵，还可能把对的改成错的。
3. **成本效率对比口径**：社区常见对比是 R1 以约 4% 的调用成本达到 o 系列旗舰相当的 AIME 精度（79.8%）——开源模型把「测试时扩展」的门槛从独家能力变成了普惠 commodity。
4. **边界条件**：测试时扩展的收益依赖任务可验证性（答案能判对错才有强化方向）与基座能力（基座不会的，想再久也想不出来）。对开放对话、纯创意生成，长链收益有限。

**面试口径：被问「测试时扩展是不是无限定律」时，标准答案是「对数曲线 + 难度窗口 + 可验证性前提」三条件，能主动说出 Mirage 类质疑与自适应思考（何时停）是 2026 的加分项。**

由「想更多未必更好」直接引出 2026 的前沿方向——自适应思考（adaptive / efficient reasoning）：

1. **难度感知停止**：训练模型自己判断「想够了」，简单输入早停、难题深挖，而非外挂固定预算。
2. **思考长度正则**：训练时对无效长链施加惩罚，抑制 overthinking（与 RLVR 训练侧的长度惩罚奖励呼应，见 H2）。
3. **级联推理**：普通模型先答 + 置信度门槛，低置信才升级推理模型——把路由做进推理栈内部。

这一方向与 H2 的训练侧（奖励里加效率项）和本篇的推理侧（预算路由）在合流：**「何时想、想多久」正在从 API 旋钮变成模型内生能力。**

### 4.6 R1 的 Nature 发表口径

DeepSeek-R1 于 2025-01 以预印本发布（arXiv 2501.12948），同年通过 Nature 同行评审正式发表（Nature，s41586-025-09422-z）。引用层级因此变化：**它是「期刊论文」而非仅预印本**——面试与文档中引用时权威度更高，可按 Nature 2025 口径引用。o 系列现役至 o3 / o4-mini，o1 首发于 2024-09（OpenAI 官方博客《Learning to Reason with LLMs》，其中即提出「生成多条链挑最好」与「长链 + 强化学习」两条扩展路线的划分）。

## 5. 架构 / 流程

一次推理请求的完整生命周期（生产视角）：

```text
用户请求
   ↓
[1] 意图/难度路由
    闲聊、翻译、格式转换 ──────────→ 普通模型直答（零思考预算）
    多步数学、调试、规划、证明 ────→ 推理模型
   ↓
[2] 思考预算分档
    预估难度 → effort 档位（medium 默认 / high 竞赛级）
    设置 max_output_tokens（含思考！）与超时
   ↓
[3] 长链生成
    思考 token：验证、回溯、多路径尝试（不可见但计费）
   ↓
[4] 答案抽取与校验
    按协议解析最终答案（区别于思考段）
    可选：并行采样 N 条 + 投票/验证器聚合
   ↓
[5] 观测与护栏
    reasoning_tokens 监控、单请求思考上限、日预算熔断
    incomplete 率告警（= 思考吃光输出预算的信号）
```

能力来源侧（与 H2 衔接）——R1 流水线：

```text
基座 V3
   ↓ 纯 RL（GRPO + 可验证奖励，无 SFT）
R1-Zero ──→ 涌现：反思 / 自我验证 / aha moment
   ↓ 冷启动 SFT（少量高质量长 CoT 数据，修可读性）
推理导向 RL（更多可验证任务、语言一致性奖励）
   ↓ 拒绝采样 + SFT（全场景数据）
   ↓ 全场景 RL（对齐 + 推理保持）
R1（生产版）
   ↓ 蒸馏（SFT 到 1.5B–70B 小模型）
R1-Distill 系列（端侧 / 低成本推理能力）
```

## 6. 代码 / 工具

### 6.1 reasoning_effort 调用对比

```python
from openai import OpenAI

client = OpenAI(api_key="YOUR_KEY")

HARD_PROBLEM = (
    "证明：对任意正整数 n，n^5 + n^3 + n 的个位数字等于 n 的个位数字。"
    "要求分情况讨论并给出完整证明。"
)

def ask_with_effort(effort: str) -> dict:
    """同一个难题，不同 reasoning_effort 各跑一次，对比正确率与开销。"""
    resp = client.responses.create(
        model="o4-mini",
        reasoning={"effort": effort},       # low / medium / high
        max_output_tokens=32768,            # 注意：包含思考 token
        input=[{"role": "user", "content": HARD_PROBLEM}],
    )
    usage = resp.usage
    think = usage.output_tokens_details.reasoning_tokens
    return {
        "effort": effort,
        "status": resp.status,              # high 档最可能出现 incomplete
        "answer": resp.output_text,         # 最终答案（思考段已隐藏）
        "reasoning_tokens": think,          # 思考量：不可见但计费
        "output_tokens": usage.output_tokens,
        "思考占比": f"{think / max(usage.output_tokens, 1):.0%}",
    }

for e in ("low", "medium", "high"):
    print(ask_with_effort(e))
```

Anthropic 侧对应写法（显式预算）：

```python
import anthropic

client = anthropic.Anthropic()
resp = client.messages.create(
    model="claude-sonnet-4-5",
    max_tokens=16000,                                    # 必须 > 思考预算
    thinking={"type": "enabled", "budget_tokens": 10000},  # 最小 1024
    messages=[{"role": "user", "content": HARD_PROBLEM}],
)
thinking_text = "".join(b.thinking for b in resp.content if b.type == "thinking")
```

### 6.2 思考预算成本测算

```python
# 成本测算：思考 token 也是钱。单价为示意量级，以各家现价为准。
PRICE = {                                # 单位：美元 / 百万 token（示意）
    "normal": {"in": 0.15, "out": 0.60},   # 普通模型
    "reason": {"in": 1.10, "out": 4.40},   # 推理模型
}

def cost(in_toks: int, out_toks: int, p: dict) -> float:
    return in_toks / 1e6 * p["in"] + out_toks / 1e6 * p["out"]

def estimate(task: str, in_toks: int, think_toks: int, ans_toks: int) -> None:
    """同一请求在「直答」与「三档思考预算」下的成本对比。"""
    if task == "easy":
        c = cost(in_toks, ans_toks, PRICE["normal"])
        print(f"普通模型直答：思考 0 tok，成本 ${c:.5f}")
        return
    for effort, mult in (("low", 1), ("medium", 4), ("high", 12)):
        t = think_toks * mult
        c = cost(in_toks, t + ans_toks, PRICE["reason"])
        print(f"{effort:>6}：思考 {t:>6} tok，成本 ${c:.5f}")

estimate("easy", 800, 1500, 120)   # 简单任务：直答即可
estimate("hard", 800, 1500, 400)   # 难题：high 档成本约为 low 档的 8 倍
```

运行结论（示意）：难题上 high 档成本是 low 档约 8 倍，换来的准确率增益集中在难题；简单任务上推理模型直答成本已是普通模型的约 20 倍——这就是路由存在的理由。

### 6.3 难度路由器（最小实现）

```python
import re

HARD = re.compile(r"(证明|求解|推导|调试|Traceback|规划|优化|多步|为什么.*如何)", re.I)

def route(query: str) -> dict:
    """两段式路由：先判任务类型，再按难度分档思考预算。"""
    if HARD.search(query):
        effort = "high" if len(query) > 200 else "medium"   # 示意：题干复杂度分档
        return {"model": "reasoning", "reasoning_effort": effort,
                "max_output_tokens": 32768}
    return {"model": "normal", "temperature": 0}            # 简单任务零思考预算

# 生产化补齐：分类器替换正则、双测试集（难题集+简单题集）回归调阈值、
# 单请求思考 token 上限 + 日预算熔断 + reasoning_tokens 专项监控。
```

## 7. 案例

### 案例 A：数学辅导产品的思考预算路由

**场景**：某教育公司的「拍照解题 + 日常答疑」App，同时接入普通模型与推理模型，此前全部流量走推理模型 high 档。

**改造**：正则+小分类器做意图路由（答疑/翻译/闲聊走普通模型），解题按题干复杂度分 medium/high；单请求思考 token 上限 32k，日预算熔断；建「难题集 + 简单题集」双测试集回归路由阈值。

**效果**（示意量级）：整体推理成本下降 70%；难题（奥数/竞赛题）准确率 61% 提升到 83%（high 档只给难题）；简单答疑 P95 延迟从 12s 降到 1.8s。核心教训：**先想清楚「哪里需要想」，再谈模型多强。**

### 案例 B：调试 Agent 的输出预算事故

**场景**：一家金融科技公司的报表核对 Agent 接入推理模型处理差异归因，上线后大量请求「没给答案」。

**排查**：incomplete 率 12%——max_output_tokens 沿用了普通模型的 4096，思考 token 把预算吃光，答案还没开始写就被截断。

**修复**：按 effort 档位设置输出预算（medium 给 16k、high 给 32k），并对 incomplete 状态自动重试一次（预算翻倍）。

**效果**：incomplete 率降到 1% 以下；差异归因准确率 58% 提升到 79%。教训：**推理模型的输出上限必须包含思考段，监控要盯 incomplete 率。**

### 案例 C：过度思考治理

**场景**：某电商客服机器人换成推理模型后，成本翻 15 倍，且「退货政策是什么」这类简单问题偶发答非所问（长链把用户绕晕）。

**改造**：意图路由回退普通模型；对保留的推理调用做「过度思考」检测——思考 token 超过答案 token 20 倍且答案为一步直答型，标记为可疑样本回灌路由规则。

**效果**：成本回落到原来的 1.8 倍；简单题满意度回升；这批数据成了向业务方解释「推理模型不是万金油」的最好材料。

## 8. 常见坑

1. **简单任务拉满思考预算**。翻译、格式转换用 high 档纯属烧钱；对策：意图路由 + 零思考预算直答。
2. **不知道思考 token 计费**。只盯可见输出 token 估算成本，账单翻倍才反应过来；对策：单独监控 reasoning_tokens。
3. **输出上限忘了含思考段**。答案被思考吃掉预算，incomplete 收场；对策：按 effort 档位配置 max_output_tokens 并告警 incomplete 率。
4. **把提示词 CoT 等同于推理模型**。提示词只能引导表达，训练才内化行为；对策：难题直接换推理模型，别在提示词上死磕。
5. **路由只按意图不按难度**。同是「解题」，口算和竞赛题预算应不同；对策：两段式路由（类型 + 难度分档）。
6. **相信「想越多越好」的线性外推**。长链在部分任务上引入错误路径（Mirage 类质疑）；对策：按任务实测收益曲线，找到峰值点就停。
7. **忽略延迟体验**。长链推理首响慢，交互场景用户直接流失；对策：流式输出思考摘要或改异步任务。
8. **把思考段当事实引用**。思考是探索过程，中间结论会自我推翻；对策：只引用最终答案区段。
9. **并行采样不做聚合设计**。多数投票对开放生成题失效，N 条一起错时投票无意义；对策：可验证任务才投票，开放任务换 verifier 或人工抽检。
10. **成本护栏缺失**。没有单请求/日预算上限，异常流量直接打穿账单；对策：思考 token 专项熔断与告警。
11. **引用 R1 时不区分口径**。R1-Zero（纯 RL 实验）与 R1（生产版）结论不同；对策：面试引用时明确说哪个版本、什么设定。
12. **忽视版本差异**。o1、o3、o4-mini 能力与价格差异大，「用了推理模型」不等于同档表现；对策：评测集上分模型建档，按档路由。

## 9. 练习

1. 用 6.1 的脚本对同一道奥数题跑 low/medium/high 三档，记录正确率、reasoning_tokens、成本，画出「预算-准确率」曲线。
2. 构造 5 个「一步直答」简单任务，验证推理模型在它们上是否比普通模型更差或更贵，写出路由规则。
3. 实现两段式路由器：意图分类（正则或小模型）+ 难度分档，接双测试集回归，调出「难题不降分、简单题不多花钱」的阈值。
4. 故意把 max_output_tokens 设为 4096 跑 high 档难题，观察 incomplete 状态与截断行为，再修复。
5. 用自部署 R1 类模型对比「限制思考上限 2k」与「放开到 16k」在难题集上的差异，验证串行路线的收益边界。
6. 对同一难题做 best-of-8 并行采样 + 多数投票，对比单条长链的效果与成本，判断该题更适合哪条路线。
7. 给推理调用接入 reasoning_tokens 监控与日预算熔断，模拟异常流量验证护栏生效。

## 10. 小结

- 测试时扩展＝推理时算力换准确率，是与训练时扩展互补的第二条扩展曲线。
- 两条路线：**串行长 CoT**（链内反思回溯，o 系列/R1 主路线）与**并行采样**（多条生成聚合投票）。
- R1-Zero 证明推理行为可从**纯 RL + 可验证奖励**中涌现（aha moment：反思与自我验证自发出现）。
- R1 生产版用冷启动 SFT 修可读性，多阶段 RL 保能力，再蒸馏到 1.5B–70B 小模型。
- 预算旋钮：**reasoning_effort（o 系列）/ budget_tokens（Anthropic）/ 生成上限（开源）**，按难度分档是工程关键。
- 两个计费铁律：**思考 token 不可见但计费；输出上限包含思考段**。
- 收益边界：对数曲线 + 难度窗口 + 任务可验证性；「想更多未必更好」是 2026 研究焦点（Mirage 类质疑、overthinking、自适应停止）。
- 引用口径：**DeepSeek-R1 已通过 Nature 同行评审（2025）**，是期刊论文而非仅预印本。
- 成本效率口径：R1 以约 4% 调用成本达到 o 系列旗舰相当的 AIME 精度（79.8%）。
- 生产三件套：**难度路由 + 预算分档 + 思考 token 监控熔断**。
- 能力来源在 H2：RLVR 与 GRPO 才是这台发动机的引擎室。
