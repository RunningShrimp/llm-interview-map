# 讲解 3.7 成本、延迟与可靠性

> 说明：3.6 讲了部署与扩展，3.7 讲**上线之后最现实的三件事**：钱够不够、快不快、稳不稳。  
> 核心问题：**如何在效果、成本、延迟、可靠性之间做工程权衡，让 Agent 商业上可行、体验上可接受、运行上可信？**  
> 后续 3.8 讲安全合规、3.9 讲 CI/CD 与发布、3.10 讲人机协同，都要复用本篇的预算、降级与重试机制。

---

## 1. 定位

AI 工程化层第 7 个知识点，属于“生产运行约束”。  
它解决一个核心问题：**Agent 上线后，如何持续控制成本、优化延迟、保证可靠性，而不是“能跑就行”？**

它是 3.8 安全、合规与权限、3.9 CI/CD、版本管理与发布、3.10 人机协同与反馈闭环的直接前置；4.4 浏览器/计算机使用 Agent 的稳定性设计，也直接复用本篇的超时、重试与降级机制。

## 2. 一句话定义

成本、延迟与可靠性，是在效果约束下，通过模型路由、缓存、并行、降级、重试、幂等、容量规划等手段，实现“花得少、响应快、跑得稳”的系统工程能力。

简化公式：

```text
生产可行性 = 效果达标 × 成本可承受 × 延迟可接受 × 可靠性可保障
```

## 3. 为什么需要

Demo 阶段只关心“能不能回答”。  
生产阶段：

- **成本**：一次 Agent 任务 10 次 LLM 调用，日活 1 万就是 10 万次调用。GPT-4o 量级的模型一次调用 $0.01 量级，一天 $1000，一个月 $3 万。
- **延迟**：串行 5 步，每步 2 秒，用户等 10 秒。P99 可能 30 秒。
- **可靠性**：LLM API 限流、超时、故障；工具服务挂掉；网络抖动。
- **容量**：峰值 QPS 是均值的 10 倍，按峰值配置浪费，按均值配置崩溃。
- **SLA**：承诺 99.9% 可用，一年只能停 8.76 小时。
- **幂等（Idempotency）**：重试导致重复退款、重复发邮件。
- **降级（Fallback）**：主模型挂了，整个系统不可用。

**类比**：

```text
Demo = 一辆能开的车
生产 = 一支车队：油耗、速度、故障率、维修成本都要管
```

## 4. 核心原理

### 4.1 成本模型

**成本构成**：

```text
总成本 = LLM API 成本 + 基础设施成本 + 工具/API 成本 + 人力成本
```

**LLM 成本公式**：

```text
单次成本 = 输入 token × 输入单价 + 输出 token × 输出单价
```

**Agent 成本放大**：

```text
单 Agent 任务成本 = Σ(每步 LLM 调用成本) + Σ(工具调用成本) + 检索成本
```

举例：

```text
Step 1 规划: 500 in + 200 out = $0.003
Step 2 决策: 800 in + 100 out = $0.004
Step 3 工具: $0.001
Step 4 决策: 1000 in + 100 out = $0.005
Step 5 反思: 1200 in + 300 out = $0.008
总计: ~$0.021/任务
日 1 万任务: $210/天 = $6300/月
```

### 4.2 成本优化策略

| 策略 | 节省 | 实现难度 | 适用 |
|---|---|---|---|
| 模型分层 | 5–10x | 低 | 所有 |
| 缓存 | 视命中率 | 低 | FAQ、分类 |
| 语义缓存 | 20–40% | 中 | 问答 |
| 上下文压缩 | 30–70% | 中 | 长对话 |
| Prompt 精简 | 10–30% | 低 | 所有 |
| 输出限制 | 视场景 | 低 | 所有 |
| 批处理 | 视场景 | 中 | 离线 |
| 路由 | 3–5x | 中 | 混合任务 |
| 小模型微调 | 5–10x | 高 | 固定任务 |
| 本地部署 | 视规模 | 高 | 大规模 |

**成本归因**：

```python
class CostTracker:
    def __init__(self):
        self.costs = defaultdict(float)

    def record(self, model, input_tokens, output_tokens, **labels):
        cost = calculate_cost(model, input_tokens, output_tokens)
        for dim, value in labels.items():
            self.costs[(dim, value)] += cost
        return cost

    def report(self, dimension: str) -> dict:
        return {
            k[1]: v for k, v in self.costs.items() if k[0] == dimension
        }
```

归因数据来自链路追踪：每个 span 携带 token 用量与模型单价，就能按模型、租户、任务任意维度拆账（trace 细节见 3.4）。

**面试高频问法**：“老板要求 LLM 成本降 10 倍（或账单降 60%），高价值场景质量不能掉，你怎么做？”共识口径是按杠杆顺序分层落地：先**计量归因**，把账单按模型/租户/任务拆开找到大头；再依次上**缓存（精确 + 语义）→ 模型路由/级联（简单任务下沉小模型）→ 上下文与输出压缩 → 批处理**；每上一项杠杆都过一道质量门禁（见 3.5），评估集证明效果没掉再放量——降本不等于降质。

### 4.3 延迟模型

**延迟组成**：

```text
总延迟 = 网络 + 排队 + 嵌入 + 检索 + LLM 推理 + 工具执行 + 后处理
```

**Agent 延迟放大**：

```text
串行 5 步，每步 1s → 总延迟 5s
P99 可能 15s（每步 P99 叠加）
```

**关键指标**：

| 指标 | 说明 | 目标 |
|---|---|---|
| TTFT | 首 token 延迟 | < 1s |
| 总延迟 | 完整响应 | < 5s |
| P50 | 中位数 | 基准 |
| P95 | 长尾 | < 10s |
| P99 | 极端长尾 | < 30s |

**面试高频问法**：“用户抱怨 Agent 慢，怎么定位？”共识口径：先拿 trace 把分段耗时拆开（见 3.4）——网络、排队、检索、LLM 推理、工具执行，找到大头再动手；TTFT 慢靠流式输出改善感知，P99 高靠并行化与缓存收长尾，改完用评估集对比验证（见 3.5）。

**SLA / SLO / SLI**：

| 概念 | 说明 | 例子 |

```text
4. 自动恢复
5. 优雅降级

```

### 4.6 重试与幂等

**重试策略**：

```python
async def retry_with_backoff(fn, max_retries=3, base_delay=1.0):
    for attempt in range(max_retries):
        try:
            return await fn()
        except RetryableError as e:
            if attempt == max_retries - 1:
                raise
            delay = base_delay * (2 ** attempt) + random.uniform(0, 1)
            await asyncio.sleep(delay)
        except NonRetryableError:
            raise
```

**哪些可重试**：

| 错误 | 是否可重试 | 说明 |
|---|---|---|
| 429 限流 | 可重试 | 指数退避，优先读 Retry-After 头 |
| 500/502/503 | 可重试 | 服务端偶发故障，稍后通常恢复 |
| 超时 | 可重试 | 必须配幂等，防止重复副作用 |
| 400 参数错 | 不可重试 | 重试同样失败，应修参数或 Prompt |
| 401 认证 | 不可重试 | 检查密钥，重试无意义 |
| 403 权限 | 不可重试 | 检查授权，重试无意义 |

**幂等**：

```python
class IdempotentExecutor:
    def __init__(self, redis):
        self.redis = redis

    async def execute(self, idempotency_key: str, fn, *args):
        # 检查是否已执行
        cached = await self.redis.get(f"idem:{idempotency_key}")
        if cached:
            return json.loads(cached)

        # 执行
        result = await fn(*args)

        # 记录结果，TTL 24h
        await self.redis.setex(
            f"idem:{idempotency_key}",
            86400,
            json.dumps(result),
        )
        return result
```

### 4.7 降级策略

**降级层次**：

```text
L1: 正常路径
L2: 主模型失败 → 备用模型
L3: 备用模型失败 → 缓存结果
L4: 缓存未命中 → 简化回答
L5: 全部失败 → 友好错误 + 人工介入
```

降级响应要显式标注（如返回 `degraded: true`），让上层与用户知道这不是正常质量的答案。

**实现**：

```python
async def resilient_agent(query: str) -> dict:
    try:
        return await primary_agent(query)
    except Exception as e:
        logger.warning(f"Primary failed: {e}")
        try:
            return await fallback_agent(query)
        except Exception:
            cached = await cache.get(query)
            if cached:
                return {"answer": cached, "degraded": True}
            return {
                "answer": "抱歉，服务暂时不可用，请稍后再试。",
                "error": True,
            }
```

### 4.8 熔断与限流

**熔断（Circuit Breaker）**：

```python
class CircuitBreaker:
    def __init__(self, failure_threshold=5, recovery_timeout=60):
        self.failures = 0
        self.threshold = failure_threshold
        self.timeout = recovery_timeout
        self.last_failure = 0
        self.state = "closed"

    async def call(self, fn, *args):
        if self.state == "open":
            if time.time() - self.last_failure > self.timeout:
                self.state = "half-open"
            else:
                raise CircuitOpenError()

        try:
            result = await fn(*args)
            if self.state == "half-open":
                self.state = "closed"
                self.failures = 0
            return result
        except Exception:
            self.failures += 1
            self.last_failure = time.time()
            if self.failures >= self.threshold:
                self.state = "open"
            raise
```

**限流（Rate Limiting）**：

```python
class TokenBucket:
    def __init__(self, rate: float, capacity: int):
        self.rate = rate
        self.capacity = capacity
        self.tokens = capacity
        self.last_refill = time.time()

    def allow(self, tokens: int = 1) -> bool:
        now = time.time()
        elapsed = now - self.last_refill
        self.tokens = min(self.capacity, self.tokens + elapsed * self.rate)
        self.last_refill = now
        if self.tokens >= tokens:
            self.tokens -= tokens
            return True
        return False
```

### 4.9 容量规划

**步骤**：

```text
1. 估算日均请求量
2. 估算峰值系数（通常 3–10x）
3. 估算单请求资源消耗（CPU、内存、延迟）
4. 计算所需副本数
5. 留 30% 余量
6. 配置 HPA 自动伸缩
7. 定期复盘调整
```

第 6 步的自动伸缩与队列削峰属于部署层手段，见 3.6。

**副本数估算**：

```text
所需副本 = (峰值 QPS × 单请求延迟) / 单副本并发能力 × 安全系数
```

举例：

```text
峰值 QPS = 100
单请求延迟 = 2s
单副本并发 = 50
安全系数 = 1.3

副本 = (100 × 2) / 50 × 1.3 = 5.2 → 6 个
```

### 4.10 成本-延迟-可靠性权衡

**三者不可兼得**：

```text
效果 ←→ 成本 ←→ 延迟 ←→ 可靠性
```

| 场景 | 策略 |
|---|---|
| 高价值任务 | 大模型 + 多轮验证 + 高可靠 |
| 普通问答 | 中模型 + 缓存 + 标准可靠 |
| 简单分类 | 小模型 + 批处理 + 基础可靠 |
| 实时交互 | 流式 + 小模型 + 缓存 |
| 离线分析 | 大模型 + 批处理 + 可重试 |

**决策矩阵**：

```text
任务价值高？
├─ 是 → 用大模型 + 高可靠
└─ 否 → 延迟敏感？
    ├─ 是 → 小模型 + 流式 + 缓存
    └─ 否 → 小模型 + 批处理 + 降级
```

```python
from collections import defaultdict

class CostManager:
    def __init__(self, daily_budget: float):
        self.daily_budget = daily_budget
        self.cost_today = 0.0
        self.cost_by_model = defaultdict(float)
        self.cost_by_user = defaultdict(float)

    def record(self, model: str, input_tokens: int, output_tokens: int, user_id: str | None = None):
        cost = calculate_cost(model, input_tokens, output_tokens)
        self.cost_today += cost
        self.cost_by_model[model] += cost
        if user_id:
            self.cost_by_user[user_id] += cost

        # 告警
        if self.cost_today > self.daily_budget * 0.8:
            alert(f"成本已达预算 80%: ${self.cost_today:.2f}")
        if self.cost_today > self.daily_budget:
            raise BudgetExceeded(f"日预算超限: ${self.cost_today:.2f}")

        return cost

    def report(self) -> dict:
        return {
            "today": self.cost_today,
            "budget": self.daily_budget,
            "remaining": self.daily_budget - self.cost_today,
            "by_model": dict(self.cost_by_model),
            "top_users": sorted(self.cost_by_user.items(), key=lambda x: -x[1])[:10],
        }
```

### 6.3 容错执行

```python
async def resilient_execute(
    primary,
    fallbacks: list,
    timeout: float = 30,
    max_retries: int = 3,
    idempotency_key: str | None = None,
):
    # 幂等检查
    if idempotency_key:
        cached = await idempotent_store.get(idempotency_key)
        if cached:
            return cached

    # 主路径
    for attempt in range(max_retries):
        try:
            result = await asyncio.wait_for(primary(), timeout=timeout)
            if idempotency_key:
                await idempotent_store.set(idempotency_key, result)
            return result
        except asyncio.TimeoutError:
            if attempt == max_retries - 1:
                break
            await asyncio.sleep(2 ** attempt)
        except RetryableError:
            if attempt == max_retries - 1:
                break
            await asyncio.sleep(2 ** attempt)
        except NonRetryableError:
            break

    # 降级
    for fallback in fallbacks:
        try:
            return await fallback()
        except Exception:
            continue

    raise AllFallbacksFailed()
```

### 6.4 熔断器

```python
class CircuitBreaker:
    def __init__(self, name: str, failure_threshold=5, recovery_timeout=60, half_open_max=3):
        self.name = name
        self.failure_threshold = failure_threshold
        self.recovery_timeout = recovery_timeout
        self.half_open_max = half_open_max
        self.failures = 0
        self.successes = 0
        self.last_failure_time = 0
        self.state = "closed"

    async def call(self, fn, *args, **kwargs):
        if self.state == "open":
            if time.time() - self.last_failure_time > self.recovery_timeout:
                self.state = "half-open"
                self.successes = 0
            else:
                raise CircuitOpenError(f"{self.name} 熔断中")

        try:
            result = await fn(*args, **kwargs)
            if self.state == "half-open":
                self.successes += 1
                if self.successes >= self.half_open_max:
                    self.state = "closed"
                    self.failures = 0
            return result
        except Exception:
            self.failures += 1
            self.last_failure_time = time.time()
            if self.failures >= self.failure_threshold:
                self.state = "open"
            raise
```

### 6.5 容量规划脚本

```python
import math

def calculate_capacity(
    peak_qps: float,
    avg_latency: float,
    per_replica_concurrency: int,
    safety_factor: float = 1.3,
) -> dict:
    replicas = (peak_qps * avg_latency) / per_replica_concurrency * safety_factor
    return {
        "replicas": math.ceil(replicas),
        "peak_qps": peak_qps,
        "avg_latency": avg_latency,
        "per_replica_concurrency": per_replica_concurrency,
        "safety_factor": safety_factor,
    }

# 使用
plan = calculate_capacity(
    peak_qps=100,
    avg_latency=2.0,
    per_replica_concurrency=50,
)
print(plan)  # {"replicas": 6, ...}
```

## 7. 案例

### 案例 A：成本从 $5000 降到 $500

**问题**：日成本 $5000，商业不可行。

**排查**：先做计量归因（按任务类型拆账单，方法见 3.4），发现 70% 的调用是分类、改写、抽取这类简单任务，却在用主力大模型。

**优化**（依次作用，效果相乘而不是相加）：

```text
基线 $5000
→ 模型路由：70% 简单任务下沉 mini 档（该部分成本降 90%）→ $1850
→ 语义缓存：命中率 40%，命中部分近零成本             → $1110
→ 上下文压缩：输入 token 减半（输入占总成本约 60%）  → $780
→ 输出限制：max_tokens 2000 → 500                    → $620
→ Prompt 精简：系统提示词 3000 → 1500 token          → ≈$500
总降幅 90%；单任务成本 $0.02 → $0.002 量级
```

**质量门禁**：每上一项杠杆，评估集先跑一遍（见 3.5），准确率回退超过 1 分就回滚——降本不能变成降质。

**结果**：日成本 $500，降低 90%，核心质量指标持平。

### 案例 B：P99 从 30s 降到 8s

**问题**：P99 延迟 30 秒，用户流失。

**排查**：

1. Trace：串行 5 步，每步 P99 6s。
2. 工具串行执行。

**优化**：

1. 并行工具调用：3 个工具并行，延迟从 9s 降到 3s。
2. 流式输出：TTFT 从 6s 降到 1s。
3. 缓存：命中时毫秒级。
4. 小模型：简单步骤用 mini。

**结果**：P99 从 30s 降到 8s。

### 案例 C：LLM API 故障自动降级

**问题**：主模型服务商 API 大面积故障，服务不可用。

**处理**：

1. 熔断器检测到连续失败，打开。
2. 自动降级到备用模型（另一家厂商，上线前已通过同样的评估门禁）。
3. 备用也失败，返回缓存结果（响应标注 degraded）。
4. 缓存未命中，返回友好错误。
5. 告警通知，人工介入。

**结果**：故障期间可用性从 0% 提升到 95%（示意）；服务商恢复后熔断器进入半开状态试探成功，自动切回主模型。

## 8. 常见坑

1. **不追踪成本**。  
   月底才发现账单爆炸。实时追踪 + 预算告警。

2. **所有任务用大模型**。  
   成本高 10 倍。模型分层。

3. **不做缓存**。  
   相同请求反复调用。至少精确缓存。

4. **不做上下文压缩**。  
   多轮对话 token 线性增长。摘要 + 滑动窗口。

5. **串行执行**。  
   可并行的串行，延迟高。asyncio.gather。

6. **无超时**。  
   LLM 调用挂住，线程耗尽。所有外部调用包一层 wait_for。

7. **无重试**。  
   偶发失败直接报错。可重试错误加指数退避 + 抖动。

8. **重试不幂等**。  
   重复退款、重复发邮件。

9. **无熔断**。  
   下游挂了，自己也被拖死。

10. **无降级**。  
    主模型挂了整体不可用。至少备一条「备用模型 + 缓存」链路。

11. **不限流**。  
    被刷接口，成本失控。按用户、租户双维限流 + 用量配额。

12. **不看 P99**。  
    平均延迟好看，长尾体验差。监控 P95/P99，按长尾优化。

13. **不做容量规划**。  
    峰值来了才扩容，来不及。按峰值系数提前规划 + 自动伸缩（见 3.6）。

14. **只监控技术指标，不监控业务指标**。  
    延迟低但成功率低，用户照样不满意。技术指标旁并排任务完成率、用户订正率。

15. **成本、延迟、可靠性分开管**。  
    三者互相牵制，单点优化常互相拆台。用 4.10 的权衡矩阵统一决策。

16. **不做 A/B 测试**。  
    优化了但不知道是否真的变好。优化前后跑评估集对比（见 3.5）。

8. 实现限流器，每用户每分钟 60 次。

## 10. 小结

- 成本 = **LLM API + 基础设施 + 工具 + 人力**。
- 成本优化：**模型分层、缓存、压缩、路由、批处理**。
- 延迟 = **网络 + 排队 + 嵌入 + 检索 + LLM + 工具**。
- 延迟优化：**流式、并行、缓存、小模型、压缩**。
- 可靠性：**SLA/SLO/SLI、错误预算、无单点、故障隔离**。
- 容错：**超时、重试、幂等、熔断、降级、限流**。
- 容量规划：**峰值 QPS × 延迟 / 并发能力 × 安全系数**。
- 权衡：**效果、成本、延迟、可靠性不可兼得，按任务价值决策**。
- 核心原则：**能度量才能优化；能降级才能可靠；能并行才能快；能缓存才能省。**
- 这些能力直接支撑：3.8 安全、合规与权限、3.9 CI/CD、版本管理与发布、3.10 人机协同与反馈闭环、4.4 浏览器/计算机使用 Agent。
