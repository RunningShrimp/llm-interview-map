# 讲解 H8 Agent 沙箱与可靠执行

> 说明：2.3 的异常防护（重试上限、熔断、人工在环）是应用层刹车，本篇把安全下沉到基础设施层——沙箱（Sandbox）让「出错可承受」从软件约定变成物理保证。  
> H6 的 Coding Agent 测试循环、4-3 的数据分析 Agent 代码沙箱都是本篇机制的业务落地；2-9b 的复合失败率与 Trace 治理是度量沙箱收益的工具。

---

## 1. 定位

H 层第 8 个锚点（deps：2-3、2-9b）。站点状态口径：**趋势观察**，但要做精确拆分：

- **社区热度高**：沙箱技术本身已是 Coding Agent 的生产标配（E2B/Firecracker/gVisor 路线是基础设施共识），选型对比文与评测持续活跃；安全讨论已从 prompt 安全转向「工具、代码执行、上下文暴露、MCP 权限与审计」。
- **已进面试真题**：作为「隔离技术谱系/微 VM 选型」这一基础设施深度的独立考点，截至 2026-09 未检索到确证真题；但「Agent 执行代码怎么保证安全」这一问题**借道 4-3 已有真题先例**（数据分析 Agent 的代码沙箱，题库含沙箱原文）。面试答法：给足 4-3 的场景答案（隔离+资源上限+产物通道），再向上补出本篇的档位谱系与选型论证，就是超预期。

三个支柱：

1. **原理层**：沙箱三属性（隔离、一次性、可复现）与隔离强度谱系（容器→gVisor→Firecracker microVM）。
2. **选型层**：E2B/Modal/Daytona/自建四条路线，冷启动、GPU 透传、快照恢复的取舍。
3. **治理层**：产物回传与扫描、审计，以及安全焦点从 prompt 转向工具与代码执行后的供应链延伸（Skills/工具包）。

前置关系：2-3 回答「调用出错怎么办」（软件层），本篇回答「执行本身无害化」（物理层）；2-9b 的轨迹评估用来验证沙箱改造前后的失败率与成本。H6 中 Coding Agent 敢大规模重构的前提、H7 中 CUA 执行环境的隔离要求，都在本篇收口。

## 2. 一句话定义

Agent 沙箱是一个隔离、一次性、可复现的受控执行环境：Agent 生成的代码与命令只允许在容器或微 VM（microVM）里运行——破坏被限制在环境内部，任务结束即销毁，需要的结果经显式通道扫描后回传——它是 Agent 从「建议者」升级为「执行者」的安全基石。

## 3. 为什么需要

Agent 写的代码本质是**概率性输出**：它可能算错路径（`rm -rf` 打错目录）、装错包、死循环，甚至被 prompt 注入诱导执行恶意命令。模型层没有「意图可靠性」保证，因此执行层必须假设每一次执行都可能是错的。直接在主机上跑，错误的代价是不可逆的。

| 维度 | 主机直接执行 | 沙箱执行 |
|---|---|---|
| 错误爆炸半径 | 整台主机及其数据 | 容器/VM 内部，销毁即归零 |
| 可逆性 | 删了就是删了 | 环境用完即弃，重跑一次即可 |
| 可复现性 | 主机状态被污染，难复现 | 从干净快照启动，问题可稳定复现 |
| 多任务干扰 | 状态残留互相污染 | 一任务一环境，天然隔离 |
| 审计 | 分散在各处日志 | 执行内容、资源用量、输出集中留痕 |
| 权限面 | 进程权限即用户权限 | 网络禁用/白名单、只读文件系统、降权用户 |

一句话：**隔离不提升模型智力，它把不可靠输出的代价变成可承受的**——这是「可靠执行」中「可靠」二字的工程含义。

## 4. 核心原理

### 4.1 三属性：隔离、一次性、可复现

| 属性 | 含义 | 工程手段 | 反面案例 |
|---|---|---|---|
| 隔离 | 逃不出去：网络、文件系统、进程、权限全面受限 | 禁网/白名单出口、只读根文件系统、降权用户、seccomp | 容器里挂载宿主机 Docker socket+全量凭证 |
| 一次性 | 用完即毁：不跨任务保留任何状态 | 任务结束强制销毁，不复用容器 | 多用户复用同一容器造成交叉泄漏 |
| 可复现 | 从干净快照重启，问题可定位 | 基础镜像版本化、快照与恢复、环境即代码 | 排障时环境已被下一次任务改掉 |

三者是乘法关系：只做隔离不做一次性，状态残留会慢慢磨穿隔离；只做一次性不留快照，排障无从下手。

### 4.2 隔离强度谱系：进程级 → 容器 → gVisor → Firecracker microVM

| 档位 | 代表技术 | 隔离原理 | 冷启动 | 运行开销 | 适用 |
|---|---|---|---|---|---|
| 进程级 | 受限子进程/沙箱库（命名空间+seccomp+资源上限），WASM 运行时近似此档 | 共享宿主内核，仅软限制 | 毫秒级 | 最低 | 本地开发、自家高可信代码 |
| 容器 | Docker/containerd | namespace+cgroups，共享内核 | 秒级 | 低 | 默认档：内部工具、单租户代码执行 |
| 用户态内核 | gVisor（用户态实现的 Linux 内核层） | 在进程与内核间拦截/过滤系统调用，系统调用暴露面大幅收窄 | 秒级（略慢于容器） | 中（syscall 密集场景有明显损耗） | 半可信代码、多租户 SaaS |
| microVM | Firecracker（AWS 开源，Lambda/Fargate 同源技术） | KVM 轻量虚拟机，独立内核+最小设备模型 | 百毫秒级 | 中 | 云端高并发代码执行、强多租户 |
| 完整 VM/物理机 | KVM 全量虚拟机、裸金属 | 硬件虚拟化完整实现 | 分钟级 | 最高 | 极高风险、强合规 |

读法：**隔离强度与轻便性是一对交换**。按风险选档——跑自己写的单元测试，容器足够；跑用户上传的任意脚本，至少 gVisor/microVM；处理不可信来源的文件与代码，microVM 起步。

### 4.3 选型对比：E2B / Modal / Daytona / 自建

社区对比的三大维度正是冷启动、GPU 透传、快照恢复。下表为口径性对比，具体能力与数字以厂商最新文档为准（趋势观察期的选型必须实测）：

| 维度 | E2B | Modal | Daytona | 自建（Docker 池/Firecracker 池） |
|---|---|---|---|---|
| 定位 | 开源的 AI 代码执行沙箱 | AI 无服务器算力平台 | 开发环境即服务 | 全自控基础设施 |
| 隔离底座 | microVM（Firecracker 系） | gVisor 隔离的容器 | 容器/VM 工作区 | 自选档位 |
| 冷启动 | 主打低延迟，支持快照/暂停恢复 | 秒级弹性扩缩 | 主打秒级起环境 | 取决于工程：预热池可压到亚秒 |
| GPU 透传 | 非主打（面向代码执行） | 丰富，主流 GPU 按需分配 | 有限，视产品线 | 可配，但运维重 |
| 快照恢复 | 有（环境状态可暂停恢复） | 有镜像层缓存/快照能力 | 有（工作区快照） | Firecracker 快照自研 |
| 适合 | 快速给 Agent 加代码执行能力 | 训练/推理与代码执行混合负载 | Agent 开发工作区场景 | 强合规、数据不出域、成本敏感 |

选型口诀：**先问数据能不能出域**——能出域优先托管服务（快、省运维），不能出域只剩自建；再按负载选底座——纯代码执行选 E2B 类，要 GPU 选 Modal 类，长驻开发环境看 Daytona 类。

### 4.4 一次性环境的生命周期

```text
创建（从版本化镜像/快照）→ 预热（池化温环境）→ 执行（带资源硬上限）
→ 产物显式导出（扫描）→ 销毁（强制，含清理）→ 审计（全量留痕）
```

两个工程要点：

1. **快照与 fork**：Firecracker 类 microVM 可把预热好的环境打成快照，后续任务从快照毫秒级拉起——这是「一次性」与「低延迟」兼得的关键，也是 H6 中 Coding Agent 每个任务秒级开新环境的前提。
2. **禁止复用**：容器复用是性能优化的诱饵、数据泄漏的经典通道。多租户场景一人（一任务）一容器，销毁前清盘。

### 4.5 产物回传与扫描

沙箱追求「用完即弃」，因此**需要持久化的东西必须显式导出**，其余全部丢弃：

- **显式通道**：只开放约定导出目录（如 `/sandbox/out`），容器内其他改动一概不回传。
- **扫描管道**：导出物过三道——恶意文件扫描（病毒/脚本特征）、敏感信息扫描（密钥、内部数据指纹）、格式校验（只允许声明的产物类型，如 PNG/CSV）。
- **丢弃即安全**：脚本试图写到导出目录之外的内容，随容器销毁自然蒸发——这比「事后清理」可靠得多。

### 4.6 安全焦点转移与供应链延伸

Agent 安全的重心已经从「prompt 防注入」移向执行面：

| 旧焦点 | 新焦点（2026 社区口径） |
|---|---|
| prompt 注入防御 | 工具与代码执行的安全（本篇沙箱） |
| 输出内容审查 | 上下文暴露控制（敏感数据不进不可信上下文） |
| 单体应用权限 | MCP/工具权限收敛与调用审计（2-3b 的延伸） |
| 模型自带安全 | 工具/技能供应链安全 |

**Skills 与工具供应链**是沙箱话题的自然延伸：技能包（如 Agent Skills 的 SKILL.md 生态）本质是「提示词+脚本+工具权限」的组合，供应链风险与 npm 恶意包同构——一个带恶意脚本的技能包被 Agent 安装执行，沙箱是最后一道闸。已有安全扫描报告给出量级口径：**3,984 个技能中 36.82% 存在问题**（MintMCP 2026 厂商报告，单一来源，引用时需注明）。落地纪律：技能与工具白名单化、安装前审查（脚本行为+权限申请）、来源可信验证、执行仍走沙箱。

## 5. 架构 / 流程

一个生产级「Agent 代码执行」管线：

```text
Agent 生成代码/命令
        |
┌───────▼────────────────────────────────┐
│ 执行准入                                │
│  静态检查（危险 API/网络调用指纹）        │
│  权限核对（该任务允许哪些能力）           │
└───────┬────────────────────────────────┘
        ▼
┌─────── 沙箱池（按风险选档）──────────────┐
│  温环境预热池 ←── 快照（Firecracker）     │
│     ↓ 领取                              │
│  一任务一环境：                          │
│   禁网/白名单出口 ｜ 只读根文件系统        │
│   CPU/内存/PID 上限 ｜ 降权用户           │
│   超时强杀（wall-clock）                 │
└───────┬────────────────────────────────┘
        ▼
┌─────── 产物通道 ────────────────────────┐
│  显式导出目录 → 打包回传                  │
│  → 恶意文件扫描 ｜ 敏感信息扫描 ｜ 格式校验│
│  未导出的其余改动 → 随销毁丢弃            │
└───────┬────────────────────────────────┘
        ▼
┌─────── 销毁与审计 ───────────────────────┐
│  强制销毁容器/VM（清盘）                  │
│  留痕：代码内容+资源用量+输出+扫描结论     │
│  异常行为告警（试联网/读敏感路径/超时）    │
└─────────────────────────────────────────┘
```

## 6. 代码 / 工具

### 6.1 Docker 沙箱执行器（Python）

```python
# docker_sandbox.py —— 最小 Docker 沙箱执行器：隔离+资源上限+产物导出+销毁
import io
import tarfile
import uuid

import docker


def run_in_sandbox(code: str, timeout: int = 60,
                   mem_limit: str = "512m", cpus: float = 1.0) -> dict:
    """在一次性容器里执行代码，返回退出码、日志与显式导出的产物。"""
    client = docker.from_env()
    workdir = "/sandbox"
    container = client.containers.create(
        image="python:3.12-slim",
        command=["python", "-c", code],
        name=f"sandbox-{uuid.uuid4().hex[:8]}",
        network_disabled=True,             # 隔离：切断数据外传与回连
        mem_limit=mem_limit,               # 资源上限：内存
        nano_cpus=int(cpus * 1e9),         # 资源上限：CPU 配额
        pids_limit=64,                     # 防 fork 炸弹
        read_only=True,                    # 根文件系统只读
        tmpfs={workdir: "size=64m"},       # 唯一可写区：64MB 内存盘
        user="65534:65534",                # 降权：nobody 运行
        security_opt=["no-new-privileges"],
    )
    try:
        container.start()
        try:
            result = container.wait(timeout=timeout)
        except Exception:
            container.kill()               # 超时强杀：防死循环与资源滥用
            result = {"StatusCode": 124}
        logs = container.logs(stdout=True, stderr=True).decode(errors="replace")
        artifacts = _export(container, f"{workdir}/out")   # 只回传导出目录
        return {"exit_code": result["StatusCode"], "logs": logs,
                "artifacts": artifacts}
    finally:
        container.remove(force=True)       # 一次性：用完即毁


def _export(container, path: str) -> dict:
    """把导出目录打包取回，交由扫描管道（恶意文件/敏感信息/格式）。"""
    bits, _ = container.get_archive(path)
    tar = tarfile.open(fileobj=io.BytesIO(b"".join(bits)))
    out = {}
    for m in tar.getmembers():
        if m.isfile():
            out[m.name] = tar.extractfile(m).read()
    return out


if __name__ == "__main__":
    r = run_in_sandbox(
        "with open('/sandbox/out/hello.txt','w') as f: f.write('ok')\n"
        "print('done')"
    )
    print(r["exit_code"], r["logs"], list(r["artifacts"]))
```

### 6.2 E2B 云端沙箱调用示例（Python）

```python
# e2b_demo.py —— E2B：创建一次性微 VM、执行、产物回传、自动销毁
# pip install e2b-code-interpreter（SDK 接口以官方最新文档为准）
from e2b_code_interpreter import Sandbox


def analyze() -> str:
    with Sandbox(timeout=120) as sbx:          # 一次性微 VM 环境
        # 1. 注入数据
        sbx.files.write("/home/user/data.csv",
                        "city,sales\nhangzhou,120\nshanghai,98\n")

        # 2. 在沙箱里执行模型生成的分析代码
        code = (
            "import pandas as pd, matplotlib\n"
            "matplotlib.use('Agg')\n"
            "import matplotlib.pyplot as plt\n"
            "df = pd.read_csv('/home/user/data.csv')\n"
            "df.plot.bar(x='city', y='sales', figsize=(6,4))\n"
            "plt.tight_layout()\n"
            "plt.savefig('/home/user/out/chart.png')\n"
            "print(df.describe())"
        )
        execution = sbx.run_code(code)
        print(execution.logs.stdout)           # 文本输出：describe 结果

        # 3. 产物显式回传（回传后仍应过本地扫描管道）
        chart = sbx.files.read("/home/user/out/chart.png", format="bytes")
        with open("chart.png", "wb") as f:
            f.write(chart)
    # with 退出即销毁：本地与云端都不留运行状态
    return "chart.png"


if __name__ == "__main__":
    analyze()
```

### 6.3 沙箱安全检查清单（配置化）

```yaml
# sandbox-policy.yaml —— 上线前逐项确认
isolation:
  one_env_per_task: true          # 一任务一环境，禁止跨任务/跨用户复用
  network: deny                   # deny | allowlist；禁网优先
  rootfs_readonly: true
  run_as: nobody                  # 降权用户
  no_new_privileges: true
resources:
  memory: 512m
  cpus: 1.0
  pids: 64
  wall_clock_timeout: 120s        # 超时强杀
lifecycle:
  prewarm_pool: 32                # 温环境池：压冷启动
  snapshot: firecracker           # 快照恢复：毫秒级拉起
  destroy_on_exit: force          # 用完即毁+清盘
artifacts:
  export_dir: /sandbox/out        # 唯一显式导出通道
  scan: [malware, secrets, file_type_allowlist]   # PNG/CSV 等白名单
audit:
  log: [code, stdout_stderr, resource_usage, scan_verdict]
  alert_on: [network_attempt, sensitive_path_read, timeout]
supply_chain:
  skills_allowlist: true          # 技能/工具包白名单化
  pre_install_review: true        # 安装前审查脚本行为与权限申请
```

## 7. 案例

### 案例 A：数据分析 Agent 的脚本执行架构

**场景**：一家金融科技公司的数据分析 Agent 要执行用户上传的 Python 脚本自动出图表，涉及多租户数据。

**实施**：按四层落地——隔离层每脚本一个容器（禁网、只读根文件系统、降权用户）；资源层 2 核 2G、120 秒硬上限，超时强杀；产物层只开放导出目录，回传物过恶意文件与敏感信息扫描，格式白名单 PNG/CSV；审计层全量留痕并告警异常行为（约 0.3% 的脚本有联网尝试，全部被禁网拦截）。

**效果**：温环境池把冷启动从约 8 秒压到 1.2 秒；上线一年零跨租户数据事故。关键决策是**拒绝容器复用**——性能换安全的交易不做。

### 案例 B：Coding Agent 平台的微 VM 化

**场景**：某研发效能团队的 Coding Agent 平台，每个 PR 要在干净环境跑构建与测试，高峰并发约 200 任务，容器现起冷启动约 22 秒，体验与成本双差。

**实施**：底座换 Firecracker microVM，把预热好的基础环境打成快照；任务从快照拉起后克隆仓库执行，结束销毁。

**效果**：环境就绪时间从 22 秒降到约 0.9 秒；同等并发下宿主机数量降约七成（快照共享基础层+更小的运行时开销）；每个 PR 天然获得干净可复现环境，flaky 环境问题归零。印证 4.4 的结论：快照让「一次性」与「低延迟」兼得。

### 案例 C：一次交叉污染事故复盘

**场景**：某 SaaS 团队为省资源让多用户复用同一批长生命周期容器。用户 A 的脚本把中间数据缓存到工作目录，用户 B 的脚本遍历目录时读到 A 的数据——数据泄漏。

**定责与整改**：审计日志还原了完整链路（这正是留痕的价值）。整改三条：一人（一任务）一容器、销毁前强制清盘、产物只走扫描后的导出通道；容器复用策略整体下线。

**结果**：吞吐下降约 15%，用池化温环境补回。教训：**复用容器跑不同用户的任务是数据泄漏的经典通道，这条性能优化永远不做**。

## 8. 常见坑

1. **主机直接跑 Agent 生成的命令**。  
   一次算错路径的 `rm -rf` 就不可逆。任何模型输出一律进沙箱。
2. **容器挂载 Docker socket 与全量凭证**。  
   等于把宿主机 root 交给沙箱内进程。最小挂载、按需注入、短时凭证。
3. **沙箱能访问外网**。  
   禁网优先；确需联网走域名白名单出口，防止数据外传与下载恶意载荷。
4. **复用容器跑不同用户的任务**。  
   交叉污染是数据泄漏的经典通道。一任务一环境，销毁前清盘。
5. **无资源上限**。  
   死循环、fork 炸弹、内存打爆拖垮宿主。CPU/内存/PID/墙钟超时四项硬上限。
6. **产物不扫描直接回传**。  
   恶意文件或带密钥的导出物流进下游。扫描三道：恶意文件、敏感信息、格式白名单。
7. **只装沙箱不留审计**。  
   出事无法回答「执行了什么、用了多少资源」。代码+输出+资源用量+扫描结论全留痕。
8. **把长生命周期容器当沙箱**。  
   状态残留慢慢磨掉隔离假设。一次性+快照拉起，别恋战。
9. **隔离档位选错**。  
   用户上传的任意脚本只给了进程级软限制。按风险选档：不可信代码至少 gVisor/microVM。
10. **冷启动不优化**。  
    秒级到十秒级的现起毁掉体验。预热池+快照恢复，目标亚秒。
11. **技能/依赖不做供应链审查**。  
    技能包与 npm 包同构，恶意脚本随安装进环境。白名单+安装前审查+沙箱执行兜底（业界扫描口径：3,984 技能 36.82% 有问题，单一来源需标注）。
12. **把 prompt 防护当全部安全**。  
    注入防得住措辞防不住执行。安全重心在工具与代码执行面，沙箱是最后闸。
13. **快照里带敏感状态**。  
    含凭证/客户数据的快照被复用即泄漏。快照只含干净基础环境，敏感物运行时注入。
14. **超时后不清理**。  
    僵尸容器堆积吃光资源。finally 强制销毁+池巡检兜底。

## 9. 练习

1. 用 Docker SDK 写最小沙箱执行器（禁网+内存上限+超时强杀+用完即毁），跑一段会写文件的代码，验证只有导出目录的内容能回来。
2. 故意跑恶意样本（死循环、fork 炸弹、尝试 curl 外网），逐项确认爆炸半径为零，并记录审计日志里出现了什么。
3. 注册 E2B（或同类托管沙箱）跑 6.2 的示例，对比自建容器与托管服务的首任务延迟与运维成本。
4. 实现产物扫描管道：对导出文件做类型白名单+敏感信息正则扫描，构造一个「导出目录里混入 .env」的用例验证拦截。
5. 做冷启动实验：对比「现起容器」「预热池」「快照恢复」三种方案的就绪时间，画出量级对比。
6. 给 H6 的 Coding Agent 测试循环接入 6.1 的执行器，统计沙箱化前后「环境问题导致的 flaky 失败」占比变化。
7. 按 4.6 的清单审查三个开源 Agent Skills/工具包：脚本行为、权限申请、来源，写一份供应链审查报告。
8. 白板设计题：多租户数据分析 Agent 执行用户脚本的完整架构（隔离、资源上限、产物通道、审计四层），对照 4-3 真题口径自查是否答全。

## 10. 小结

- 核心逻辑：**Agent 输出是概率性的，隔离不提升智力，而是把不可靠输出的代价变成可承受的**——这是 Agent 从建议者变执行者的门票。
- 三属性：**隔离（逃不出去）、一次性（用完即毁）、可复现（快照重启）**，三者是乘法关系。
- 隔离谱系：**进程级 → 容器 → gVisor 用户态内核 → Firecracker microVM → 完整 VM**——按风险选档，不可信代码至少 gVisor/microVM。
- 选型四线：**E2B（AI 代码执行沙箱）、Modal（GPU 弹性算力）、Daytona（开发环境）、自建池**——先问数据能否出域，再按负载选底座，选型必实测。
- 冷启动工程：**预热池+Firecracker 快照**让一次性与低延迟兼得——H6 测试循环、H7 执行环境都靠它。
- 产物纪律：**显式导出通道+三道扫描（恶意文件/敏感信息/格式白名单），其余随销毁丢弃**。
- 生命周期：**创建→预热→执行（资源硬上限）→导出→销毁→审计**，超时强杀与 finally 销毁是底线。
- 安全焦点已从 prompt 转向**工具与代码执行、上下文暴露、MCP 权限与审计**；沙箱是执行面的最后闸。
- 供应链延伸：技能包与 npm 包同构——白名单、安装前审查、沙箱执行兜底；3,984 技能 36.82% 有问题为单一来源口径，引用需标注。
- 铁律：**禁止复用容器跑不同用户的任务**——交叉污染是数据泄漏的经典通道。
- 状态口径：**趋势观察**——技术已是生产标配，独立考点未进确证真题；但借道 4-3 已有沙箱真题先例，按「四层架构」作答即覆盖真题口径。
