# 讲解 2.4 记忆 Memory

## 1. 定位

Agent 四件套（2.1）中的第四件。它解决一个根本问题：**上下文窗口有限且会话必然结束，Agent 如何跨轮、跨会话、跨月地「记住该记的、忘掉该忘的」？**

前置依赖：

- 1.5 记忆与上下文管理：窗口内管理（截断、摘要压缩、检索式选取）的通用手法，本篇是它在 Agent 场景的体系化。
- 0.7 向量与嵌入基础 + 1.4 RAG：长期记忆的存储与检索引擎就是向量库，检索技术直接复用。
- 2.1 Agent 定义与范式：记忆是 Agent 四件套之一。

后续展开：

- 2.5 执行循环与状态机：每一步 ReAct 如何把检索到的记忆注入上下文。
- 2.6 反思与自我修正：反思结论沉淀为「经验记忆」的回路。
- 3.2 数据与知识工程：企业级知识库与记忆系统的合流。

面试定位：**「Agent 的记忆系统怎么设计？」「上下文工程怎么做？」**——标准答法是「两层记忆 + 三种压缩 + 写入过滤 + 治理」，全部在本篇。

## 2. 一句话定义

Agent 记忆是「窗口内状态 + 外挂持久存储」的两层体系：**短期记忆是当前上下文窗口内的对话与中间结果，长期记忆是外挂存储（向量库/数据库）中的偏好、事实与经验，按需检索注入**。记忆工程的全部内容可以压缩成三问：写什么、存哪、怎么调。

## 3. 为什么需要

LLM 的上下文窗口（Context Window）有两个硬约束：

1. **有限**：再长的窗口也会被长任务、多轮对话填满——20 步任务、每步观察 2000 字，轨迹就膨胀到几万字。
2. **易失**：会话结束，窗口内容即消失。用户三个月前说的过敏史，今天新会话里模型一无所知。

把历史全塞窗口的两难：

| 做法 | 后果 |
|---|---|
| 全部保留原文 | 爆窗口；成本线性上涨；早期关键信息被挤到注意力低效区（lost in the middle），模型忘记最初目标 |
| 到上限直接截断 | 丢失关键约束（预算、偏好、已确认口径），行为前后不一致 |
| 微调把信息写进参数 | 更新慢、成本高、无法按用户隔离、隐私灾难、不可遗忘 |

记忆系统的价值正在于此：**在「窗口有限」与「任务需要长历史」之间做信息调度**——近期原文保细节、远期摘要保大意、重要事实外挂落库按需召回。类比：医生问诊时脑子里记着今天的症状（短期），病历柜里存着三年前的手术记录（长期），病历太厚就写一张摘要卡「青霉素过敏」（压缩）——一句摘要胜过十页原始记录。

## 4. 核心原理

### 4.1 记忆分层：工作 / 情景 / 语义 / 程序

认知科学的记忆分类在 Agent 上的映射，业界主流实现（MemGPT、ChatGPT Memory 等）均循此思路：

| 类型 | 内容 | 载体 | 生命周期 | 例子 |
|---|---|---|---|---|
| 工作记忆 Working | 当前任务的状态与中间结果 | 上下文窗口内（或外置状态块） | 单任务 | 已确认的预算、当前子任务进度 |
| 情景记忆 Episodic | 历史交互的具体轨迹 | 对话历史库 / 轨迹存储 | 跨会话可检索 | 「上周三用户投诉过物流慢」 |
| 语义记忆 Semantic | 抽象出的事实、偏好、知识 | 向量库（+关系库） | 长期 | 「用户对海鲜过敏」「偏好靠窗座」 |
| 程序记忆 Procedural | 沉淀为技能的提示词、SOP | 提示模板 / 技能库 | 长期 | 「该用户的周报固定用这个模板」 |

工程上最常见的分层落地是两桶：**短期（窗口内）+ 长期（窗口外）**，四类记忆分别映射进去。程序记忆常被忽视——把反复验证有效的提示词固化成模板，本质是把「会做」变成「记住怎么做」。

### 4.2 短期窗口与长期向量库

**短期记忆 = 上下文窗口本身**：系统提示、最近 N 轮对话、当前任务的中间结果、已确认口径。它随会话结束消失，管理要点是「排版」：目标固定在最前、关键状态显式注入、最新信息靠后（近因效应）。

**长期记忆 = 外挂持久存储**：

| 存储引擎 | 存什么 | 检索方式 | 适合的记忆 |
|---|---|---|---|
| 向量库（Chroma/Qdrant/pgvector） | 语义记忆：偏好、事实、经验 | 向量相似 + 元数据过滤 | 「过敏史」「写作风格偏好」 |
| 关系库 / KV 库 | 结构化强事实：画像、订单、证件号 | 精确查询 | 用户 ID、订阅状态、过敏清单 |
| 文档库 | 长笔记、会话纪要 | 全文 + 向量混合 | 任务复盘、会议记录 |

关键设计判断：**安全关键记忆（过敏、合规约束、金额上限）不能只赌语义召回的运气**——相似度搜索可能漏召回，这类记忆必须同时走结构化存储并设为「必检白名单」，意图触发相关场景时强制注入。

### 4.3 写入过滤与记忆污染

**不是所有对话都值得长记**——这是记忆系统最容易被忽略的半边。写入不过滤的后果：

- 记忆库被闲聊、临时口误、错误结论塞满（**记忆污染**）。
- 检索时噪音挤占上下文，「检索错了不如不用」。
- 过时信息与新信息冲突，模型行为摇摆。

写入过滤流水线：

```text
对话结束 → LLM 抽取候选记忆（实体-属性-时效三元组）
        → 过滤（闲聊/临时/敏感？丢弃）
        → 去重合并（已有同类记忆则更新而非新增，带时间戳）
        → 打标签（类型/用户/时间/置信度）
        → 写入向量库 + 关键事实同步结构库
```

过滤判定表：

| 候选内容 | 判定 | 理由 |
|---|---|---|
| 「我对花生过敏」 | 写入（语义-健康类，高优先级） | 长期有效、安全关键 |
| 「帮我订下周二的票」 | 不写 | 一次性任务指令，非事实 |
| 「今天天气真差」 | 丢弃 | 闲聊 |
| 「改一下，我其实偏好过道座」 | 覆盖旧偏好并留时间戳 | 记忆更正 |
| 「我们公司明年要上市」（传闻） | 写入但标低置信度 + 时效 | 可能过时，召回时提示时效 |

另一侧的污染源是**读取侧**：检索注入了不相关记忆、过时记忆、甚至「记忆投毒」（用户或第三方诱导 Agent 写入恶意指令，后续会话被注入）。对策见 4.4 与第 8 节。

### 4.4 检索式记忆注入

新任务开始时，把相关记忆「召唤」进上下文——复用 RAG 检索技术，但对象从文档换成记忆：

1. **查询构造**：当前用户消息（多轮时先做查询重写，见 1.4）。
2. **混合检索**：向量相似 Top-K + 标签过滤（类型/用户/时间）+ 白名单必检。
3. **重排与阈值**：相关性分数低于阈值的宁可不注入——错误记忆比没有记忆更糟。
4. **注入排版**：以固定区块（如 `[长期记忆]`）放进系统提示区，带时间戳与来源，提示模型注意时效。
5. **写入触发**：会话结束或每 N 轮跑一次写入过滤，形成读写闭环。

注入模板：

```text
[长期记忆]（按当前意图检索，共 3 条，来源与时间如下）
- [健康/2026-03-12] 用户对海鲜过敏（置信度 0.98）
- [偏好/2026-08-01] 用户偏好靠窗座位（置信度 0.9）
- [事实/2026-09-01] 用户常驻上海，出差以京沪线为主
涉及订餐场景时，健康类记忆必须优先遵守。
[/长期记忆]
```

### 4.5 摘要压缩与遗忘策略

窗口接近上限时的三种压缩策略（1.5 三板斧的组合拳）：

| 策略 | 做法 | 保什么 | 丢什么 | 适用 |
|---|---|---|---|---|
| 滑动窗口 | 只保留最近 N 轮原文 | 近期细节 | 远期历史 | 轮数可控的对话 |
| 摘要压缩 | 旧历史浓缩成一段纪要 | 大意与结论 | 措辞细节 | 长对话、长任务 |
| 检索式选取 | 历史按相关性召回 Top-K | 相关片段 | 不相关片段 | 需要精准回溯的场景 |

标准答案是**组合**：「摘要 + 滑窗」——前 1~30 轮压成 200 字纪要放最前，保留最近 5 轮原文，兼顾大意间与细节。

**遗忘（Forgetting）是被低估的刚需**，四类策略：

| 策略 | 机制 | 例子 |
|---|---|---|
| TTL 过期 | 记忆带时效标签，到期降权或删除 | 「用户本月在杭州出差」下月失效 |
| 冲突覆盖 | 新记忆覆盖旧记忆，以时间戳为准 | 偏好从靠窗改成过道 |
| 显式删除 | 用户行使删除权，同步删向量库与结构库 | 合规硬要求（被遗忘权） |
| 评分衰减 | 按访问频率与置信度衰减分数，低分沉底或清理 | 半年未被命中的低置信记忆归档 |

### 4.6 多租户记忆隔离

SaaS 场景下，A 公司的用户绝不能召回 B 公司的记忆。隔离必须在**存储、检索、注入三层同时成立**：

| 层 | 措施 | 失守后果 |
|---|---|---|
| 存储 | 每条记忆强制携带 `tenant_id` + `user_id` 元数据；或物理分库/分集合 | 数据混存，事故源头 |
| 检索 | 查询侧强制 where 过滤（`tenant=当前租户 AND user=当前用户`）；过滤在服务端做，不接受客户端传参 | 越权召回他人记忆 |
| 注入 | 注入前二次校验归属；日志记录每条注入记忆的来源 | 泄露难以审计定责 |

补充纪律：向量删除要彻底（向量、原文、元数据、缓存四处一致删除）；共享记忆（团队级知识）须显式声明共享范围并支持审计；测试与生产记忆库物理隔离——用真实用户数据调试记忆检索是高频泄露事故。

## 5. 架构 / 流程

一次跨会话的记忆流转全图：

```text
┌──────────────────── 会话中（短期记忆 = 上下文窗口）────────────────────┐
│                                                                       │
│  [系统提示] → [长期记忆注入区] → [摘要纪要] → [最近 N 轮原文] → [本轮]   │
│      ↑ 检索注入 ↑                ↑ 滚动压缩                           │
└───────────────────────────────────────────────────────────────────────┘
        ↑ 召回                                    │ 写入
┌───────┴────────────────────┐        ┌───────────↓──────────────────┐
│ 长期记忆（会话外，持久化）    │        │ 写入过滤流水线                │
│                            │        │ 抽取→过滤→去重→打标签→落库     │
│  向量库：语义记忆           │        └──────────────────────────────┘
│   （偏好/事实/经验）        │
│  结构库：强事实/画像        │        ┌──────────────────────────────┐
│  轨迹库：情景记忆           │        │ 遗忘策略                      │
│  （按需检索的会话历史）      │        │ TTL/冲突覆盖/显式删除/评分衰减  │
│  每条记忆：tenant_id+user_id│        └──────────────────────────────┘
│   +类型+时间戳+置信度        │
└────────────────────────────┘
```

一次新会话的检索注入清单：

1. 接收用户消息，多轮则先查询重写。
2. 白名单必检：意图命中「订餐/订票」等场景 → 强制注入健康/合规类记忆。
3. 向量检索 Top-K（K=3~5），标签过滤 `tenant + user + type`。
4. 相关性阈值过滤，低于阈值不注入。
5. 以固定区块注入系统提示区，带时间戳与置信度。
6. 会话结束触发写入过滤流水线，读写闭环。

## 6. 代码 / 工具

### 6.1 向量库记忆读写（写入过滤 + 元数据 + 冲突覆盖）

```python
import chromadb, json
from openai import OpenAI

client = OpenAI(api_key="YOUR_KEY")
chroma = chromadb.Client()
mem = chroma.get_or_create_collection("agent_memory")

def embed(text: str) -> list:
    return client.embeddings.create(
        model="text-embedding-3-small", input=text
    ).data[0].embedding

def remember(text, tenant, user, mtype, confidence=0.9, ttl_days=None):
    """写入一条记忆：强制租户/用户隔离元数据 + 冲突覆盖"""
    hits = mem.query(
        query_embeddings=[embed(text)], n_results=1,
        where={"$and": [{"tenant": tenant}, {"user": user},
                        {"type": mtype}]},
    )
    if hits["ids"][0]:                       # 同类记忆已存在 → 覆盖
        old = hits["metadatas"][0][0]
        mem.update(
            ids=hits["ids"][0],
            documents=[text],
            embeddings=[embed(text)],
            metadatas=[{**old, "text": text,
                        "ts": now(), "confidence": confidence}],
        )
        return "updated"
    mem.add(
        ids=[new_id()],
        documents=[text],
        embeddings=[embed(text)],
        metadatas=[{"tenant": tenant, "user": user, "type": mtype,
                    "ts": now(), "confidence": confidence,
                    "ttl": ttl_days}],
    )
    return "created"

# 写入过滤：只让值得记的内容进入 remember()
def write_back(dialogue: str, tenant: str, user: str):
    """会话结束后用 LLM 抽取候选记忆，过滤后落库"""
    resp = client.chat.completions.create(
        model="gpt-4o-mini", temperature=0,
        response_format={"type": "json_object"},
        messages=[{"role": "user", "content": f"""
从对话中抽取值得长期记住的用户事实/偏好/结论。
输出 JSON: {{"memories": [{{"text":..., "type":"health|preference|fact",
"confidence":0-1, "ttl_days": 数字或 null}}]}}
只抽长期有效的事实；闲聊、一次性任务指令一律不输出。
对话：{dialogue}"""}])
    for m in json.loads(resp.choices[0].message.content)["memories"]:
        if m["confidence"] >= 0.7:           # 置信度过滤
            remember(m["text"], tenant, user,
                     m["type"], m["confidence"], m.get("ttl_days"))
```

### 6.2 检索式记忆注入（白名单必检 + 阈值过滤 + 排版）

```python
WHITELIST_TRIGGERS = {
    "订餐": "health", "点菜": "health",
    "订票": "preference", "订酒店": "preference",
}

def recall(query: str, tenant: str, user: str,
           intent: str = "", top_k: int = 5, min_score: float = 0.75):
    """混合召回：向量检索 + 租户/用户过滤 + 白名单必检"""
    results = mem.query(
        query_embeddings=[embed(query)],
        n_results=top_k,
        where={"$and": [{"tenant": tenant}, {"user": user}]},
    )
    picked = [d for d, dist in zip(results["documents"][0],
                                   results["distances"][0])
              if 1 - dist >= min_score]          # 相似度阈值过滤

    forced_type = WHITELIST_TRIGGERS.get(intent)  # 安全关键：必检白名单
    if forced_type:
        forced = mem.get(where={"$and": [
            {"tenant": tenant}, {"user": user}, {"type": forced_type}]})
        picked += [d for d in forced["documents"] if d not in picked]
    return picked

def build_context(query, tenant, user, history, intent=""):
    memories = recall(query, tenant, user, intent)
    block = "\n".join(f"- {m}" for m in memories) or "（无相关记忆）"
    return f"""[长期记忆]（按当前意图检索，来源与时间戳见库内元数据）
{block}
涉及健康与合规类记忆时必须优先遵守。
[/长期记忆]

{history}   # 摘要纪要 + 最近 N 轮原文（滚动压缩后）

用户：{query}"""
```

## 7. 案例

### 案例 A：跨月个人助理的过敏记忆

**场景**：某旅行订餐助理。用户三个月前说过「对海鲜过敏」，今天让助理订商务餐。

**做法**：写入过滤把「海鲜过敏」标为健康类高置信记忆，同时同步进结构库白名单；召回时意图命中「订餐」触发白名单必检——不赌相似度的运气，强制注入；注入时带时间戳与健康类优先声明。

**效果**：三个月后订餐场景下过敏记忆命中率 100%（纯语义召回方案实测约 85%）；助理主动备注「已避开海鲜」并说明原因，用户投诉率明显下降。

### 案例 B：长会话「摘要 + 滑窗」压缩

**场景**：某客服 Agent 单会话平均 40 轮，全部保留原文时轮次过半后频繁「忘记」用户开头确认的退款口径，答非所问。

**做法**：前 30 轮滚动压缩为 200 字纪要（保留已确认口径、单号、承诺），保留最近 5 轮原文；关键口径（退款金额、承诺时效）额外写入工作记忆状态块，每轮固定注入上下文最前部。

**效果**：口径一致率从约 70% 升到 96%，单会话 token 成本下降约 45%，长会话中途放弃率下降三分之一。

### 案例 C：多租户隔离事故复盘

**场景**：一家 SaaS 厂商的知识助手，初期向量库按集合共用，检索过滤由前端传入租户参数。一次联调中前端误传租户 A 的 ID，B 公司用户召回了 A 公司的内部问答。

**治理**：过滤条件改为服务端从会话凭证解析租户与用户，客户端传参一律忽略；每条记忆强制携带 `tenant_id` 且注入前二次校验归属；注入日志记录每条记忆来源以备审计；测试与生产库物理隔离。

**效果**：越权召回归零；后续新增团队级共享记忆时，共享范围声明与审计直接复用同一套机制。

## 8. 常见坑

1. **所有对话一把梭写入向量库**。闲聊与临时指令污染记忆库，检索全是噪音。写入前必须过滤：抽实体、偏好、结论类信息，置信度低于阈值丢弃。
2. **只写不更正**。用户偏好变了，旧记忆还在，行为摇摆。同类记忆覆盖更新并带新时间戳，冲突时以新为准。
3. **安全关键记忆只赌语义召回**。过敏、合规约束这类保命事实可能漏召回。走结构化白名单存储 + 意图触发必检。
4. **检索结果不做阈值过滤**。相似度 0.5 的「相关」记忆注入进去，误导决策。低于阈值宁可不注入——检索错了不如不用。
5. **记忆不带时间戳与置信度**。模型无法判断新旧与可信度。每条记忆必带 `ts` 与 `confidence`，注入时提示时效。
6. **历史到上限直接硬截断**。丢掉开头确认的口径与约束。用「摘要 + 滑窗」组合，关键口径外置状态块固定注入。
7. **摘要把关键数字压没了**。LLM 摘要爱丢精确值。摘要 Prompt 中明确「保留金额、日期、单号、已确认承诺」。
8. **多租户过滤靠客户端传参**。改个参数就越权。过滤条件必须服务端从凭证解析，注入前二次校验。
9. **遗忘机制缺失**。记忆只增不减，一年后检索全是陈年旧账。TTL、冲突覆盖、显式删除、评分衰减至少落地两种。
10. **删除不彻底**。只删向量不删元数据与缓存，「被遗忘权」合规踩雷。向量、原文、元数据、缓存四处一致删除。
11. **记忆注入位置随意**。塞在长上下文中部会被遗忘（lost in the middle）。固定注入系统提示区，目标与关键记忆靠前。
12. **测试用真实用户记忆调试**。高频泄露事故。测试与生产记忆库物理隔离。
13. **把记忆当成万能外脑**。记忆解决「记住」，不解决「正确」——事实性知识仍应走 RAG 知识库，两者存储与召回策略分开设计。

## 9. 练习

1. 用 Chroma 实现最小记忆库：写入 5 条偏好 + 时间戳元数据，检索 Top-3 并观察相似度分数。
2. 实现写入过滤：用 LLM 从一段对话中抽取候选记忆，规则 + 置信度双过滤后再落库。
3. 模拟偏好变更：先写入「靠窗」，再写入「改偏好过道」，验证覆盖更新与时间戳逻辑。
4. 给记忆库加白名单必检：构造订餐意图，对比「纯语义召回」与「白名单强制注入」的命中率。
5. 实现「摘要 + 滑窗」：40 轮对话压成 200 字纪要 + 最近 5 轮原文，验证口径保持率。
6. 实现多租户隔离：两条相同文本分属两个租户，验证 where 过滤在服务端强制生效。
7. 落地遗忘策略：给记忆加 TTL 与访问计数，跑一次「半年后」的衰减清理脚本。
8. 红蓝演练：尝试构造「记忆投毒」输入（诱导 Agent 写入恶意指令），验证写入过滤与注入校验能否拦截。

## 10. 小结

- 记忆 = 短期（上下文窗口内）+ 长期（外挂向量库/结构库），全部工程压缩成三问：**写什么、存哪、怎么调**。
- 四类记忆：工作（任务状态）、情景（历史交互）、语义（事实偏好）、程序（沉淀的 SOP），分别映射到窗口、轨迹库、向量库、模板库。
- **写入即过滤**：抽取实体-属性-时效，过滤闲聊，去重合并，打标签带时间戳与置信度——记忆污染防在写入侧。
- 检索注入五步：查询重写 → 混合检索 + 标签过滤 → 阈值取舍 → 固定区块注入 → 会话末写回，读写闭环。
- 安全关键记忆走**结构化白名单 + 意图触发必检**，不赌语义召回的运气。
- 压缩三策组合拳：**摘要 + 滑窗**（远期保大意、近期保细节），关键口径外置状态块固定前置。
- 遗忘是刚需：TTL、冲突覆盖、显式删除、评分衰减；删除必须四处一致。
- 多租户隔离三层同时成立：存储带租户元数据、检索服务端强制过滤、注入前二次校验。
- 这些能力由 0.7/1.4 的向量检索技术支撑，在 2.5 执行循环中逐步被取用，在 3.2 与知识工程合流。
