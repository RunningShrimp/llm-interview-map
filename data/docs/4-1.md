# 讲解 4.1 单 Agent 原型

> 说明：2.7 单 Agent 架构模式给了架构理论，2.5 执行循环与状态机、2.3 工具使用给了机制细节；本篇把三者压缩成一个百行级可运行的 MVP（Minimum Viable Product，最小可行产品），亲手跑通感知-决策-行动闭环。  
> MVP 的轨迹日志是后续一切的种子数据：接可观测与评估体系见 3.4/3.5，生产化部署与运维见 4.9，把这个项目讲成有证据链的故事见 4.10 与 4.10b。

---

## 1. 定位

L4 实战层第 1 个锚点，回答关键问题：**最小可用 Agent 是什么样？**

前置依赖：

- 2.7 单 Agent 架构模式：为什么「一个循环 + 工具」就能构成 Agent，理论在那里。
- 2.5 执行循环与状态机：主循环的状态转移机制，本篇给出它的最小实例。
- 2.3 工具使用 Tool Use：工具定义、参数校验、失败处理的完整战术。

下游去向：

- 4.9 部署与运维：MVP 上线要做软故障防御与告警，本篇给出从原型到生产的路径。
- 4.10 / 4.10b：这个从零到一的项目，配上护栏与评估数据，就是作品集里最有说服力的故事。

它解决一个根本问题：**新手做 Agent 常死于「一上来就要做万能助理」——功能规划宏大，闭环从未跑通。MVP 的价值不在功能多，而在把拆解、工具、循环、容错四件事亲手摸一遍。**

## 2. 一句话定义

最小可用 Agent = 一个主循环 + 两三个原语工具 + 参数校验 + 失败处理，百来行代码跑通「感知-决策-行动」闭环；验收标准是**五收口**——任何输入都落到五种确定结局之一，绝不卡死、绝不静默吞错。

## 3. 为什么需要

类比：先摆地摊，再开商场。很多新人的第一个 Agent 计划是「做个万能助理」——像第一次创业就规划商场动线。正确的路径是先摆地摊：一个主循环（用户问一句，Agent 想一步做一步）、两个工具（搜索 + 读取）、一条兜底（工具挂了就如实说）。地摊虽小，进货（工具定义）、卖货（循环）、处理投诉（失败处理）一样不缺——跑完这一遍，才知道哪一步最常翻车，这决定后面架构怎么设计。

为什么「闭环」比「功能」重要：

| 维度 | 万能助理路线 | MVP 路线 |
|---|---|---|
| 首个可用版本 | 3 个月难产 | 一两天跑通 |
| 调试对象 | 十几个模块的黑盒 | 一个循环 + 两个工具 |
| 踩坑收益 | 坑埋在系统深处 | 坑全暴露在主循环里 |
| 后续扩展 | 架构靠想象 | 架构靠实测数据决定 |
| 面试叙事 | 罗列功能清单 | 闭环 + 失败案例 + 改造路径 |

闭环的含义：每一步都有去处。用户的问题进去，最终一定有五种去处之一——答案、澄清反问、工具结果汇总、如实承认做不到、超限熔断提示。怕的不是做不完美，而是「卡住」：死循环、无限等待、默默吞掉错误。MVP 的验收标准就是：**任何输入都不会让程序既不报错也不响应。**

## 4. 核心原理

### 4.1 组件四件套

| 组件 | 内容 | 职责 |
|---|---|---|
| 主循环 | LLM 决策 → 程序执行 → Observation 回传 | 驱动感知-决策-行动闭环 |
| 原语工具 | search（返回前 5 条摘要）+ read（抓正文截断） | 与外部世界交互；工具多不如工具稳 |
| 系统提示词 | 规定输出格式、工具清单、终止规范 | 约束模型行为，决策的结构化契约 |
| 轨迹日志 | 每步 thought/action/observation 写 JSONL | 调试依据 + 未来评估体系的种子数据 |

工具设计三条纪律：

- **原语优先**：search + read（或 calc）足够构成闭环，两三个工具能暴露的问题，十个工具只会放大。原语是指不可再拆的最小能力——search 给信息入口，read 给细节入口，calc 给精确计算，其余复杂操作都应由模型组合原语完成，而不是为每个业务场景造一个专用大工具。
- **统一返回结构**：每个工具返回 `{ok, data | error}`，成功失败同构，主循环无需特判。
- **参数即不可信输入**：模型会幻觉参数、拼错 URL、传空字符串——校验必须发生在程序侧，工具内部不做第二道信任。

### 4.2 主循环五处理

循环头上的五道防护，缺一道就多一类生产事故：

| 防护 | 触发条件 | 动作 | 反例后果 |
|---|---|---|---|
| ① 参数校验 | 模型输出缺字段、空查询、非法 URL | 拒绝执行，错误信息作为 Observation 回传 | 幻觉参数直接打到下游接口 |
| ② 步数/预算上限 | 达到步数上限（如 8 步）或 token 预算 | 熔断，如实交代已收集的信息 | 无限循环烧钱，任务悬挂 |
| ③ 错误回传自修 | 工具异常、校验失败 | 可读错误回传，让模型换路重试 | 异常被吞，模型在错误前提上继续编 |
| ④ 指纹熔断 | 连续重复同一工具调用（参数指纹相同） | 切断循环，注入提示要求换策略 | 同一失败调用重复到步数上限 |
| ⑤ 终止信号 | 模型输出 finish/最终答案标记 | 退出循环，进入收口 | 循环收不了口，答案出不来 |

关键认知在 ③：校验失败**不终止任务、也不替模型做主**——把「查询不能为空」作为 Observation 回传，模型自修成功率很高，这正是「校验 + 错误回传自修」的学习闭环。静默终止与替模型补默认值，都会破坏这个循环。

②的上限要有两把尺子：**步数上限**防逻辑死循环，**预算上限**（token 数或费用）防「每步都合法但加起来烧穿成本」的慢性失血——长任务里后者更常见，也更容易被忽略。两把尺子任一触发都走熔断收口。

### 4.3 五收口

| 收口 | 触发 | 示例输出 |
|---|---|---|
| 答案 | 模型发出 finish 且信息充分 | 「DeepSeek-R1 发布于 2025 年 1 月，距今约 60 周。来源：…」 |
| 澄清反问 | 目标模糊、缺必要参数 | 「你要查的是 DeepSeek-R1 还是 R1-Distill？」 |
| 工具结果汇总 | 多源信息需要整合 | 「三个来源口径不一，汇总如下：…」 |
| 如实承认做不到 | 资料不足、工具反复失败 | 「公开资料中没有找到该数据，我不编造。」 |
| 熔断提示 | 步数/预算超限、指纹熔断 | 「已达 8 步上限，已确认 A 与 B，C 未能验证。」 |

验收即测试：把「正常问题、模糊问题、恶意输入、工具必失败」各构造若干条灌进主循环，断言每条都落入五收口之一且程序不崩——这就是 MVP 的回归测试。

澄清反问值得单独说一句：它不是模型自发行为，要靠系统提示词显式授权——「目标模糊时，用 finish 在 answer 里写澄清反问」。不授权的模型倾向于硬答，把模糊问题编成确定答案，这是 MVP 阶段最隐蔽的一类错误。

### 4.4 轨迹 JSONL

从第一天开始落盘，每步一条：

```text
{"ts": "...", "step": 1, "thought": "先查发布时间", "action": {"tool": "search", "args": {"q": "DeepSeek-R1 发布时间"}}, "observation": {"ok": true, "data": "..."}}
```

三重价值：调试靠它（错在哪一步一目了然）；评估靠它（步骤数、失败率、工具成功率都从轨迹统计）；面试展示工程思维也靠它（能拿出轨迹日志，说明跑过真闭环）。它是将来接 3.4 可观测性与 3.5 评估体系的种子数据。

轨迹每条的最小字段：时间戳、步数、thought、action（工具 + 参数）、observation（含 ok 与 error）。字段从第一天就定死，中途改格式会让自己历史轨迹不可比。落盘用追加写 JSONL 而不是内存列表——进程崩了轨迹还在，事后能完整还原事故现场。

### 4.5 从 MVP 到生产化

MVP 与生产系统的差距是明确的、可清单化的：

| MVP 中的做法 | 生产化改造 | 去向锚点 |
|---|---|---|
| 裸调模型 API | 网关 + 重试 + 限流 + 模型路由 | 3.6 部署与扩展 |
| print 调试 | 全链路 trace + 结构化日志 | 3.4 可观测性与追踪 |
| 无评估 | 冒烟集 + 回归集 + 评估门禁 | 3.5 / 3.9 |
| 工具硬编码 | 工具注册 + 权限控制 + 审计 | 2.3 / 3.8 |
| 单进程跑完 | 部署 + 软故障监控 + 告警 | 4.9 部署与运维 |
| 无记忆 | 会话记忆 + 跨会话存储 | 2.4 / 1.5 |

路径建议：不要等 MVP「完美」再生产化——每次 MVP 暴露的最痛问题，就是下一个生产化改造项，按上表逐格补齐即可。

### 4.6 面试讲述法

面试官问「手写一个最小 Agent，循环里必须处理什么」时，按五段作答，先 MVP 后生产化（倒过来讲容易像背架构图）：

1. **任务**：选窄而真实的任务，如「给定技术问题，搜索资料并输出带来源的三句话小结」。
2. **组件**：主循环 + 两个原语工具 + 系统提示词 + 轨迹日志，一句话说清各自职责。
3. **循环五处理**：参数校验、步数上限、错误回传自修、指纹熔断、终止信号——逐条给出触发条件与动作。
4. **验收**：五收口，任何输入都有确定行为，不卡死不静默。
5. **延伸**：主动指出轨迹日志是接可观测、评估与生产护栏的种子数据——这一步是从及格到优秀的分界。

## 5. 架构 / 流程

最小 Agent 的主循环与五收口：

```text
        用户目标（感知）
             │
             ▼
┌────────────────────────────────────┐
│            主循环（≤8 步）           │
│                                    │
│  LLM 决策 → 输出结构化 Action        │
│      │                             │
│      ▼                             │
│  ① JSON/参数校验 ──失败→ 错误回传──┐ │
│      │通过                        │ │
│      ▼                             │ │
│  ④ 指纹检查 ──重复→ 熔断提示────────┤ │
│      │新调用                       │ │
│      ▼                             │ │
│  程序执行工具 → {ok, data|error}    │ │
│      │                             │ │
│      ▼                             │ │
│  Observation 回传给模型 ←──────────┘ │
│      │                             │
│      ├── tool=finish → 跳出循环（⑤终止信号）
│      └── 步数耗尽 → 熔断（②上限）     │
│                                    │
│  每步轨迹写 JSONL（thought/action/observation）│
└────────────────────────────────────┘
             │
             ▼
     五收口之一（输出）
  答案 / 澄清 / 汇总 / 承认做不到 / 熔断提示
```

## 6. 代码 / 工具

### 6.1 百行级最小 Agent 实现

```python
# mini_agent.py —— 一个主循环 + 两个原语工具 + 校验与容错 ≈ 100 行
import json, time, hashlib
from openai import OpenAI

client = OpenAI()
MAX_STEPS = 8                                   # ② 上限写在循环头上

SYSTEM = """你是任务执行 Agent。每轮只输出一个 JSON 对象：
{"thought": "简要推理", "action": {"tool": "search|read|finish", "args": {...}}}
- search: args={"q": "查询词"}   检索资料，返回前 5 条摘要
- read:   args={"url": "网址"}   抓取正文（截断）
- finish: args={"answer": "最终答案"}  信息足够时调用
信息不足就如实说明，禁止编造。目标模糊时，finish.args.answer 写澄清反问。"""

def search(q: str) -> dict:                     # 原语工具 1：统一返回结构
    if not q.strip():
        return {"ok": False, "error": "查询不能为空"}
    return {"ok": True, "data": [{"title": f"结果{i}", "snippet": f"...{q}..."} for i in range(5)]}

def read(url: str) -> dict:                     # 原语工具 2
    if not url.startswith(("http://", "https://")):
        return {"ok": False, "error": f"非法 URL：{url!r}"}
    return {"ok": True, "data": f"<{url}> 的正文内容（截断至 2000 字）"}

def validate(action: dict) -> str | None:       # ① 校验先行：模型输出=不可信输入
    tool = action.get("tool")
    if tool not in ("search", "read", "finish"):
        return f"未知工具 {tool!r}，只能用 search/read/finish"
    if not isinstance(action.get("args"), dict):
        return "args 必须是对象"
    if tool == "search" and not action["args"].get("q"):
        return "search 缺少非空参数 q"
    if tool == "read" and not action["args"].get("url"):
        return "read 缺少参数 url"
    return None

def fingerprint(action: dict) -> str:           # ④ 指纹：识别重复调用
    return hashlib.sha1(json.dumps(action, sort_keys=True).encode()).hexdigest()[:12]

def run(goal: str, trace_path: str = "traces/trace.jsonl") -> str:
    messages = [{"role": "system", "content": SYSTEM}, {"role": "user", "content": goal}]
    seen: set[str] = set()
    for step in range(1, MAX_STEPS + 1):
        raw = client.chat.completions.create(
            model="gpt-4o-mini", messages=messages, temperature=0,
        ).choices[0].message.content
        try:
            action = json.loads(raw)
        except json.JSONDecodeError:
            obs = {"ok": False, "error": "输出不是合法 JSON，严格按系统提示的格式重试"}
            action = {"thought": "(格式错误)", "tool": None}
        else:
            err = validate(action)
            obs = {"ok": False, "error": err} if err else (
                {"ok": True, "data": action["args"].get("answer")} if action["tool"] == "finish"
                else search(action["args"]["q"]) if action["tool"] == "search"
                else read(action["args"]["url"]))
        traj = {"ts": time.time(), "step": step,            # 轨迹落盘，从第一天开始
                "action": action, "observation": obs}
        with open(trace_path, "a") as f:
            f.write(json.dumps(traj, ensure_ascii=False) + "\n")
        if action.get("tool") == "finish" and obs["ok"]:
            return obs["data"]                              # ⑤ 终止信号 → 收口：答案/澄清
        fp = fingerprint(action)
        if fp in seen and obs["ok"] is False:
            obs = {**obs, "error": obs["error"] + "（同类调用已重复，请换策略或用 finish 如实交代）"}
        seen.add(fp)
        messages.append({"role": "assistant", "content": raw})
        messages.append({"role": "user", "content": f"Observation: {json.dumps(obs, ensure_ascii=False)}"})
    return "已达 8 步上限，熔断。已确认的信息如下，未能验证的部分如实交代。"   # 收口：熔断提示

if __name__ == "__main__":
    print(run("查一下 DeepSeek-R1 的发布时间并换算成周数"))
```

CASES = [

## 7. 案例

### 案例 A：技术问答 MVP 跑通闭环

**场景**：面试准备期，目标是一周内有一个能演示的 Agent。

**实现**：按本篇四件套搭建——search + read 两个工具、8 步上限、轨迹 JSONL。第一天跑通正常路径；第二天构造 20 条刁钻输入做验收，发现两类卡死：模型输出非 JSON 导致崩溃、对失败工具无限重试。分别用「格式错误回传」与「指纹熔断」修掉。

**效果**：20 条验收输入全部落入五收口；平均任务 3.2 步完成，工具失败自修成功率约 70%。这个百行项目后来扩展成带评估集的完整作品（见案例 B）。

### 案例 B：从 MVP 到生产化的改造复盘

**场景**：某团队的内部问答 MVP 要给 200 名客服真实使用。

**改造**：按 4.5 的对照表逐格补齐——接网关加重试与限流（第一周）；轨迹日志升级为全链路 trace（第二周）；从 MVP 期间的 300 条轨迹里筛出 60 条坏例，沉淀成首个回归集并接入门禁（第三周）；工具加权限与审计（第四周）。

**效果**：上线首月事故 3 起，全部由监控在用户投诉前发现；回归集滚到 250 条后，迭代引发的回归率从 20% 降到 4%。起点正是那个百行 MVP 的轨迹数据。

### 案例 C：面试口述脚本

**问**：手写一个最小可用 Agent，循环里必须处理什么？

**答**（五段骨架的实况演示）：任务选窄而真实——「搜索资料并输出带来源的三句话小结」。组件四件：主循环、search/read 两个原语工具（统一返回 `{ok, data|error}`）、规定 JSON 行为格式的系统提示词、每步落盘的轨迹日志。循环五处理：参数校验（空查询回传错误让模型自修）、8 步上限、工具异常回传、连续重复调用的指纹熔断、finish 终止信号。验收标准是五收口：正常答案、澄清反问、工具汇总、如实承认做不到、熔断提示——任何输入都有确定行为，不卡死不静默。最后补一句：这个 MVP 的轨迹日志就是将来接可观测、评估集与生产护栏的种子数据，生产化路径是明确的清单而不是玄学。

## 8. 常见坑

1. **一上来做万能助理**。对策：任务选窄而真实，先跑通闭环再谈扩展。
2. **工具一上就是十几个**。对策：两三个原语工具足够，工具多不如工具稳，每个工具都是一个失败面。
3. **信任模型输出直接执行**。对策：参数校验先行，幻觉参数在程序侧拦截。
4. **校验失败直接终止任务**。对策：错误信息作为 Observation 回传，让模型自修，多数能纠正。
5. **替模型补默认参数**。对策：静默代劳破坏学习闭环，也埋下「程序行为与模型认知不一致」的雷。
6. **没有步数上限**。对策：上限写在循环头上，超限熔断并如实交代。
7. **失败无限重试**。对策：指纹熔断——同一调用指纹重复出现就注入换策略提示。
8. **异常静默吞掉**。对策：所有异常转成可读 Observation 或收口提示，绝不既不报错也不响应。
9. **没有终止信号**。对策：finish 工具或 FINAL 标记，让循环有明确出口。
10. **轨迹只打在控制台**。对策：第一天就写 JSONL 落盘，它是调试与评估的数据底座。
11. **验收只测正常路径**。对策：构造模糊、恶意、工具必失败等输入集，断言全部落入五收口。
12. **面试倒着讲**。对策：先讲 MVP 闭环证明懂原理，再讲生产化改造证明懂工程，顺序反了像背架构图。

## 9. 练习

1. 用约 100 行实现本篇的最小 Agent，把 search/read 换成真实 API，跑通第一个闭环。
2. 构造 20 条刁钻输入（空查询、非法 URL、超长目标、注入指令），验证全部落入五收口。
3. 把工具失败率人为调到 30%，对比「失败即崩」与「错误回传自修」两种策略的任务完成率。
4. 实现指纹熔断：统计加与不加两种情况下，8 步上限内任务完成率与平均步数的差异。
5. 给轨迹 JSONL 写一个统计脚本：输出平均步数、各工具成功率、自修成功次数。
6. 从 MVP 对照表（4.5）里挑三项，给自己的原型做生产化改造，记录每项的实际工作量。
7. 用五段骨架（任务/组件/循环/失败处理/验收）把自己的实现口述一遍，录音自评是否超过 3 分钟。
8. 把 MVP 期间轨迹里的坏例筛出来，手工标注 10 条——体验它们如何变成回归集的第一批种子。

## 10. 小结

- 最小可用 Agent = **一个主循环 + 两三个原语工具 + 参数校验 + 失败处理**，百行代码跑通闭环。
- 价值在闭环不在功能：先摆地摊再开商场，踩坑收益全在主循环里。
- 主循环五处理：**参数校验、步数/预算上限、错误回传自修、指纹熔断、明确终止信号**。
- 校验失败的正确反应是**回传错误让模型自修**，不是终止也不是代劳。
- 五收口：**答案、澄清反问、工具汇总、如实承认做不到、熔断提示**——任何输入都有确定去处。
- 验收标准：任何输入都不会让程序既不报错也不响应；刁钻输入集就是 MVP 的回归测试。
- 工具设计三纪律：**原语优先、统一返回结构、参数即不可信输入**。
- 轨迹 JSONL 从第一天开始落盘：调试靠它，评估靠它，面试展示工程思维也靠它。
- MVP 到生产化是明确的对照清单：网关、trace、评估门禁、权限审计、监控告警，逐格补齐（至 4.9）。
- 面试讲述五段法：任务 → 组件 → 循环五处理 → 验收五收口 → 生产化延伸，先 MVP 后生产化。
