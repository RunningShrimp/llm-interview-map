# 讲解 1.4 RAG

> 说明：0.7 讲了嵌入与向量检索的基础，1.4 把它们组装成**完整的 RAG 系统**：文档切分、索引、检索、重排、生成、引用、评估。  
> Agent 化的 RAG（Agentic RAG）和记忆系统放在 2.4 和 2.7，1.4 聚焦“让 LLM 基于外部知识回答”。

---

## 1. 定位

LLM 应用层第 4 个知识点，也是最核心的能力之一。  
它解决一个根本问题：**LLM 的知识是冻结的、不完整的、不可信的，如何让它基于外部私有知识回答？**

前置：0.7 嵌入与向量检索，以及 1.1-1.3 的模型选型、Prompt 工程与结构化输出基础。  
它是 1.5 记忆、2.4 记忆、2.7 单 Agent 架构、3.2 数据与知识工程的直接前置。

## 2. 一句话定义

RAG（Retrieval-Augmented Generation，检索增强生成），是在 LLM 生成答案之前，先从外部知识库检索相关文档并注入上下文，让 LLM 基于事实而非仅凭参数记忆来回答的工程架构。

## 3. 为什么需要

LLM 有三个硬伤：

1. **知识截止**：训练数据有截止日期，之后的事不知道。
2. **幻觉**：不知道时会编造看似合理的答案。
3. **私有知识缺失**：企业内部文档、数据库、工单，模型没见过。

传统解法是微调，但微调：

- 成本高
- 更新慢（新知识要重新训练）
- 无法追溯来源
- 容易过拟合

RAG 的优势：

| 维度 | 微调 | RAG |
|---|---|---|
| 知识更新 | 重新训练 | 更新文档即可 |
| 成本 | 高 | 低 |
| 可追溯 | 差 | 好（可引用来源） |
| 幻觉 | 仍可能 | 显著降低 |
| 权限控制 | 难 | 可做元数据过滤 |
| 冷启动 | 需要数据 | 有文档即可 |

**RAG 是当前企业落地 LLM 应用最主流的架构。**

**面试高频问法：长上下文会取代 RAG 吗？**  
共识口径：不会。长上下文解决「装得下」，没解决「找得准」——把整个知识库塞进上下文，成本与延迟随库规模线性上涨，权限过滤与引用追溯仍要靠检索层实现。生产主流是两者结合：检索负责筛出少数相关文档，长上下文负责容纳检索结果与多文档推理。

## 4. 核心原理

### 4.1 RAG 的两个阶段

```text
离线索引（Indexing）：
文档 → 清洗 → 切分 → 嵌入 → 存入向量库

在线检索生成（Retrieval + Generation）：
查询 → 嵌入 → 检索 → 重排 → 拼接上下文 → LLM 生成 → 答案 + 引用
```

### 4.2 离线索引：文档处理

**1. 数据加载**：

- PDF、Word、Markdown、HTML、数据库、API
- 工具：LangChain Loaders、LlamaIndex Readers、Unstructured

**2. 清洗**：

- 去页眉页脚、去广告、去乱码
- 统一编码
- 保留结构信息（标题、表格、列表）

**3. 切分（Chunking）**：

| 策略 | 说明 | 适用 |
|---|---|---|
| 固定长度 | 按 token/字符切 | 简单通用 |
| 递归切分 | 按段落→句子→词逐级 | 推荐默认 |
| 语义切分 | 按语义边界切 | 质量高，成本高 |
| 按结构切 | 按标题、章节切 | 结构化文档 |
| 父子切分 | 小块检索，大块返回 | 兼顾精度和上下文 |

关键参数：

- `chunk_size`：256–1024 token
- `chunk_overlap`：10%–20%

原则：

- 太小：语义碎片化，检索不准。
- 太大：噪音多，嵌入不聚焦。
- 保留 metadata：来源、标题、时间、权限、页码。

**4. 嵌入（Embedding）**：

- 用嵌入模型把每个 chunk 变成向量。
- 同一模型处理查询和文档。
- 中文场景选 BGE、GTE、Cohere。

**5. 存储**：

- 向量库：FAISS、Chroma、Qdrant、Milvus、pgvector
- 存向量 + 原文 + metadata

### 4.3 在线检索：查询处理

**1. 查询重写（Query Rewriting）**：

用户问题可能模糊、口语化、多轮依赖。

```text
原始：那退款呢？
重写：退货后多久能收到退款？
```

方法：

- LLM 重写
- 多查询生成（Multi-Query）
- HyDE（Hypothetical Document Embeddings）：先生成假设答案，再用假设答案检索

**2. 查询嵌入**：

用同一嵌入模型把查询变成向量。

**3. 向量检索**：

- ANN 检索 Top-K（如 K=20）
- 可加 metadata 过滤（权限、时间、部门）

**4. 混合检索（Hybrid Search）**：

纯向量检索弱点：

- 对编号、代码、专有名词不敏感
- 对精确关键词匹配差

混合检索：

```text
BM25（关键词）Top-20 + 向量（语义）Top-20
→ 合并去重 → Rerank → Top-5
```

分数融合方法：

- RRF（Reciprocal Rank Fusion）：按排名融合，简单有效
- 加权求和：需要调权重

**5. 重排（Rerank）**：

向量检索是双编码器（Bi-Encoder），快但精度有限。  
Rerank 用交叉编码器（Cross-Encoder），把查询和文档一起编码，精度更高但慢。

```text
查询 + 文档 → Cross-Encoder → 相关性分数
```

常用模型：BGE-Reranker、Cohere Rerank、Jina Reranker。

流程：

```text
向量检索 Top-20 → Rerank → Top-5 → 交给 LLM
```

### 4.4 生成阶段

**1. 上下文组装**：

```text
[系统指令]
你是一个知识库问答助手。只根据以下资料回答。
如果资料中没有答案，说“资料中没有相关信息”。
回答时标注引用编号。

[资料]
[1] 退货政策：签收后 7 天内可退。
[2] 退款时效：3-5 个工作日到账。

[用户问题]
退货后多久能收到退款？
```

**2. 生成约束**：

- 只使用资料回答
- 不知道就说不知道
- 标注引用
- 不编造

**3. 引用（Citation）**：

让答案可追溯：

```text
根据资料 [2]，退款需要 3-5 个工作日到账。
```

工程实现：

- Prompt 要求标注来源编号
- 输出结构化引用（文档 ID、页码）
- 前端可点击跳转

### 4.5 高级 RAG 模式

| 模式 | 说明 |
|---|---|
| Naive RAG | 基础：检索 → 生成 |
| Advanced RAG | 加查询重写、混合检索、重排 |
| Modular RAG | 模块化，可插拔 |
| GraphRAG | 用知识图谱增强检索 |
| Agentic RAG | Agent 决定何时检索、检索什么 |
| Self-RAG | 模型自我反思检索质量 |
| CRAG（Corrective RAG） | 检索质量差时自动纠正 |

**Agentic RAG**：

```text
Agent 判断：
- 需要检索吗？
- 检索什么？
- 检索结果够吗？
- 需要再检索吗？
- 答案可信吗？
```

这是 RAG 与 Agent 的结合，放在 2.7 展开。

截至 2026 年的落地现状（趋势观察）：Agentic RAG 随 Agent 框架成熟，在复杂多跳场景成为固定管线之上的升级选项，面试考察频率已与基础链路相当；GraphRAG 对关系型、多跳问题有效，但图谱构建与增量更新成本高，生产落地集中在少数对知识结构要求高的场景。

### 4.6 RAG 评估

RAG 评估分两部分：

**检索评估**：

| 指标 | 含义 |
|---|---|
| Recall@K | 前 K 个里包含多少相关文档 |
| Precision@K | 前 K 个里有多少相关 |
| MRR | 第一个相关文档的排名倒数 |
| NDCG | 考虑排序位置的增益 |
| Hit Rate | 至少命中一个相关的比例 |

**生成评估**：

| 指标 | 含义 |
|---|---|
| 忠实度 Faithfulness | 答案是否基于检索内容 |
| 答案相关性 | 答案是否回答了问题 |
| 上下文相关性 | 检索内容是否相关 |
| 引用准确率 | 引用是否指向正确来源 |

工具：RAGAS、TruLens、DeepEval。

注意：RAGAS 的忠实度、相关性指标依赖 LLM-as-Judge 打分，judge 存在偏差且会随模型漂移，需要用人工标注的小型 golden set 定期校准（评估体系展开见 1.6）。

**核心原则**：

> **先保证检索召回，再优化生成。检索没召回，LLM 再强也白搭。**

### 4.7 RAG 失败模式

| 失败 | 原因 | 解法 |
|---|---|---|
| 检索不到 | 切分太大/太小、嵌入模型差 | 调切分、换模型、混合检索 |
| 检索到但不相关 | 纯向量检索弱点 | 加 Rerank、混合检索 |
| 答案不忠实 | LLM 忽略上下文 | 加强 Prompt 约束、验证器 |
| 答案不完整 | Top-K 太小 | 增大 K、多查询 |
| 引用错误 | 编号混乱 | 结构化引用、校验 |
| 多轮丢失上下文 | 查询未重写 | 查询重写、历史压缩 |
| 权限泄露 | 无 metadata 过滤 | 权限过滤、多租户隔离 |

## 5. 架构 / 流程

一个生产级 RAG 系统：

```text
┌──────────────────────────────────────────┐
│  离线索引                                 │
│  文档 → 清洗 → 切分 → 嵌入 → 向量库       │
│         ↓                                 │
│  元数据：来源、权限、时间、页码            │
└──────────────────────────────────────────┘
                  ↓
┌──────────────────────────────────────────┐
│  在线检索                                 │
│  查询 → 重写 → 嵌入 → 混合检索 → Rerank   │
│         ↓                                 │
│  元数据过滤：权限、时间、部门              │
└──────────────────────────────────────────┘
                  ↓
┌──────────────────────────────────────────┐
│  生成                                     │
│  上下文组装 → LLM → 答案 + 引用           │
│         ↓                                 │
│  校验：忠实度、引用、敏感信息              │
└──────────────────────────────────────────┘
                  ↓
┌──────────────────────────────────────────┐
│  评估与监控                               │
│  检索指标、生成指标、bad case、成本延迟    │
└──────────────────────────────────────────┘
```

## 6. 代码 / 工具

### 6.1 最小 RAG 实现

```python
import chromadb
from openai import OpenAI

client = OpenAI(api_key="YOUR_KEY")

# 1. 离线索引
documents = [
    "退货政策：签收后 7 天内可退。",
    "退款时效：3-5 个工作日到账。",
    "换货说明：15 天内可换。",
]

chroma = chromadb.Client()  # 内存模式，重启即失；生产用 PersistentClient(path="./chroma_data")
collection = chroma.create_collection("knowledge")
collection.add(documents=documents, ids=[f"doc{i}" for i in range(len(documents))])

# 2. 在线检索
def retrieve(query: str, top_k: int = 2) -> list[str]:
    results = collection.query(query_texts=[query], n_results=top_k)
    return results["documents"][0]

# 3. 生成
def rag_answer(query: str) -> str:
    docs = retrieve(query)
    context = "\n".join(f"[{i+1}] {d}" for i, d in enumerate(docs))

    prompt = f"""你是一个知识库问答助手。
只根据以下资料回答。如果资料中没有答案，说“资料中没有相关信息”。
回答时标注引用编号。

资料：
{context}

用户问题：{query}
"""

    response = client.chat.completions.create(
        model="gpt-4o-mini",
        messages=[{"role": "user", "content": prompt}],
        temperature=0,
    )
    return response.choices[0].message.content

print(rag_answer("退货后多久能收到退款？"))
```

### 6.2 带 Rerank 的 RAG

```python
from sentence_transformers import CrossEncoder

reranker = CrossEncoder("BAAI/bge-reranker-base")

def retrieve_with_rerank(query: str, top_k: int = 20, final_k: int = 5):
    # 向量检索 Top-20（复用 6.1 的 collection）
    results = collection.query(query_texts=[query], n_results=top_k)
    docs = results["documents"][0]

    # Rerank
    pairs = [(query, doc) for doc in docs]
    scores = reranker.predict(pairs)

    # 取 Top-5
    ranked = sorted(zip(docs, scores), key=lambda x: -x[1])
    return [doc for doc, _ in ranked[:final_k]]
```

### 6.3 混合检索（BM25 + 向量）

```python
from rank_bm25 import BM25Okapi
import jieba

# 复用 6.1 的 documents 与 collection
# BM25
tokenized_docs = [list(jieba.cut(d)) for d in documents]
bm25 = BM25Okapi(tokenized_docs)

def hybrid_retrieve(query: str, top_k: int = 5):
    # BM25
    tokenized_query = list(jieba.cut(query))
    bm25_scores = bm25.get_scores(tokenized_query)
    bm25_top = sorted(range(len(bm25_scores)), key=lambda i: -bm25_scores[i])[:top_k]

    # 向量
    vec_results = collection.query(query_texts=[query], n_results=top_k)
    vec_ids = [int(i.replace("doc", "")) for i in vec_results["ids"][0]]

    # RRF 融合
    scores = {}
    for rank, idx in enumerate(bm25_top):
        scores[idx] = scores.get(idx, 0) + 1 / (rank + 60)
    for rank, idx in enumerate(vec_ids):
        scores[idx] = scores.get(idx, 0) + 1 / (rank + 60)

    top_ids = sorted(scores, key=lambda i: -scores[i])[:top_k]
    return [documents[i] for i in top_ids]
```

### 6.5 RAGAS 评估

```python
# pip install ragas langchain-openai
# RAGAS 0.2+ 的 evaluate 需要 EvaluationDataset 和一个评测 LLM
from ragas import evaluate, EvaluationDataset
from ragas.llms import LangchainLLMWrapper
from ragas.metrics import faithfulness, answer_relevancy, context_precision
from langchain_openai import ChatOpenAI

evaluator_llm = LangchainLLMWrapper(ChatOpenAI(model="gpt-4o-mini"))

dataset = EvaluationDataset.from_list([
    {
        "question": "退货后多久能收到退款？",
        "answer": "3-5 个工作日。",
        "contexts": ["退款时效：3-5 个工作日到账。"],
        "ground_truth": "3-5 个工作日。",
    }
])

result = evaluate(
    dataset=dataset,
    metrics=[faithfulness, answer_relevancy, context_precision],
    llm=evaluator_llm,
)
print(result)
```

## 7. 案例

### 案例 A：企业知识库问答

**场景**：1000 份内部文档，员工问政策、流程、产品问题。

**架构**：

1. 文档按标题递归切分，chunk_size=512，overlap=64。
2. BGE-M3 嵌入，Qdrant 存储。
3. 混合检索 + BGE-Reranker。
4. GPT-4o-mini 生成，标注引用。
5. RAGAS 评估，每周跑回归。

**效果**：回答准确率从 60% 提升到 85%，幻觉率从 15% 降到 3%。

### 案例 B：多轮 RAG 查询重写

**对话**：

```text
用户：退货政策是什么？
助手：签收后 7 天内可退。
用户：那退款呢？
```

“那退款呢？”单独检索会失败。  
查询重写：

```text
结合历史，重写为：退货后多久能收到退款？
```

再检索，命中“退款时效”。

### 案例 C：权限过滤

多租户系统，A 公司不能看 B 公司文档。

存储时加 metadata：

```python
collection.add(
    documents=[...],
    metadatas=[{"tenant": "company_a", "dept": "hr"}],
    ids=[...],
)
```

检索时过滤：

```python
collection.query(
    query_texts=[query],
    n_results=5,
    where={"tenant": "company_a"},
)
```

## 8. 常见坑

1. **切分太大或太小**。  
   太大噪音多，太小语义碎。建议 256–1024 token + 10%–20% overlap。

2. **只用纯向量检索**。  
   编号、代码、专有名词需要 BM25 混合检索。

3. **不加 Rerank**。  
   Top-K 向量检索精度有限，Rerank 能显著提升。

4. **嵌入模型选错**。  
   中文场景用英文模型，效果差。选 BGE、GTE、Cohere。

5. **查询和文档用不同嵌入模型**。  
   向量空间不一致，检索失效。

6. **不做查询重写**。  
   多轮对话、模糊问题检索不到。

7. **Prompt 不约束**。  
   不要求“只根据资料回答”，LLM 会自由发挥。

8. **不标注引用**。  
   答案不可追溯，用户不信任。

9. **不做权限过滤**。  
   多租户场景可能泄露数据。

10. **不评估检索**。  
    只看最终答案，不知道是检索问题还是生成问题。

11. **Top-K 太大**。  
    上下文塞太多，噪音干扰，成本高，还容易“中间遗忘”（lost in the middle）。

12. **不更新索引**。  
    知识库变了，向量库没更新，检索旧内容。

13. **忽略元数据**。  
    来源、时间、权限、页码都要存，否则无法过滤和引用。

14. **把 RAG 当万能**。  
    RAG 解决知识问题，不解决推理、计算、实时数据，需要工具配合。

## 10. 小结

- RAG = 离线索引 + 在线检索 + 生成。
- 离线：**加载 → 清洗 → 切分 → 嵌入 → 存储**。
- 在线：**查询重写 → 嵌入 → 混合检索 → Rerank → 生成 → 引用**。
- 核心原则：**先保证检索召回，再优化生成。**
- 生产标配：**混合检索 + Rerank + 引用 + 权限过滤 + 评估**。
- 高级模式：**Agentic RAG、Self-RAG、GraphRAG**。
- 评估：**检索看 Recall@K，生成看忠实度和相关性。**
- 这些能力直接支撑：1.5 记忆、2.4 记忆、2.7 单 Agent 架构、3.2 知识工程。
