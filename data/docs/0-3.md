# 讲解 0.3 机器学习/深度学习基础

> 说明：0.1 的损失与梯度下降、0.2 的 Python 底座在本篇合流：所谓训练，就是一个用 Python 跑的「前向-损失-反向-更新」循环。前置 0-1、0-2；后续 0-4 Transformer、0-5b 预训练与 SFT、3.x 数据工程，全部建立在「模型如何学习、泛化、失败」这组直觉上。

---

## 1. 定位

L0 基础层第 3 个锚点，对应大纲核心问题：**模型如何学习、泛化、失败？**

掌握档位是「了解-理解」：不要求从零推导反向传播，要求能讲清训练循环每一步在干什么、过拟合为什么会发生、以及它在大模型时代的两种形态（SFT 死记、数据去重）。

三个子问题对应三块内容：

| 子问题 | 概念 | 与后续锚点的接口 |
|---|---|---|
| 学习：参数怎么被改 | 训练循环、反向传播 | 0-5b 预训练与 SFT、0-5c RLHF |
| 泛化：为什么新题也会做 | 训练-验证-测试、正则化 | 3.x 评估体系、2-9b Agent 评测 |
| 失败：为什么会学崩 | 过拟合、欠拟合、梯度消失 | 0-5b 的 SFT 数据质量、3.2 数据工程 |

应用岗常被问：「SFT 之后模型为什么 sometimes 逐字复述训练数据？」「训练集和验证集分数差距大说明什么？」答案全在本篇。

## 2. 一句话定义

模型训练像教学生刷题：先乱猜答案，对错之间的差距（损失）经反向传播归因到每个参数，再按梯度下降微调，几百万轮后规律刻进参数——这是学习。把练习题连答案背死、模拟考满分而真高考崩盘，就是过拟合；根本没学进去、看啥都不会，是欠拟合。训练的本质是学规律，不是背答案。

## 3. 为什么需要

应用岗不训底座模型，但天天在「用模型、微调模型、评估模型」，这三件事都要求懂训练直觉：

1. **微调是应用岗的真实工作**。SFT 小样本微调、LoRA 适配业务，不懂训练循环就看不懂 loss 曲线，调不了学习率与轮数。
2. **评估体系建立在数据切分上**。不知道训练-验证-测试为什么要分开，就理解不了 benchmark 污染、评测集泄露这些大模型时代的高频事故。
3. **数据质量决定模型上限**。「数据去重」「防捷径特征」这些数据工程动作（3.x），全是为治过拟合与记忆化服务的。

| 不懂训练直觉 | 懂训练直觉 |
|---|---|
| SFT 把 loss 调到 0 当成功 | loss 趋 0 警惕死记（见 4.3） |
| 评测集随手混进训练数据 | 三集严格隔离，防污染 |
| 数据多多益善，重复堆量 | 重复数据催生背诵，先去重 |
| 模型差就无脑加训练轮数 | 先分辨欠拟合还是过拟合 |

## 4. 核心原理

### 4.1 监督、无监督与自监督

| 范式 | 数据形态 | 学什么 | 典型任务 |
|---|---|---|---|
| 监督学习（Supervised） | 带人工标注的（输入, 正确答案）对 | 输入到答案的映射 | 垃圾邮件分类、SFT（指令-回答对） |
| 无监督学习（Unsupervised） | 无标注的原始数据 | 数据内在结构 | 聚类、降维 |
| 自监督学习（Self-Supervised） | 无标注，但从数据自身构造监督信号 | 数据的统计规律 | LLM 预训练：用下一词当标签 |

关键认知：**LLM 的预训练是自监督**——拿互联网文本「今天天气真好，适合出去玩」，把每个词依次遮住让模型猜，猜错即损失。不需要人工标注，文本本身就是答案，因此才能吃下海量数据。而 SFT 回到监督形态：人工写的（指令, 回答）对，教模型「按指令干活」（0-5b 展开）。

### 4.2 训练-验证-测试：为什么要切三份

切数据像考试制度设计：平时作业（训练集）可以翻着学，模拟考（验证集）用来调整策略，真高考（测试集）只能考一次。

| 集合 | 占比（常规） | 用途 | 谁有权限看 |
|---|---|---|---|
| 训练集 Training | 70-80% | 前向、算损失、更新参数 | 模型反复见 |
| 验证集 Validation | 10-15% | 每轮评估、调超参、早停 | 模型不训练，工程常看 |
| 测试集 Test | 10-15% | 最终一次性评估，报告泛化能力 | 最后才碰，考完不回头 |

两条纪律：

1. **验证集驱动决策，测试集只准用一次**。反复拿测试集调参，它就退化成了验证集，泛化数字开始虚高。
2. **防数据泄露（Data Leakage）**：测试信息以任何形式混入训练（同一用户样本跨集、评测题混进训练语料）都会让分数失真。大模型时代的对应形态是 benchmark 污染——训练语料里混入了评测集原题，跑分漂亮、真实能力没涨。3.x 评估体系与 2-9b 的 Agent 评测都以此为前提。

### 4.3 过拟合与欠拟合

两种学崩法，症状相反，药方也相反：

| 维度 | 欠拟合 Underfitting | 过拟合 Overfitting |
|---|---|---|
| 训练集分数 | 低 | 极高（接近满分） |
| 验证/测试集分数 | 低 | 明显更低（落差大） |
| 病因 | 模型太简单 / 训练不足 / 特征没学到 | 数据太少太单一 / 训练过头 / 模型记住了题目本身 |
| 直觉 | 根本没学进去 | 把题背死了 |
| 药方 | 加大模型、训久一点、加特征 | 更多更多样的数据、正则化、早停、去重 |

判断口诀：**看两条曲线的分岔**。训练损失与验证损失一起下降→还在学；训练降验证不降→停滞；训练降验证回升→过拟合发生，该早停了。

**大模型时代的两种特殊形态：**

1. **SFT 死记（记忆化 / Memorization）**。小数据集上微调大模型、重复跑几十个 epoch，模型会把训练回答逐字背下来：换个问法就答不上，或原样复述训练语料（连带其中的隐私、错误一起背）。根因是「重复暴露 + 容量远超数据信息量」，模型干脆记忆而不是提炼规律。这与传统过拟合同源，但症状更隐蔽——生成质量看着流畅，实际是背诵。
2. **数据去重（Deduplication）**。预训练语料中同一篇文章被抓取几十次，重复样本会让模型对它记忆化（逐字背诵训练文本），既浪费算力又有隐私风险。工程对策：精确去重（哈希）+ 近重复去重（MinHash/SimHash 等指纹聚类）。「训练数据先去重再喂」是数据工程（3.2）的第一课，也是 0-3 与数据工程的直接接口。

一句话：**大模型没有消灭过拟合，只是把它从「曲线分岔」变成了「背诵与复述」。**

### 4.4 反向传播与梯度消失

反向传播（Backpropagation）回答一个问题：损失是最后算出来的，亿万个参数各自该怎么改？答案是**链式法则逐层归因**：输出错了，先算出最后一层的责任，再按「谁影响了谁、影响多大」把责任往回分，一直分到第一层——错题归因的自动化。

```text
前向:   x -> 层1 -> 层2 -> ... -> 层N -> 输出 -> 损失 L
反向:   dL/d参数N -> dL/d参数(N-1) -> ... -> dL/d参数1
        （每往回一层，都要乘上该层的局部导数）
```

**梯度消失（Vanishing Gradient）**的直觉就在这个「乘」字：每往回传一层都要乘一个 0 到 1 之间的局部导数，连乘几十层后梯度趋近于 0——越靠近输入的层收到的责任信号越弱，等于「归因归到一半就散了」，浅层学不动，深网络训不出来。

深度学习基建的相当一部分就是对这个问题的围剿：

| 手段 | 一句话原理 |
|---|---|
| ReLU 等激活函数 | 正区间导数恒为 1，连乘不衰减（对比 sigmoid 两端饱和区导数趋 0） |
| 残差连接（ResNet/Transformer） | 输出 = F(x) + x，梯度可以沿「捷径」直通浅层 |
| LayerNorm | 稳定每层数值分布，防止信号逐层放大或衰减 |
| 合理初始化 | 让前向信号与反向梯度的方差在层间基本不变 |
| 注意力里的缩放 √d_k | 防点积过大→softmax 饱和→梯度消失（0-4c 的考点点） |

与之相对的是梯度爆炸（连乘大于 1 的数，梯度无限放大），对策是梯度裁剪——按范数封顶。

### 4.5 与过拟合斗争的手段

| 手段 | 做法 | 一句话原理 |
|---|---|---|
| 早停（Early Stopping） | 盯验证损失，一回升就停 | 别让模型进入背题阶段 |
| 更多更多样的数据 | 扩数据集、覆盖真实分布 | 见多识广才能提炼规律 |
| 数据去重 | 哈希 + MinHash 近重复检测 | 重复样本催生记忆化 |
| 正则化（权重衰减） | 惩罚过大的参数值 | 逼模型用更平缓的方式拟合 |
| Dropout | 训练时随机丢弃一部分神经元 | 不让模型依赖单一通路，逼出冗余表征 |
| 数据增强 | 翻转、改写、同义替换扩充样本 | 等效于更多样数据 |
| 清理捷径特征 | 排查与标签伪相关的字段 | 防模型学「看日期判垃圾」这类假规律 |

## 5. 架构 / 流程

一个带验证与早停的完整训练循环——这就是「模型是怎么学的」的全部机械细节：

```text
准备: 数据切分为 训练集 / 验证集 / 测试集（互不相交）
        |
        v
+-----------------------------------------------+
| 每轮 epoch:                                     |
|   对训练集的每个 batch:                          |
|     1. 前向传播:  输入 -> 模型 -> 预测            |
|     2. 算损失:    预测 vs 正确答案 -> 标量 loss   |
|     3. 反向传播:  链式法则求 loss 对每个参数的梯度 |
|     4. 参数更新:  theta <- theta - lr * 梯度     |
|        |                                       |
|        +-- 重复，直到训练集过完一遍 = 1 epoch     |
+-----------------------------------------------+
        |
        v
每轮结束: 在验证集上评估（模型不更新参数）
        |
        +-- 验证损失仍在降? -> 继续下一轮
        |
        +-- 验证损失回升 / 训练损失趋 0 而验证停滞?
        |        -> 过拟合征兆 -> 早停，回到最优 checkpoint
        v
全部结束: 在测试集上跑最终评估（只用这一次）
        |
        v
训练损失 vs 验证损失 对照 -> 诊断: 欠拟合 / 刚好 / 过拟合
```

参数有亿万个，但循环只有这五步：**前向、损失、反向、更新、评估**。0-2 的 Python 底座（循环、异步、日志）承载的就是它。

## 6. 代码 / 工具

### 6.1 PyTorch 最小训练循环（含过拟合演示）

```python
import torch
import torch.nn as nn

torch.manual_seed(0)

# 任务：拟合 20 个点。标签是纯随机噪声——没有任何规律可学。
# 模型只能靠"背答案"降训练损失，于是过拟合被原样复现。
n_samples, n_features = 20, 64
X = torch.randn(n_samples, n_features)
y = torch.randn(n_samples, 1)                    # 纯噪声标签

# 数据切分：训练 12 / 验证 8（演示用小数字）
X_train, y_train = X[:12], y[:12]
X_val,   y_val   = X[12:], y[12:]

model = nn.Sequential(                           # 一个 3 层小网络
    nn.Linear(n_features, 128), nn.ReLU(),
    nn.Linear(128, 128),         nn.ReLU(),
    nn.Linear(128, 1),
)
optimizer = torch.optim.SGD(model.parameters(), lr=0.01)   # 用的就是 0-1 的更新规则 θ←θ-lr·∇L
loss_fn = nn.MSELoss()                           # 回归任务用 MSE（见 0-1 4.4）

EPOCHS = 300
for epoch in range(EPOCHS):
    # ---- 训练阶段：前向 -> 损失 -> 反向 -> 更新 ----
    model.train()
    optimizer.zero_grad()                        # 清上一轮梯度
    pred = model(X_train)                        # 1. 前向
    loss = loss_fn(pred, y_train)                # 2. 损失
    loss.backward()                              # 3. 反向传播求梯度
    optimizer.step()                             # 4. 梯度下降更新

    # ---- 验证阶段：只评估，不更新 ----
    if (epoch + 1) % 50 == 0 or epoch == 0:
        model.eval()
        with torch.no_grad():                    # 验证不需要梯度
            val_loss = loss_fn(model(X_val), y_val).item()
        print(f"epoch {epoch+1:3d}  train_loss={loss.item():7.3f}  "
              f"val_loss={val_loss:7.3f}")

# 观察输出：train_loss 一路降（模型在背这 12 个答案），
# val_loss 却越来越差（背的答案对新数据毫无用处）——过拟合现场。
# 真实任务里标签有规律，曲线应先同降、后分岔，早停就停在分岔前。
```

对照实验：把 `y = torch.randn(...)` 换成有真实规律的标签（如 `y = (X[:, :1] * 2 + 1)`），两条曲线会一起下降——**有规律可学时，模型学规律；无规律可学时，模型只能背题。** 过拟合的本质由此一目了然。

### 6.2 早停的最小实现

```python
# 在 6.1 的循环骨架上加一个早停器
class EarlyStopping:
    def __init__(self, patience: int = 5):
        self.patience = patience     # 验证损失连续多少轮不降就停
        self.best = float("inf")
        self.counter = 0

    def step(self, val_loss: float) -> bool:
        if val_loss < self.best - 1e-4:
            self.best = val_loss     # 有改善：记录最优，清零计数
            self.counter = 0
            return False
        self.counter += 1            # 无改善：累计
        return self.counter >= self.patience   # 触发即停

# 用法（嵌进训练循环）:
# stopper = EarlyStopping(patience=5)
# ...
# if stopper.step(val_loss):
#     print("验证损失不再下降，早停于 epoch", epoch)
#     break
```

工具速查：训练框架 PyTorch / 微调用 Hugging Face Transformers + PEFT（LoRA）；实验追踪 TensorBoard / Weights & Biases（盯 train/val 两条曲线）；去重可用 datasketch（MinHash）或文本相似度指纹库。

## 7. 案例

### 案例 A：垃圾邮件分类器上线一周崩盘

某团队训练垃圾邮件分类器：训练集准确率 98%，上线一周后真实邮件判断一团糟。复盘发现两个根因：一是训练数据太少且单一（集中于某几类模板），模型背题而非学规律；二是混入捷径特征——这批垃圾邮件恰好都来自某个日期段，模型学会了看日期而不是看内容。治理：扩充样本多样性并剔除日期类伪相关字段（清捷径）；切出验证集、损失一回升就早停。复训后训练集 92%、线上准确率 88%，差距收窄，真实可用。**训练集近乎满分而线上崩，是过拟合最典型的验尸报告。**

### 案例 B：SFT 死记与数据去重

一家公司用约 5000 条客服对话 SFT 一个对话模型，其中大量回答是同一套话术模板原样复制。微调几十个 epoch 后，模型对新问题开始逐字复述模板，问法稍变就答非所问，甚至把训练数据里的内部工单编号原样吐了出来（记忆化连带隐私风险）。治理：对 SFT 数据做去重与改写（同义扩写，模板保留语义但表达多样化），epoch 从 40 降到 5 并配早停。之后模型对换问法的问题回复正常，测试集回复多样性显著上升，复述训练原文的比例大幅下降。**SFT 不是把答案塞进模型，而是教风格与格式——重复塞会变成背。**

### 案例 C：跑分虚高与评测污染

某团队自研模型在内部评测集上 85 分，业务方实测却远低于预期。排查发现：评测题目曾被同事贴进过一份「参考示例」文档，而这份文档进了微调数据——测试集信息泄露进训练，分数自然虚高。治理：评测集单独保管、微调数据上线前与评测集做相似度碰撞去重、另建一批从不进任何训练流程的盲测题定期抽查。治理后跑分降到 72，但与业务实测一致——**一个可信但难看的数字，好过一个漂亮但撒谎的数字。**

## 8. 常见坑

1. **训练集分数当唯一指标**。只看训练准确率，过拟合完全隐形。对策：切验证集，两条曲线一起看。
2. **测试集反复使用**。用测试集调参，泛化数字虚高。对策：测试集只在最终评估时碰一次。
3. **数据切分前没打乱或按时间乱切**。分布不一致导致验证集失真。对策：常规任务随机切、时序任务按时间切，切完查分布。
4. **数据泄露**。同一用户/同一原文的样本跨集出现。对策：按实体分组切分，训练前做跨集碰撞检查。
5. **把「loss 趋 0」当成功**。小数据上这多半是背题。对策：警惕 SFT 死记，查验证表现与输出多样性。
6. **重复数据堆量**。同一话术复制 N 遍只会催生记忆化。对策：入库前哈希 + MinHash 去重。
7. **无脑加训练轮数**。模型差就多训是常见误判。对策：先分清欠拟合（两条曲线都低）还是过拟合（分岔），对症下药。
8. **忽略捷径特征**。模型学会看日期、看模板编号而非内容。对策：检查特征与标签的伪相关，必要时剔除。
9. **学习率太大震荡、太小停滞**。loss 曲线毛刺大或不降。对策：按曲线诊断调参（0-1 案例 C 的方法）。
10. **验证集忘了 model.eval() / no_grad**。验证阶段仍在更新参数或白算梯度，结果失真。对策：训练/验证两种模式严格分开（6.1 的写法）。
11. **梯度消失导致深网训不动**。深层模型浅层几乎没学。对策：ReLU、残差、LayerNorm、合理初始化，是基建不是可选项。
12. **评测集混入训练语料**。跑分好看、业务拉胯。对策：评测数据隔离保管 + 相似度碰撞去重（案例 C）。

## 10. 小结

- 训练循环五步：**前向、损失、反向、更新、评估**——所有训练框架都是它的变体。
- LLM 预训练是**自监督**（下一词预测），SFT 回到**监督**（指令-回答对）（0-5b 展开）。
- 数据切三份：**训练学、验证调、测试考**；测试集只准用一次。
- 过拟合 = **训练高、验证低的落差**，本质是背题而非学规律；欠拟合是两条曲线都低。
- 大模型形态的过拟合：**SFT 死记**（小数据重复训→逐字复述）与**训练数据重复→记忆化**。
- 对策优先级：**更多样数据 > 去重 > 早停 > 正则化**；数据是食材，质量决定上限。
- 反向传播 = **链式法则逐层归因**；梯度消失 = 连乘小于 1 的局部导数让浅层收不到信号。
- 深度学习基建在围剿梯度消失：**ReLU、残差、LayerNorm、初始化、√d 缩放**（0-4c 呼应）。
- 早停盯验证损失回升；`model.eval()` + `no_grad` 是验证阶段的纪律。
- 评测污染是过拟合思想在 LLM 时代的翻版：**测试信息进了训练，分数就开始撒谎**。
- 这组直觉直接支撑：0-4 Transformer（被训练的对象）、0-5b 预训练与 SFT、3.2 数据工程、2-9b 评估治理。
