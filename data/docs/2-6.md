# 讲解 2.6 反思与自我修正

> 说明：2.5 的 ReAct 循环解决了「每一步该干什么」，但它只保证单步合理，不保证整趟结果正确——本篇给循环装上「事后复盘」：执行→反思→语言化经验入记忆→带经验重执行。  
> 自主型架构（2.7）常以 ReAct+Reflection 组合出战，反思负责质量兜底；反思收益如何量化落在 2.9 评估体系；RAG 侧的自我修正（Self-RAG/CRAG）在 1.4 已埋伏笔，H4 Agentic RAG 再展开。

---

## 1. 定位

单 Agent 核心（S2 关卡）的收官件。2.1 定义 Agent、2.2 规划、2.3 工具、2.4 记忆、2.5 执行循环——五个模块拼出一个能干活的 Agent；2.6 回答最后一个问题：**它错了怎么办？**

工程上，「执行失败」分两种：

1. **硬失败**：工具报错、输出不合法、超时——2.3/2.5 的重试与熔断处理这类。
2. **软失败**：跑完了、没报错，但答案错了——这才是反思机制的靶子。

面试高频问法是「Agent 执行失败了，你的系统怎么发现错了、怎么修正？」标准答题骨架就是本篇结构：怎么发现（验证器与自评）→ 怎么修正（Reflexion 经验沉淀）→ 特殊场景（幻觉校正）→ 代价控制（最大轮数熔断）。

它是 2.7 自主型架构的直接前置（自主型 = ReAct + Reflection 兜底），也支撑 H4 Agentic RAG（规划-检索-反思）。

## 2. 一句话定义

反思（Reflection/Reflexion）是让 Agent 在执行后回头检查：发现错误就把「错在哪、下次怎么办」写成**语言化经验（Verbal Experience）**存入记忆，下一轮带着经验重执行——不靠改模型权重、不靠盲目重试，靠把失败教训沉淀成可复用的文字。

Reflexion 一词来自论文《Reflexion: Language Agents with Verbal Reinforcement Learning》（arXiv 2303.11366）：把强化学习的「奖励信号」替换成「语言反馈」，让 Agent 从自己的失败里学。

## 3. 为什么需要

**重试解决不了软失败。** 考虑一个真实场景：

```text
任务：财报里 2025 年净利润是多少？
第 1 轮回答：120 亿（错，表格里写的是 102 亿）
简单重试第 2 轮：118 亿（还是错，又记串了）
简单重试第 3 轮：121 亿（还是错）
```

重试时上下文里没有任何新信息，模型只是换个姿势犯同一个错——原样再掷一次骰子。错误率要下降，每一轮必须比上一轮**多知道一点东西**。

三个硬理由：

1. **LLM 的输出有随机性，一次执行不代表能力上限**——但无信息的重复只是重复。
2. **任务环境会反馈失败信号**（工具报错、评估不通过、用户拒绝）——这个信号不利用就浪费了。
3. **把教训写成文字比微调模型便宜几个数量级**——语言化经验是最便宜的「学习」方式。

| 维度 | 简单重试 | Reflexion 反思 |
|---|---|---|
| 每轮新增信息 | 无（上下文不变） | 一条语言化经验卡 |
| 失败去向 | 被丢弃 | 沉淀进记忆，跨任务复用 |
| 错误率趋势 | 随机波动，不单调下降 | 逐轮下降（有验证器时） |
| 上下文成本 | 不变 | 每轮增加经验卡（需截断） |
| 适用失败类型 | 偶发瞬时错误（限流、超时） | 系统性错误（方法不对） |
| 类比 | 把卷子重做一遍 | 翻错题本再重做 |

## 4. 核心原理

### 4.1 Reflexion 四步循环

```text
执行（Actor）→ 评估（Evaluator）→ 反思（Reflector）→ 经验入记忆 → 带经验重执行
```

1. **执行**：Agent 带着当前记忆里的经验卡跑完一轮任务，产出答案与轨迹。
2. **评估**：判断这轮是否成功。先上硬验证器，验证器覆盖不到的再用自评（见 4.3）。
3. **反思**：失败时，把「失败轨迹 + 评估意见」交给反思器，产出一条**可执行的教训**——不是态度检讨。
4. **经验入记忆**：教训写成一句话经验卡，存入记忆（2.4 的记忆模块），下次执行前注入上下文。

反思质量的关键在第三步。对比：

```text
差的反思：「这次没答对，下次要更认真。」           ← 空话，下一轮毫无作用
好的反思：「失败原因：没查数据源就凭印象作答。
          下次动作：涉及具体数字，先调 read_table
          核实原文，再回答。」                     ← 可执行，下一轮照做
```

经验卡还要能**跨任务复用**：「涉及数字先核实再作答」对任何财务问答都有效——失败一次，全线受益。

### 4.2 与简单重试的本质区别

一句话：**重试是原样再掷一次骰子；反思让每一轮都比上一轮多一张经验卡。**

工程视角再看三处差异：

1. **失败的处理位置不同**：重试在调用层（拿到异常就再来一次）；反思在任务层（整趟跑完、评估不通过才触发）。
2. **需要的状态不同**：重试无状态；反思需要记忆模块持久化经验卡，否则每个会话都重新踩坑。
3. **收益曲线不同**：重试的成功率是常数；反思的成功率随轮数上升——这正是它比「加大 temperature 重roll」有效得多的原因。

### 4.3 验证器（Verifier）与自评（Self-Evaluation）

「怎么发现错了」是反思的前置。发现手段按可靠度排序：

| 手段 | 原理 | 可靠度 | 例子 |
|---|---|---|---|
| 硬验证器 | 规则/程序判定，确定性 | 最高 | JSON Schema 校验、单测、SQL EXPLAIN、编译、数值范围检查 |
| 工具反馈 | 外部系统的真实回报 | 高 | HTTP 状态码、API 报错信息、数据库异常 |
| 外部 Judge | 另一个模型按标准打分 | 中 | LLM-as-Judge（1.6 的裁判模型） |
| 自评 | 模型检查自己的输出 | 最低 | 「你的答案对吗？」——有自我偏好，倾向给自己打高分 |

两条工程原则：

1. **硬验证器优先**。凡是有客观判据的任务（代码、SQL、结构化输出、有金标答案的题），一律用程序判定，绝不交给模型自评。
2. **自评只做兜底，且尽量「换人评」**。用更强或不同的模型当 Judge，比让干活模型自评可靠；让原模型自评自己的答案，相关性错误会让它坚持错误答案。

### 4.4 反思用于幻觉校正：存疑触发核实

幻觉（Hallucination，0.5d）的机理是「似真不等于为真」——模型在知识空白处按风格补全。反思给幻觉治理（1.7b 的分层防御）提供了**事后自查**这一层：

```text
生成草稿 → 自查每条事实性陈述
        ├─ 有资料依据（grounded）→ 保留
        └─ 凭印象写的（memory），把握不足 → 触发搜索/核实工具查证
                ├─ 查到 → 用事实替换印象，带上来源
                └─ 查不到 → 删掉或标注「待核实」，绝不硬写
```

要点两条：

1. **存疑的信号要具体**：不是「感觉不对」，而是「这条数字我没查过」「这个论断没有资料支持」——让模型自查时标注每句话的依据来源。
2. **核实要动真格**：触发搜索/数据库工具拿事实，而不是在措辞上加「大概、可能」——那只是把幻觉包装得更隐蔽。

### 4.5 Self-RAG：检索侧的自我修正（一笔）

Self-RAG（arXiv 2310.11511）把反思思想搬进 RAG：从「一次检索」升级为「检索→自评→修正」的循环——检索结果不相关就改写查询重查，生成后自评答案是否被资料支持，不支持就回炉。CRAG（Corrective RAG）同理，检索质量差时自动纠正。1.4 的高级 RAG 模式表里已列出，本篇不展开，H4 Agentic RAG 汇总。

```text
查询 → 检索 →【自评：资料相关吗？】
      ├─ 相关 → 生成 →【自评：答案被资料支持吗？】→ 带引用输出
      └─ 不相关 → 改写查询 → 再检索（最多 N 次）→ 仍无 → 回复「资料不足」
```

### 4.6 反思的成本边界

反思不是免费的：每多一轮 = 一次完整执行 + 一次评估 + 一次反思调用。成本结构：

| 环节 | 触发条件 | 成本量级 | 可省点 |
|---|---|---|---|
| 执行 | 每轮必有 | 最高（含工具调用） | 断点续跑，别全量重跑 |
| 评估 | 每轮必有 | 低（规则）到中（Judge） | 硬验证器替代 LLM Judge |
| 反思 | 仅失败轮 | 中 | 失败才反思，成功不反思 |
| 经验注入 | 每轮必有 | 低 | 只带 top-k 相关经验卡 |

三条边界原则：

1. **最大轮数熔断**：给反思循环设上限，论文常见配置 2–7 轮。无限自我怀疑和死循环一样烧钱（2.3 的预算护栏在此同样生效）。
2. **成功不反思**：评估通过直接输出，别为了「更稳」再自我怀疑一轮——过度反思可能把对的改成错的。
3. **经验卡限量**：注入上下文的经验卡只取与当前任务最相关的 top-k（如 5 条），防止记忆撑爆上下文（1.5 的上下文管理）。

## 5. 架构 / 流程

```text
              ┌─────────────────────────────────┐
              │           任务（Task）           │
              └────────────────┬────────────────┘
                               ↓
   ┌─────────────  第 N 轮执行（Actor）──────────────┐
   │ 读取记忆中的经验卡 → ReAct 循环执行（2.5）→ 答案 │
   └────────────────┬────────────────────────────────┘
                    ↓
          ┌──────────────────┐
          │  评估（Evaluator）│  硬验证器优先，自评兜底
          │  通过？           │──通过──→ 输出答案，结束
          └────────┬─────────┘
                 失败 ↓
          ┌───────────────────────────┐
          │  反思（Reflector）         │  输入：轨迹 + 评估意见
          │  产出：错在哪 + 下次动作   │  禁止态度性空话
          └────────┬──────────────────┘
                   ↓
          ┌───────────────────────────┐
          │  经验卡写入长期记忆（2.4） │  跨任务可复用
          └────────┬──────────────────┘
                   ↓
        带经验进入第 N+1 轮（N < 最大轮数，否则熔断上报）
```

流程清单版：

1. 注入经验卡 → 执行任务。
2. 评估：硬验证器通过即输出。
3. 失败 → 反思器产出可执行教训。
4. 教训写入记忆，进入下一轮。
5. 轮数达到上限仍失败 → 返回最优结果并标记人工介入。

## 6. 代码 / 工具

### 6.1 Reflexion 循环实现

```python
import json
import re
from dataclasses import dataclass, field
from openai import OpenAI

client = OpenAI(api_key="YOUR_KEY")
MODEL = "gpt-4o-mini"

# ---------- 0. 记忆：经验卡（错题本） ----------
@dataclass
class EpisodicMemory:
    cards: list = field(default_factory=list)

    def add(self, task_hint: str, lesson: str) -> None:
        self.cards.append({"task_hint": task_hint, "lesson": lesson})

    def render(self, task_hint: str, k: int = 5) -> str:
        """只带最相关的 k 条经验卡，防止上下文爆炸"""
        related = [c for c in self.cards if c["task_hint"] == task_hint]
        pool = related or self.cards
        if not pool:
            return "（无历史经验，正常执行即可）"
        return "\n".join(f"- {c['lesson']}" for c in pool[-k:])

# ---------- 1. 工具（最小示例：读财报表格） ----------
TABLE_DB = {"2025": "净利润 102 亿", "2024": "净利润 118 亿"}

def read_table(row: str) -> str:
    return TABLE_DB.get(row, "未找到该行")

# ---------- 2. 执行器：带经验跑一轮 ----------
def execute(task: str, memory: EpisodicMemory, max_steps: int = 6) -> str:
    system = f"""你是财务问答 Agent。工具：read_table(row)。
执行前先看历史经验卡，严格遵守其中的教训：
{memory.render(task_hint='financial_qa')}"""
    messages = [{"role": "system", "content": system},
                {"role": "user", "content": task}]
    trajectory = []
    for _ in range(max_steps):
        resp = client.chat.completions.create(
            model=MODEL, temperature=0, messages=messages)
        msg = resp.choices[0].message
        if not msg.tool_calls:                       # 没有工具调用 = 最终答案
            return msg.content or ""
        for call in msg.tool_calls:                  # 执行工具并回传观察
            args = json.loads(call.function.arguments)
            obs = read_table(**args)
            trajectory.append(f"{call.function.name}({args}) -> {obs}")
            messages.append({"role": "tool", "tool_call_id": call.id,
                             "content": obs})
    return "（步数耗尽，本轮失败）"

# ---------- 3. 评估：硬验证器优先，自评兜底 ----------
def evaluate(task: str, answer: str) -> dict:
    if "未找到" in answer or "耗尽" in answer:
        return {"pass": False, "why": "未取到数据就作答"}
    if not re.search(r"\d", answer):
        return {"pass": False, "why": "回答中缺少具体数字"}
    judge = client.chat.completions.create(          # 自评兜底：换 Judge 口径
        model=MODEL, temperature=0,
        response_format={"type": "json_object"},
        messages=[{"role": "user", "content":
            f"问题：{task}\n回答：{answer}\n"
            '回答是否正确？只回 JSON：{"pass": bool, "why": str}'}])
    return json.loads(judge.choices[0].message.content)

# ---------- 4. 反思器：产出可执行教训 ----------
REFLECT_TMPL = """任务：{task}
失败轨迹：{trajectory}
评估意见：{why}
请反思本次失败。要求：
1. 指出失败的具体原因，引用轨迹中的关键步骤；
2. 给出下次执行可直接照做的动作（如：先调 read_table 核实再作答）；
3. 禁止态度性空话（如"下次认真点"）。
用一句话输出教训。"""

def reflect(task: str, trajectory: str, why: str) -> str:
    resp = client.chat.completions.create(
        model=MODEL, temperature=0,
        messages=[{"role": "user", "content": REFLECT_TMPL.format(
            task=task, trajectory=trajectory, why=why)}])
    return resp.choices[0].message.content

# ---------- 5. Reflexion 主循环 ----------
def reflexion(task: str, max_rounds: int = 4) -> str:
    memory = EpisodicMemory()
    answer = ""
    for round_no in range(1, max_rounds + 1):
        answer = execute(task, memory)               # 带经验执行
        verdict = evaluate(task, answer)             # 评估
        if verdict.get("pass"):
            print(f"第 {round_no} 轮通过")
            return answer
        lesson = reflect(task, answer, verdict.get("why", ""))
        print(f"第 {round_no} 轮失败：{lesson}")
        memory.add("financial_qa", lesson)           # 经验入记忆
    return answer                                    # 熔断：转人工介入
```

### 6.2 幻觉校正：存疑触发核实

```python
CLAIM_CHECK_PROMPT = """逐句检查下面的回答，输出 JSON 数组，每句一项：
{"claim": "该句内容", "source": "grounded 或 memory",
 "confidence": 0 到 1 之间}
grounded = 该句有上文资料依据；memory = 凭模型印象写出。只回 JSON。"""

def self_check(answer: str) -> list:
    resp = client.chat.completions.create(
        model=MODEL, temperature=0,
        response_format={"type": "json_object"},
        messages=[{"role": "user",
                   "content": CLAIM_CHECK_PROMPT + "\n回答：" + answer}])
    return json.loads(resp.choices[0].message.content)["claims"]

def answer_with_verification(question: str, docs: list) -> str:
    draft = generate(question, docs)                 # 第一遍正常生成
    for item in self_check(draft):                   # 第二遍自查
        if item["source"] == "memory" and item["confidence"] < 0.7:
            evidence = web_search(item["claim"])     # 存疑触发核实工具
            if not evidence:                         # 查不到：删掉，不硬写
                draft = draft.replace(
                    item["claim"], "（该数据待核实，暂不引用）")
            else:                                    # 查到：事实替换印象
                draft = draft.replace(
                    item["claim"],
                    f"{item['claim']}（来源：{evidence['url']}）")
    return draft
```

### 6.3 反思 Prompt 模板（可直接复用）

```text
角色：你是任务的复盘员，不是执行者。
输入：任务描述、本轮执行轨迹、评估意见。
输出：一条可执行的经验教训，格式为「失败原因：……；下次动作：……」。
约束：
- 原因必须指向轨迹中的具体步骤，不许归因于「运气」或「状态」；
- 动作必须是下一轮能直接照做的操作（调用什么工具、先做什么检查）；
- 禁止输出「认真一点」「再仔细些」等无操作含义的话；
- 成功的任务不进入复盘。
```

## 7. 案例

### 案例 A：财报问答的经验卡闭环

**场景**：一家金融科技公司的财报问答 Agent，用户问「2025 年净利润是多少」。

**过程**：第 1 轮模型凭参数记忆作答「120 亿」，验证器比对表格取数失败；反思产出教训「涉及具体数字，先调 read_table 核实原文再作答」；经验卡写入记忆。第 2 轮带卡执行，先调工具取到「102 亿」再回答，一次通过。

**效果**：上线经验卡机制后，同类数字类问题的首轮通过率从约 62% 升到 89%，平均调用轮次从 2.6 降到 1.3——且经验卡对所有「涉及数字」的任务持续复用。

### 案例 B：SQL Agent 的验证器反思

**场景**：数据分析 Agent 生成 SQL 查询数仓。

**做法**：每条生成的 SQL 先跑 `EXPLAIN`，语法错、缺列、越权表等信息作为观察回传；反思器把报错翻译成教训（「该库字段用 snake_case，日期字段是 dt 不是 date」），下一轮生成前注入。

**效果**：SQL 一次通过率从约 55% 升到 84%；常见报错类的经验卡沉淀一周后，几乎不再出现重复错误。

### 案例 C：行业报告的幻觉校正

**场景**：某电商的分析 Agent 自动生成行业周报，曾出现「该品类年增长 30%」这类无来源数字被用户截图质疑。

**做法**：生成后加自查环节——模型逐句标注依据来源，confidence 低于 0.7 且 source 为 memory 的事实句触发搜索核实；查不到的直接删除或标「待核实」。

**效果**：报告事实性投诉率从每周 5-6 起降到基本为零，多付的自查成本约为生成成本的 30%。

## 8. 常见坑

1. **反思写成态度检讨**。「下次认真点」对下一轮毫无指导作用。对策：Prompt 里强制「失败原因 + 可执行动作」两段式，禁止空话。
2. **无验证器、纯靠自评**。模型自评有自我偏好，倾向给自己打高分。对策：有客观判据一律用程序验证器，自评只做兜底且尽量换模型当 Judge。
3. **不设最大轮数**。反思循环可能陷入无限自我怀疑，账单和死循环一样难看。对策：熔断上限 2-7 轮，超限转人工。
4. **成功也反思**。评估已通过还再自我怀疑一轮，可能把对的改成错的，还多烧一次钱。对策：通过即输出。
5. **经验卡无限累积**。全量注入会撑爆上下文，旧经验还会和新任务无关。对策：按任务画像检索 top-k（约 5 条）注入。
6. **经验不区分任务类型**。把「写代码」的教训注入「写周报」的任务会负迁移。对策：经验卡带任务画像标签，注入前做相关性过滤。
7. **反思时只看最终答案**。不看轨迹找不到真错因（可能是第二步工具就用错了）。对策：把完整轨迹喂给反思器。
8. **验证器本身有 bug**。错误信号会让反思越修越歪。对策：验证器单独测试、有金标回归集。
9. **存疑不加核实**。自查发现「凭印象写的」却只在措辞上加「大概」。对策：必须触发核实工具拿事实，查不到就删。
10. **经验卡不持久化**。只存在会话内存里，换个会话重新踩坑。对策：写入长期记忆（向量库或 KV 存储），按 2.4 的机制检索。
11. **反思与执行用同一模型同一温度**。相关性错误让它坚持原答案。对策：反思用不同模型或更低温度。
12. **反思收益不进评估集**。加了反思却说不清有没有用。对策：在 2.9 的评估体系里对比开关反思的成功率与成本。
13. **把瞬时故障也送去反思**。限流、超时这类硬失败该走 2.3 的重试，反思只会产出「网络不好」这种无用教训。对策：按错误类型路由，硬失败重试、软失败反思。

## 9. 练习

1. 给 2.5 写的 ReAct Agent 加上 Reflexion 循环：验证器 + 反思器 + 经验卡记忆，跑通「失败一次、第二次通过」。
2. 做对照实验：同一任务分别用「简单重试」和「Reflexion」跑 20 次，统计平均成功轮数与 token 消耗。
3. 为 SQL 生成任务写一个硬验证器（语法检查 + 表字段白名单），对比它和 LLM 自评的误判率。
4. 实现幻觉校正：让模型对自己的草稿逐句标注 source 与 confidence，对存疑句触发搜索核实，观察改动前后的事实准确率。
5. 把经验卡持久化到向量库，按任务画像检索注入，验证经验跨会话复用。
6. 把最大轮数从 2 调到 8，画出「成功率-成本」曲线，找出收益拐点。
7. 用更强的模型当反思器（执行用 mini、反思用旗舰），对比反思质量差异。
8. 构造一个「反思帮倒忙」的用例：让成功结果再被反思一轮，观察是否被改错，并写出防止它的代码条件。

## 10. 小结

- 反思 = **执行 → 评估 → 反思 → 经验入记忆 → 带经验重执行**，闭环在记忆模块上。
- 与简单重试的本质区别：**重试原样再掷骰子；反思把教训语言化沉淀，喂给下一轮**。
- 发现错误靠验证器：**硬验证器优先（规则/工具反馈），自评只兜底且换模型当 Judge**。
- 反思产物必须是**可执行教训**：失败原因 + 下次动作，禁止态度性空话。
- 幻觉校正：**自查发现存疑事实，触发核实工具拿事实替换印象**，查不到就不写。
- Self-RAG/CRAG 把同一思想搬到检索侧：检索→自评→修正的循环。
- 成本边界：**最大轮数熔断（2-7 轮）、成功不反思、经验卡限量注入**。
- 硬失败（超时/限流）走重试，软失败（答错/跑偏）走反思——先分流再处理。
- 经验卡要**跨任务复用且持久化**：失败一次，全线受益。
- 反思效果必须进评估集量化（2.9），否则说不清它值不值这份 token。
