# 文档阅读页 · 深度讲解文档写作规范（子 Agent 必读）

目标：为每个锚点写一篇教科书级的 Markdown 深度讲解，供学习者在「文档阅读」页快速、系统地查阅。**纯知识文档：无游戏化、无引导话术、无例题**。

## 范文（必须先完整读一遍）

`data/docs/1-4.md` —— 结构、深度、口吻的唯一基准。你的产出必须与之同级。

## 固定结构（10 节，标题按此编号）

```markdown
# 讲解 <锚点号> <锚点名>

> 说明：<用 1-2 句交代本篇与前后锚点的衔接（前置是什么、后续在哪展开）>

---

## 1. 定位
## 2. 一句话定义
## 3. 为什么需要
## 4. 核心原理        （可分 4.1 / 4.2 … 小节，鼓励表格与 text 代码块）
## 5. 架构 / 流程      （至少一个 text 画的结构/流程图或清单式流程）
## 6. 代码 / 工具      （≥2 段可运行风格的代码或模板/配置/清单，按锚点性质选语言）
## 7. 案例            （2-3 个，含场景与效果/数字）
## 8. 常见坑           （8-14 条，编号列表，每条一句现象+一句对策）
## 9. 练习            （6-8 条动手练习）
## 10. 小结           （8-12 条要点 bullets）
```

## 硬性要求

1. **篇幅**：正文（不含代码）≥ 250 行 Markdown；总字符 ≥ 6000。宁深勿浅。
2. **表格**：全文 ≥ 3 个（对比表/参数表/指标表/失败模式表等）。
3. **代码块**：≥ 2 个（Python/JSON/YAML/bash/text 均可；非代码锚点可用 Prompt 模板、配置、清单的 fenced 块替代，但 `## 5` 的 text 图必配）。
4. **忠实**：技术事实以公认资料与本站 data/content/*.json、research/*.md 的既有口径为准；**禁止编造面试来源与论文编号**；可以陈述业界共识但不引用具体面经原题。
5. **衔接**：开头 `> 说明` 与「1. 定位」中用锚点号（如 2.5、3.2）指明前后依赖，与本站大纲一致（见 data/syllabus.js 中该锚点的 deps 与相关锚点名）。
6. **口吻**：直接、密度高、面向面试与工程实战；不用「我们可以」「接下来让我们」等水话；不用 emoji。
7. **首行标题**：`# 讲解 <锚点号> <锚点名>`，锚点名与 data/syllabus.js 中 modules 的 name 一致。
8. **中文**，术语首次出现给英文。
9. 第 7 节案例中的数字是**示意性量级**（如「准确率 60%→85%」），须写得像真实工程复盘，但不要虚构具体公司真名（可用「某电商」「一家金融科技公司」）。
10. 文件保存为 `data/docs/<文件名>.md`，文件名由派发方指定；UTF-8，LF。
