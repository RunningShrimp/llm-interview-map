## 1. 定位

基础热身关（S0）的核心锚点，回答本模块的关键问题：**能力、幻觉、上下文窗口从哪来？**

一切应用层工程的地基。不理解"接龙"这个本质，后面每个环节都会误判：把模型当数据库会踩幻觉，把随机性当 bug 会瞎调参，把窗口当均匀记忆会丢关键信息。

依赖与去向：

- 前置：0.4（NLP 与 Transformer）——接龙的每一次"看懂上文"都由注意力完成。
- 站内专卡：0.5b（预训练与 SFT）、0.5c（RLHF 与 DPO）、0.5d（幻觉机理），本篇将其串成一条线。
- 后续：0.6（提示工程——用上下文引导接龙）、1.1（模型选型）、1.1b/1.1c（温度与采样的实操与数学）、1.5（上下文管理实操）、1.7b（幻觉治理的分层防御）。

## 2. 一句话定义

LLM（Large Language Model，大语言模型）是一个在海量文本上用"预测下一个 token"这一个目标训练出的超级接龙机器：给它前文，它输出下一个 token 的概率分布，采样一个、拼回去、再预测——接得又长又合理，就涌现出对话、翻译、写代码等能力。

## 3. 为什么需要

应用工程师必须先建立正确的心智模型，否则每个环节都在误用：

| 错误心智模型 | 导致的误用 | 正确认知 |
|---|---|---|
| 模型是数据库，存着答案 | 直接问事实，被幻觉打脸 | 模型学的是语言规律，不是答案库 |
| 随机输出是 bug | 反复重试"碰运气" | 采样机制本就有意随机，参数可控 |
| 窗口内一视同仁 | 关键信息埋中间被忽略 | 注意力呈头尾强、中间弱的 U 型 |
| 会说 = 会做 | 把流畅当正确 | 下一词预测优化"似真"，不是"为真" |
| 训练 = 全知 | 期待它知道训练后的事 | 知识有截止日期，新知识要外挂 |

LLM 的能力与局限是同一个来源——训练目标。理解这一点，能力、幻觉、窗口、采样四个主题就有了统一的解释框架。

## 4. 核心原理

### 4.1 下一词预测：唯一的训练任务

预训练目标只有一句话：给定前文，最大化下一个 token 的概率。

```text
输入：白日依山尽，黄河入海
目标：预测"流" —— P(流 | 白日依山尽，黄河入海)
```

这是自监督（Self-supervised）任务：任何文本天然自带标签（下一个词就是标签），不需要人工标注，所以数据能堆到万亿 token 级。模型要预测得准，就必须学会语法、常识、事实、甚至推理——因为猜对"因此他摔倒了"的下一个词，需要理解因果。**规模 + 数据 + 简单目标，共同催生涌现能力（Emergent Abilities）**：上下文学习、指令泛化、多步推理，这些能力没有被显式教过，是规模化后的副产品。面试口径上，"涌现"是业界主流框架，学术圈对其是否只是度量假象仍有争论——答题时用主流框架即可，能主动提一句争议是加分项。

### 4.2 预训练：从文本到世界知识

预训练（Pre-training）阶段的关键事实（0.5b 详述）：

- 数据：海量互联网文本，去重与质量过滤比堆量更关键；数据里的偏见与错误会被一并学走。语料配比（代码、数学、多语言、教科书的占比）直接决定下游能力的知识面——代码语料甚至被普遍认为能带动推理能力。
- 成本：千卡集群 × 数月，千万美元级——应用岗几乎不做预训练。
- 产物：一个"会说话"的基座模型（Base Model），知识丰富但只会续写，不听指令。

知识截止（Knowledge Cutoff）从这里来：训练数据定格在某天，之后的世界它没见过。

### 4.3 SFT：从会说话到会干活

SFT（Supervised Fine-Tuning，监督微调）用几万到百万条人工构造的"指令-回答"对继续训练，教会模型"接到指令该输出什么形态"。这是"会说话 → 会做事"的关键一跃（0.5b 详述）。

要点速记：

- 自监督换监督信号：数据形态从"任意文本"变成"指令对"。
- 质量与多样性大于数量；全用领域数据会灾难性遗忘（通用能力被覆盖），常混 30%-70% 通用数据。
- LoRA 等参数高效微调只训小附件，消费级卡也能做。
- 与提示工程划一条成本边界：能靠 few-shot 示例稳定解决的行为（格式、风格、流程），先改提示再考虑微调——成本按"提示 < RAG < LoRA < 全量 SFT"递增，行为改变需求越深，手段越往后选。

### 4.4 对齐一览：RLHF 与 DPO（全景版）

SFT 教了"怎么答"，没教"哪种答更得体"——同一问题有多种可接受的答法，"得体、安全、有分寸"很难写成唯一标准答案。对齐（Alignment）把人类的相对判断变成训练信号（0.5c 详述）：

| 阶段 | 做法 | 核心组件 | 特点 |
|---|---|---|---|
| RLHF-PPO | 人类对多回答排序 → 训练奖励模型 → 模型照分数在线优化 | 4 个模型协同 + KL 惩罚 | 上限高、工程贵、可能 reward hacking |
| DPO | 直接用"好答案 > 坏答案"偏好对离线优化 | 2 个模型，免奖励模型 | 简单稳定、成本低，上限取决于数据 |
| GRPO | 同题采样一组答案，以组内相对优劣当奖励 | 砍掉价值网络 | 推理模型（H1/H2）的对齐引擎 |

两个必须知道的概念：**KL 惩罚**约束模型不偏离原语言能力太远；**reward hacking**指模型学会讨好打分器（堆长度、堆客套话）而非真的变好。本篇记住定位即可：**SFT 教模仿，对齐教分寸。** 三条路线的关系一句话：都在把偏好或奖励信号变成策略更新，区别只在信号从哪来、要协同几个模型。

### 4.5 上下文窗口与 lost in the middle

上下文窗口（Context Window）是模型一次能处理的 token 上限："128K"指 128K 个 token，中文约 6~10 万字。窗口决定"一次性能看到多少"，但不决定"每个位置都被用好"。

Lost in the middle 现象（Liu et al., TACL 2024；站内 1-5 锚点的实验依据）：把关键信息放在长上下文的不同位置测试，模型对**开头和结尾**的信息利用率高，对**中段**明显下降，注意力呈 U 型。

工程对策（1.5 实操展开）：

| 位置 | 适合放什么 | 原因 |
|---|---|---|
| 开头 | 系统指令、任务定义、最关键的约束 | 首位注意力最强，且决定接龙基调 |
| 结尾 | 当前问题、待处理的原文、引用资料 | 近因效应强，靠近生成位置 |
| 中段 | 次要参考资料、历史摘要 | U 型谷底，避免放必须逐字命中的信息 |
| 窗口外 | 历史压缩、外部知识库（RAG） | 根本放不下或不必全量在场 |

窗口外的信息有三个去向，对应三篇后文：压缩成摘要留在窗口内（1.5 上下文管理）、存进外部知识库按需检索（1.4 RAG）、或在 Agent 里交给记忆系统调度（2.4 记忆）。选择依据是信息的复用频率与新鲜度：高频短期用压缩，低频长期用检索。

另一条暗线：窗口越长，注意力的计算与显存代价越高（0.4 的 O(n²)），长窗口不是免费的。

### 4.6 温度与采样

模型每步输出的是整个词表上的概率分布（logits 经 Softmax）。采样策略决定"接哪条路"：

```text
logits [2.0, 1.5, 0.8, 0.1]
  │ × (1/temperature)          ← 温度缩放
  ▼ softmax
概率分布 → 排序截断（top_k / top_p）→ 按概率抽一个 token
```

- **Temperature（温度）**：T 趋近 0 时分布尖锐化，趋近贪心（每步取最大概率，输出确定）；T 升高时分布拉平，低概率词更容易被抽中，输出多样。温度不改模型，只改"从分布里怎么抽"。
- **top_k**：只保留概率前 k 个候选。**top_p（核采样）**：保留累积概率达 p 的最小候选集。两者都在砍掉长尾噪声（1.1b/1.1c 展开机制与经验值）。
- 一个工程细节：`temperature=0` 并不保证 100% 复现——浮点非结合性、批处理与路由的不确定性可能造成极小概率的输出差异。要严格复现得靠 `seed`（部分 API 支持）加确定性推理配置，而非只靠温度归零。

任务-参数经验对照：

| 任务类型 | temperature | top_p | 理由 |
|---|---|---|---|
| 抽取、分类、SQL 生成 | 0~0.3 | 1.0（或不截断） | 要确定性与格式稳定 |
| 客服问答、摘要 | 0.2~0.5 | 0.9 | 稳定优先，留一点自然度 |
| 文案、故事创作 | 0.7~1.0 | 0.9~0.95 | 需要多样性 |
| 头脑风暴 | 1.0+ | 0.95 | 鼓励发散，接受多次重试 |

档位不是教条：换模型、换任务形态都要重测。把 6.3 的双温实验纳入新场景的验收清单，比背经验值可靠。

### 4.7 幻觉机理：训练目标决定的宿命

幻觉（Hallucination）指模型一本正经地输出虚假内容。根源不是参数不够大，而是**训练目标只优化"似真"，不校验"为真"**（0.5d 详述）：

```text
下一词预测的目标 = 说得连贯、像样
知识空白处的解法 = 按"最像答案的文本"补全，不会留白
RLHF 的副作用   = 奖励自信流利的回答，加剧不懂装懂
```

成因分三层，对策也按层给：

| 层次 | 成因 | 缓解手段 |
|---|---|---|
| 机制层 | 优化似真非为真，无内建真值校验 | 接受幻觉不可根除，工程上纵深防御 |
| 数据层 | 训练错误/过时信息、知识截止、长尾知识稀薄 | RAG 外挂新知识与私域知识（1.4） |
| 采样层 | 高温抽到低概率词链；参数不当 | 关键事实任务用低温 + top_p 收紧 |
| 对齐层 | 奖励自信流利，惩罚"我不知道" | 提示允许说不知道；校准类评估 |

三板斧按时间轴排：**事前** RAG 供真实资料；**事中**提示约束（仅依据资料、不知则说不知、要求标注引用）；**事后**引用溯源核查、多次采样一致性比对。细节在 1.7b 的分层防御体系展开。

一句话收束：幻觉治理不追求根除，追求**可控、可溯源、可兜底**——工程目标从"让模型不说错"换成"让说错的内容进不来、留不下、传不出去"。

## 5. 架构 / 流程

LLM 从训练到推理的全景流水线：

```text
┌──────────────────────────────────────────────────────┐
│ 训练侧：三段成长                                        │
│                                                      │
│   预训练              SFT                对齐           │
│   万亿 token 网络文本   指令-回答对         人类偏好        │
│   任务：下一词预测  →   教会按指令干活  →   教会分寸        │
│   千卡×数月            几卡×几天           几卡~几十卡     │
│   产物：会说话的基座     产物：会做事        产物：答得得体  │
│        （Base Model）    （Instruct 模型）  （对齐模型）    │
└──────────────────────────────────────────────────────┘
                        ↓ 部署为推理服务（3.6）
┌──────────────────────────────────────────────────────┐
│ 推理侧：接龙循环                                        │
│                                                      │
│   prompt ──token 化──> Transformer 前向               │
│      → 下一 token 的概率分布                           │
│      → 温度缩放 + top_p/top_k 截断                     │
│      → 采样一个 token，拼回输入                         │
│      → 重复，直到 EOS 或 max_tokens                    │
│                                                      │
│   全程只看窗口内的 token：                              │
│   窗口 = 计量上限；窗口内头尾强中间弱（lost in middle）  │
└──────────────────────────────────────────────────────┘
```

两条主线合一：训练侧决定了模型"是什么"（接龙 + 会干活 + 有分寸），推理侧决定模型"怎么答"（分布 + 采样 + 窗口约束）。所有应用层技巧——提示工程、RAG、温度调参——都是在这两个侧面上做文章。

## 6. 代码 / 工具

### 6.1 token 计数与成本估算

```python
# pip install tiktoken
import tiktoken

enc = tiktoken.get_encoding("cl100k_base")
texts = [
    "Transformer 是大模型的身体。",
    "Transformer is the body of large language models.",
]

for t in texts:
    n = len(enc.encode(t))
    print(f"{n:3d} tokens | {t}")

# 工程意义：计费双程 + 窗口预算（单价为示意量级）
PRICE_IN, PRICE_OUT = 0.5, 1.5            # 美元 / 百万 token（示意）
in_tokens, out_tokens = 12000, 3000       # 一次调用的输入/输出
cost = in_tokens / 1e6 * PRICE_IN + out_tokens / 1e6 * PRICE_OUT
print(f"本次调用成本 ≈ ${cost:.6f}")
print(f"128K 窗口余量检查: {'OK' if in_tokens + out_tokens < 128_000 else '超窗'}")
```

### 6.2 温度采样的数值对比

```python
import numpy as np

def softmax_with_temperature(logits, temperature=1.0):
    logits = np.asarray(logits, dtype=float) / max(temperature, 1e-6)
    logits -= logits.max()                 # 数值稳定
    e = np.exp(logits)
    return e / e.sum()

logits = [2.0, 1.5, 0.8, 0.1]              # 4 个候选 token 的原始分数
words = ["A", "B", "C", "D"]

print(f"{'温度':>6}  " + "  ".join(f"P({w})" for w in words))
for t in [0.2, 0.7, 1.0, 1.5]:
    p = softmax_with_temperature(logits, t)
    print(f"T={t:<4}  " + "  ".join(f"{x:.3f} " for x in p))

# 输出示意：低温尖锐（几乎必选 A），高温拉平（四选一趋于均匀）
# T=0.2   0.969  0.030  0.001  0.000
# T=1.5   0.381  0.296  0.197  0.126
```

低温不是"不随机"而是"几乎确定"；高温下原本的第二名、第三名开始频繁胜出——这就是同一问题两次回答不一样的来源。

### 6.3 同题双温对比实验

```python
from openai import OpenAI
client = OpenAI(api_key="YOUR_KEY")

def run(question: str, temperature: float, n: int = 5) -> set:
    outs = set()
    for _ in range(n):
        r = client.chat.completions.create(
            model="gpt-4o-mini",
            messages=[{"role": "user", "content": question}],
            temperature=temperature,
        )
        outs.add(r.choices[0].message.content.strip())
    return outs

q = "用 3 个要点总结：退货需在签收后 7 天内申请，退款 3-5 个工作日到账。"
for t in (0.0, 1.0):
    outs = run(q, t)
    print(f"temperature={t}: 5 次生成中 {len(outs)} 种不同结果")
```

预期观察：T=0 时 5 次输出高度一致；T=1 时措辞、要点数量开始漂移。事实类摘要任务应锁低温，这条实验结论直接支撑 4.6 的参数对照表。

## 7. 案例

### 案例 A：客服机器人的幻觉事故与修复

**场景**：某电商客服机器人上线两周，用户投诉集中在一类：模型编造退货政策细节（如"90 天内可退"——真实政策是 7 天）。统计显示约 12% 的回答含事实性错误。

**修复**：三层组合拳——接入商品与售后知识库做 RAG；提示词强约束"仅依据资料回答，资料中没有就说不知道"，并要求标注引用编号；事实类回答温度从 0.8 降到 0.2。两周后抽检幻觉率降到约 2%。

**复盘要点**：不是换更大的模型，而是承认"开放域闭卷答题"这个模式本身有缺陷，把它改成"开卷答题"。另一个教训：修复后要把这批 bad case 回流进知识库与评测集——同类问题换个问法还会再来一遍，没有回归集就拦不住复发。

### 案例 B：账单爆炸的 token 排查

**场景**：某 SaaS 的 AI 助手月账单超预算 3 倍，功能没变。

**排查**：按 token 三步走——看账单里输入/输出占比，输入占 85%；检查会话构造，发现每轮把全部历史原文反复塞入（第 30 轮时输入已达 2 万 token）；再查系统提示 3000 token 且未用前缀缓存。

**修复**：历史改为"近期原文 + 远期摘要"，系统提示启用前缀缓存，输出设 max_tokens 上限。账单回到预算内。**根因不是模型贵，是没做 token 意识的上下文管理。**

### 案例 C：摘要任务的温度调参

**场景**：某资讯 App 的摘要功能被投诉"有时 3 条要点有时 5 条，有时夹带主观评价"。

**修复**：金标集 100 篇文章（人工标 3 条式标准摘要），测试 T=0.9 与 T=0.2 两档，配合五件套提示词固定格式。

**效果**：条数达标率从 68% 提升到 97%，主观评价出现率从 15% 降到 1%。结论：**创作任务才配高温，交付格式要稳定的任务一律低温。**

## 8. 常见坑

1. **把模型当数据库**。直接问事实不供资料，幻觉率最高的用法；事实类问题一律配 RAG 或工具查证。
2. **把随机输出当 bug**。反复手动重试不如把温度锁到任务匹配的档位（对照 4.6 表）。
3. **事实类任务用高温**。T=0.8 以上做抽取、分类，格式与事实都漂移；交付类任务 T≤0.3。
4. **把窗口当均匀记忆**。关键信息埋中段会被"lost in the middle"吃掉；放头尾。
5. **历史无限累积**。每轮全量塞入历史，输入成本线性甚至指数膨胀；做压缩与滑动窗口。
6. **以为指令微调模型会自动拒答不知道的事**。对齐降低了幻觉率但没根除；必须提示约束 + 事后校验。
7. **混淆 Base 模型与 Instruct 模型**。拿基座模型做对话，只会续写不会回答；选对齐过的对话模型。
8. **温度当玄学调参**。每次乱调，效果不可复现；任务定型后参数进配置并写明理由。
9. **认为大模型幻觉会被规模根治**。更大的模型幻觉更少但不会消失；防御靠工程而非参数量。
10. **把 SFT 想成万能**。缺知识靠微调查不动（知识在预训练里），微调补的是行为与格式；知识问题选 RAG。
11. **忽视知识截止日期**。时效性问题直接问模型必错；先问"这个事实在训练截止之后吗"。
12. **对齐训练忽视 reward hacking**。模型学会堆长度堆客套话，评测分数涨了、真实质量没涨；要人工抽检兜底。
13. **忽视 max_tokens 静默截断**。长输出被砍半，下游 JSON 解析失败还以为模型抽风；检查 finish_reason 并做截断兜底。
14. **同一组参数打天下**。抽取、问答、创作共用一套温度和 top_p；按任务分档写进配置，每档注明选择理由。

## 10. 小结

- LLM 的本质是**下一词预测**：自监督、无需标注，规模 + 数据催生涌现能力。
- 训练三段：**预训练**（万亿 token，学语言与知识，千万美元级）→ **SFT**（指令对，学会干活）→ **对齐**（RLHF/DPO，学会分寸）。
- 对齐两路线：**PPO 在线闭环**（奖励模型 + KL 惩罚，能力强工程贵）vs **DPO 离线直优**（免奖励模型，简单稳定）；GRPO 是推理模型的新引擎。
- **上下文窗口**按 token 计量，中文 128K 约合 6~10 万字；窗口内注意力 U 型，关键信息放头尾。
- **温度**缩放分布：低温确定、高温多样；top_k/top_p 砍长尾；事实类任务低温，创作类任务高温。
- **幻觉的根源是训练目标**：优化似真非为真，知识空白处按风格补全——规模能缓解，不能根除。
- 幻觉防御三板斧按时间轴：**事前 RAG、事中提示约束、事后溯源校验**。
- 同一问题两次回答不同不是 bug，是采样机制的刻意随机，参数可锁。
- 应用工程师的价值在于：用窗口管理、采样参数、RAG 与提示工程，把"会接龙的模型"驯成"可靠的交付工具"。
- 记住一句话收束全篇：**能力来自预训练，行为来自 SFT 与对齐，输出形态来自采样，可靠性来自工程。**
- 行为改造的成本阶梯先记牢：提示 < RAG < LoRA < 全量 SFT——越靠前越便宜，按"要改变多深"选手段。
- 这些机制直接支撑后续：0.6 提示工程、1.1 选型与采样实操、1.5 上下文管理、1.7b 幻觉治理、1.4 RAG。
