## 2. 一句话定义

Transformer 是一种完全基于注意力机制（Attention）的序列建模架构：每个 token 通过查询-键-值（QKV）机制环顾全句、按相关度吸收信息，配合位置编码补回词序，经几十层"注意力 + 前馈网络"反复加工，把字面序列加工成语义表示——它是大语言模型的身体。

## 3. 为什么需要

在 Transformer 之前，NLP（Natural Language Processing，自然语言处理）的主流是循环神经网络 RNN（Recurrent Neural Network）及其改进版 LSTM。它们按时间步逐词处理序列，有两个结构性缺陷：

1. **无法并行**：第 t 个词的计算依赖第 t-1 个词的结果，只能排队算。GPU 的并行能力用不上，训练语料堆不上规模。
2. **长程依赖衰减**：信息像接力棒一样逐词传递，传到句尾早忘了句首。LSTM 的门控机制只是缓解，没有根治。

Transformer（2017 年提出，业界共识）换了一条路线：不逐词传递信息，而是让每个词直接和序列里所有词建立连接。对比一目了然：

| 维度 | RNN | LSTM | Transformer |
|---|---|---|---|
| 计算方式 | 逐词顺序 | 逐词顺序 | 全序列并行 |
| 长程依赖 | 严重衰减 | 门控缓解 | 任意两词一步直达 |
| 训练速度 | 慢 | 慢 | 快（可吃海量数据） |
| 序列内交互 | O(n) 步传递 | O(n) 步传递 | 一步 O(n²) 两两打分 |
| 可扩展性 | 差 | 差 | 极强（规模定律的前提） |
| 词序感知 | 天然有序 | 天然有序 | 无序，需位置编码补 |

最后一条是关键取舍：并行带来了规模，也丢掉了天然词序，所以必须发明位置编码——这是理解 4.4 的伏笔。

还有一层常被忽略：**这套架构的可扩展性（Scalability）是深度学习里罕见的干净信号**——不改变结构，只堆层数、堆数据、堆算力，能力就持续上涨。规模定律能成立，前提就是注意力这种"结构恒定、计算随规模平滑增长"的设计。RNN 时代堆数据会先撞上训练效率的天花板，Transformer 把这道墙拆了。

## 4. 核心原理

### 4.1 分词与 token：模型的输入单位

模型不认识汉字或单词，只认识 token（词块）。文本先经分词器（Tokenizer）切成 token 序列，每个 token 映射为词表里的整数编号，再查嵌入矩阵变成向量。

三种切分粒度的演进：

| 粒度 | 思路 | 问题 | 代表 |
|---|---|---|---|
| 词级 | 每个单词一个编号 | 词表爆炸；未见词（OOV）无法处理 | 早期 NMT |
| 字符级 | 每个字符一个编号 | 无 OOV，但序列过长，注意力 O(n²) 代价高 | 早期字符模型 |
| 子词级 | 高频串整块、低频串再切 | 平衡词表大小与序列长度，现代主流 | BPE / WordPiece / SentencePiece |

主流方案 BPE（Byte Pair Encoding，字节对编码）的思路是"高频合并"：

1. 把语料拆到最细单位（GPT 系用字节，byte-level BPE，天然无 OOV）。
2. 统计所有相邻单位对的频次，把最高频的一对合并成一个新单位。
3. 重复第 2 步，直到词表达到目标规模（现代 LLM 约 10 万量级）。

结果：常见词是整块（"的""the""模型"），生僻词拆成几块。工程影响（站内 0.4b 的口径）：

- token 是 API 计费单位与上下文窗口的计量单位，输入输出双程计费，输出更贵。
- 各家词表不同，同一段话 token 数不同。中文约 1 字对应 0.6~1 个 token；"128K 窗口"指 128K 个 token，中文约 6~10 万字。
- 切分陷阱：数字被切碎导致数数与算术不准，根源都在切分方式。

### 4.2 Self-Attention：QKV 与 √dk 缩放

Self-Attention（自注意力）让每个词发三种角色：

- **Query（Q，查询）**：我想找什么信息。
- **Key（K，键）**：我有什么特征标签。
- **Value（V，值）**：我真正携带的内容。

同一个词向量 x 分别乘三个权重矩阵 W_Q、W_K、W_V 得到 Q、K、V。计算四步：

1. **投影**：X 乘三个矩阵，得到 Q、K、V。
2. **打分**：目标词的 Q 与所有词的 K 做点积，得到原始相似度。
3. **缩放**：分数除以 √d_k。
4. **归一聚合**：Softmax 把分数变成和为 1 的权重，再对 V 加权求和。

完整公式：

```text
Attention(Q, K, V) = softmax(QKᵀ / √d_k) · V
```

为什么除以 √d_k：点积的方差随维度 d_k 增大而增大，维度越高分数越极端；过大的分数会把 Softmax 推进饱和区，输出接近 one-hot，梯度趋近 0，深层网络训不动。除以 √d_k 恰好把分数方差拉回约 1。注意因果链是"Softmax 饱和 → 梯度消失"，不是"防止数值溢出"。

两种掩码（mask）：

- **Padding mask**：批量输入长短不一时，挡住补齐位置不参与打分。
- **Causal mask（因果掩码）**：解码生成时挡住未来词，保证第 i 个 token 只能看到前 i 个，生成不偷看答案。

Self 与 Cross 的本质区别在 QKV 是否同源：Self-Attention 三者来自同一序列；Cross-Attention 只有 Q 来自解码端，K/V 来自另一个序列（编码器输出或多模态特征）——它是信息从一个序列流入另一个序列的桥梁。

### 4.3 多头注意力

单次注意力只能学一种"关注模式"。多头注意力（Multi-Head Attention）把 d_model 维拆成 h 份，每份 d_k = d_model / h，并行做 h 次独立注意力，各头有自己的 W_Q/W_K/W_V，输出拼接后乘 W_O 混合：

```text
MultiHead(Q,K,V) = Concat(head_1, ..., head_h) · W_O
head_i = Attention(Q·W_Q^i, K·W_K^i, V·W_V^i)
```

- 不同头自发分工：有的头盯句法搭配，有的头管指代消解，有的头只看相邻词——模型同时从多个表示子空间提取关系。
- 计算成本与单头近似：头多了，每头的维度小了，总计算量基本不变。原论文典型配置 d_model=512、h=8、每头 64 维。
- 顺带打通 4.6 的一处伏笔：MQA/GQA/MLA 的"KV 头共享"就是在多头结构上做减法——让多个查询头共用同一组 KV 头，减法发生在头的数量上，注意力公式本身没变。

### 4.4 位置编码与 RoPE

注意力对集合而非序列计算——打乱输入顺序，注意力输出不变（置换等变）。没有位置信息，"猫追狗"和"狗追猫"在模型眼里是同一句话。位置编码（Positional Encoding，PE）是唯一注入词序的通道。

三代方案的演进：

| 方案 | 机制 | 参数 | 相对位置 | 长度扩展 | 代表 |
|---|---|---|---|---|---|
| 正弦 PE | 不同频率的 sin/cos 生成固定编码，加到词向量上 | 无参数 | 任意偏移可线性表达 | 理论无限，实际外推弱 | 原论文 |
| 可学习 PE | 位置向量当可训练参数，加到词向量上 | 每位置一个向量 | 弱 | 训练时写死上限 | BERT、GPT-2 |
| RoPE | 对 Q/K 按位置做旋转，内积只依赖相对位置 | 无参数 | 天然携带 | 配合外推技术可扩展 | LLaMA、Qwen、DeepSeek |
| ALiBi | 给注意力分数加随距离线性衰减的偏置 | 无参数 | 天然携带 | 外推较好 | 部分模型采用 |

RoPE（Rotary Position Embedding，旋转位置编码）成为主流的原因：把每个位置的向量想象成按角度旋转的指针，位置 m 转 m 格；两个词做注意力时，两根指针的夹角正好等于距离 m−n——绝对位置编码进旋转，内积天然表达相对位置。注意它只旋转 Q 和 K，不动 V。配合长度外推技术（Position Interpolation 位置插值、NTK-aware 缩放、YaRN 分层缩放），训练 8K 的模型可扩展到数十 K 上下文。

### 4.5 三种架构拼法

同一个 Transformer 模块，三种拼法对应三种用法：

| 架构 | 注意力方向 | 训练目标 | 擅长任务 | 代表 | 主要短板 |
|---|---|---|---|---|---|
| Encoder-only | 双向（每个词看全句） | 掩码语言建模 MLM：挖空猜词 | 理解类：分类、NER、句子/文档嵌入 | BERT、各类嵌入模型 | 不擅长自由生成 |
| Decoder-only | 单向因果（只看前文） | 下一词预测 | 生成类：对话、写作、代码、通用 LLM | GPT、LLaMA、Qwen | 无双向编码表示 |
| Encoder-Decoder | 编码双向 + 解码因果 + Cross-Attention | 序列到序列映射 | 输入输出都是序列且差异大的任务：翻译、摘要 | T5、BART | 结构最重，推理链路长 |

为什么当代主流 LLM 几乎都是 Decoder-only（1.1 展开）：训练目标（下一词预测）与应用形态（生成）天然一致；结构简单、scaling 效率高；推理时 KV Cache 友好。而 Encoder-only 并没有过时——0.7 的嵌入检索（RAG 的召回层）正是它的主场；Enc-Dec 在翻译、结构化改写类任务上仍有优势。

### 4.6 长上下文与注意力优化概述

注意力两两打分，计算量与显存都随序列长度 n 平方增长（O(n²)），这是"LLM 为什么能处理长上下文、又为什么处理不便宜"的同一枚硬币。优化路线按层次分四类：

| 层次 | 方法 | 思路 | 代价/取舍 |
|---|---|---|---|
| 注意力结构 | 滑动窗口注意力、稀疏注意力 | 每个 token 只看局部窗口或选中的关键位置 | 长程信息靠层层传递，全局视野受限 |
| 注意力近似 | 线性注意力、低秩近似 | 把 O(n²) 改写成 O(n) 形式 | 近似有精度损失 |
| 系统与显存 | FlashAttention | 不改数学，优化访存：分块计算减少 HBM 读写，精确注意力更快更省 | 实现复杂，需硬件适配 |
| KV 压缩 | MQA / GQA / MLA | 多个查询头共享少量 KV 头，压 KV Cache 显存 | 极轻的容量损失 |
| 位置外推 | PI / NTK-aware / YaRN | 压缩或分层缩放位置坐标，让短训练模型用长序列 | 通常需少量微调 |

推理侧还有一条主线：KV Cache——缓存历史 token 的 K/V 避免每步重算，这是 3.7b 的专卡内容。工程上的另一条路是绕开：超长文档不走"全塞上下文"，而走切片检索（RAG，1.4 篇）——1.4d 专门对比三者选型。本篇只需记住地图：**结构近似换长度、系统优化换速度、KV 压置换显存、外推换窗口、RAG 换成本。**

## 5. 架构 / 流程

一个 Decoder-only Transformer（主流 LLM 的形态）处理一次输入的完整数据流：

```text
输入 token 序列 [BOS, 猫, 追, 老鼠, ...]
        │
        ▼
┌────────────────────────────────┐
│ Token Embedding 查表变向量       │  ← 0.4.1 分词的产物在这里进场
└────────────────────────────────┘
        │  + RoPE 旋转注入位置信息（只作用 Q/K）
        ▼
┌────────────────────────────────┐
│ Transformer Block × N 层        │  ← 如 32 层，每层两道工序
│                                │
│  ① 多头自注意力（带因果掩码）     │     词与词交换信息：
│     QKV 投影 → 点积打分          │     谁该关注谁
│     → ÷√d_k 缩放 → Softmax      │     → 按权重加权 V
│     → 残差 + RMSNorm            │     安全绳 + 稳定器
│                                │
│  ② 前馈网络 FFN（逐词深加工）     │     参数大头，知识存储的主力
│     → 残差 + RMSNorm            │
└────────────────────────────────┘
        │  N 层后，最后一个位置的向量
        ▼
┌────────────────────────────────┐
│ 输出层：Linear → Softmax         │  → 词表上每个 token 的概率分布
└────────────────────────────────┘
        │  采样出一个 token，拼回输入
        ▼
   重复上一步 → 逐 token 接龙生成（3.7 讲代价）
```

一句话概括流水线：**分词进场 → 逐层"交换信息（注意力）+ 深加工（FFN）"→ 输出下一 token 分布 → 接龙循环**。残差连接保证信息不丢，归一化保证数值稳定，位置编码补回词序——三件套让几十层的深层网络训得动。

## 6. 代码 / 工具

### 6.1 最小 Self-Attention（NumPy）

```python
import numpy as np

def softmax(x, axis=-1):
    x = x - x.max(axis=axis, keepdims=True)   # 数值稳定
    e = np.exp(x)
    return e / e.sum(axis=axis, keepdims=True)

def self_attention(X, Wq, Wk, Wv, causal=False):
    """X: (n, d_model)；Wq/Wk/Wv: (d_model, d_k)。返回输出与注意力权重。"""
    Q = X @ Wq                                # (n, d_k) 查询
    K = X @ Wk                                # (n, d_k) 键
    V = X @ Wv                                # (n, d_k) 值
    d_k = Q.shape[-1]
    scores = Q @ K.T / np.sqrt(d_k)           # (n, n) 点积打分 + √d_k 缩放
    if causal:                                # 因果掩码：第 i 个词只看前 i 个
        n = scores.shape[0]
        mask = np.triu(np.ones((n, n)), k=1) * -1e9
        scores = scores + mask
    A = softmax(scores)                       # 每行和为 1 的注意力权重
    return A @ V, A                           # (n, d_k) 加权求和

n, d_model, d_k = 4, 8, 4
rng = np.random.default_rng(0)
X = rng.normal(size=(n, d_model))
Wq, Wk, Wv = (rng.normal(size=(d_model, d_k)) for _ in range(3))
out, A = self_attention(X, Wq, Wk, Wv, causal=True)
print(A.round(2))   # A[i] 就是第 i 个词对全句（受掩码限制为前文）的关注分布
```

对照公式读代码：`Q @ K.T / sqrt(d_k)` 对应 softmax(QKᵀ/√d_k) 里的打分与缩放，`A @ V` 对应最后的加权求和。

### 6.2 多头注意力（PyTorch）

```python
import torch
import torch.nn as nn

class MultiHeadAttention(nn.Module):
    def __init__(self, d_model=512, n_heads=8):
        super().__init__()
        assert d_model % n_heads == 0
        self.h, self.d_k = n_heads, d_model // n_heads
        self.wq = nn.Linear(d_model, d_model, bias=False)
        self.wk = nn.Linear(d_model, d_model, bias=False)
        self.wv = nn.Linear(d_model, d_model, bias=False)
        self.wo = nn.Linear(d_model, d_model, bias=False)

    def forward(self, x, causal=True):
        B, n, d = x.shape
        # (B, n, d) -> (B, n, h, d_k) -> (B, h, n, d_k)：拆多头
        q = self.wq(x).view(B, n, self.h, self.d_k).transpose(1, 2)
        k = self.wk(x).view(B, n, self.h, self.d_k).transpose(1, 2)
        v = self.wv(x).view(B, n, self.h, self.d_k).transpose(1, 2)

        scores = q @ k.transpose(-2, -1) / self.d_k ** 0.5   # (B, h, n, n)
        if causal:
            mask = torch.triu(torch.ones(n, n, dtype=torch.bool, device=x.device), 1)
            scores = scores.masked_fill(mask, float("-inf"))
        a = torch.softmax(scores, dim=-1)
        out = a @ v                                          # (B, h, n, d_k)
        out = out.transpose(1, 2).reshape(B, n, d)           # 拼回多头
        return self.wo(out)                                  # 输出混合

x = torch.randn(2, 10, 512)          # batch=2, 序列长 10, d_model=512
mha = MultiHeadAttention(d_model=512, n_heads=8)
print(mha(x).shape)                  # torch.Size([2, 10, 512])
```

### 6.3 玩具版 BPE：体会高频合并

```python
# 简化示意（真实实现基于字节流与更完整的统计），体会"高频对合并成词块"的思想
from collections import Counter

corpus = ["l o w ", "l o w ", "l o w e r ", "n e w ", "w i d e "]
merges = []

for _ in range(4):                          # 迭代合并 4 次
    pairs = Counter()
    for word in corpus:
        sym = word.split()
        for a, b in zip(sym, sym[1:]):      # 统计相邻单位对频次
            pairs[(a, b)] += 1
    if not pairs:
        break
    best = pairs.most_common(1)[0][0]       # 最高频的一对
    merges.append(best)
    corpus = [w.replace(" ".join(best), "".join(best)) for w in corpus]

print(merges)   # [('l', 'o'), ('lo', 'w'), ...] 高频字符对逐步合并成词块
```

## 7. 案例

### 案例 A：长文档摘要的路径选择

**场景**：某内容平台要给 2 万字中文长文自动生成摘要，初版直接把全文塞进 128K 窗口的模型。

**问题与复盘**：单次调用成本约是切片方案的 6 倍；且实测发现摘要漏掉全文中段的整节内容——上下文够长不等于每个位置都被用好（该现象在 0.5 与 1.5 展开）。改造为"章节切分 + 分节摘要 + 归并"的两级流程后，中段信息覆盖率明显回升，单次成本降到原来的 1/5。结论：**窗口是上限，不是质量保证**。

### 案例 B：中文 token 效率与账单

**场景**：某 SaaS 客服系统对比两家模型，同一段中文问句，A 家切 300 token、B 家切 900 token。

**效果**：按输出长度相近估算，仅输入侧月账单就差约 3 倍。对策：选型时把"中文 token 效率"列为硬指标，用分词器实测典型对话语料的 token 数；上线后按 token 计数做预算告警。教训：**模型单价低不等于账单低，token 数也是价格的一部分。**

### 案例 C：把 8K 训练长度的模型用到 32K

**场景**：某金融科技公司持有训练长度 8K 的开源底座，业务要求单次处理 32K 合同文本。

**三条路线的取舍**：位置插值（PI）微调——需准备长文本微调数据与算力；换官方长上下文版本——最快但评估不可省；切片检索（RAG）——工程最轻，但牺牲全文级推理。最终选官方长上下文版本 + 答案必须引用原文段落做校验。结论：**外推不是免费的，窗口外的能力要靠评估验证。**

## 8. 常见坑

1. **把 token 当字数估算成本**。中文 1 字约 0.6~1 token，直接按字数估会低估；用分词器实测。
2. **忽视各家词表差异**。同一段话在不同模型 token 数可差数倍，比价必须连同 token 效率一起比。
3. **把 √d_k 缩放的原因说成防溢出**。真实机制是"点积方差随维度增大 → Softmax 饱和 → 梯度消失"，面试失分高发点。
4. **混淆 Self-Attention 与 Cross-Attention**。本质区别只在 QKV 是否同源：Cross 的 Q 来自解码端，K/V 来自另一序列。
5. **以为 RoPE 也旋转 V**。RoPE 只旋转 Q 和 K，把相对位置藏进内积；V 只负责携带内容。
6. **实现解码器时不加因果掩码**。评估指标虚高——模型偷看了未来 token，生成时立刻崩。
7. **以为 Encoder-only 模型能做对话生成**。BERT 式双向模型是理解与嵌入用的，生成要因果架构。
8. **把上下文窗口当成均匀记忆**。窗口内头尾强、中间弱，关键信息要放头尾（0.5/1.5 展开）。
9. **忽视 O(n²) 的成本放大**。序列翻倍，注意力计算约 4 倍；长上下文方案必须先算这笔账。
10. **以为位置外推免训练**。PI 需要少量微调，NTK-aware 也非零成本；"直接把 8K 模型用到 128K"会严重掉点。
11. **只看参数量不看架构**。同样是 Decoder-only，是否用 GQA/滑动窗口直接决定长文本的显存与延迟。
12. **认为应用开发不需要懂分词**。计费、窗口预算、数字切分陷阱、数数不准，全都要用 token 意识解释。
13. **混淆 token 数与显存占用**。窗口长度直接决定 KV Cache 显存与注意力计算量，"128K 窗口"不等于任何硬件都能跑满；容量规划在 3.6b 展开。
14. **把注意力权重当因果证据**。单层注意力热力图只是线索，多层残差会重新加权信息流；可解释性结论要配合消融实验，不能只看图。

## 10. 小结

- 模型的输入单位是 **token**：BPE 用"高频合并"切出子词，token 数同时是计费与窗口的计量单位。
- Transformer 的灵魂是 **Self-Attention**：`softmax(QKᵀ/√d_k)·V`——投影、打分、缩放、归一聚合四步。
- **÷√d_k** 的原因是：点积方差随维度增大 → Softmax 饱和 → 梯度消失；缩放把方差拉回约 1。
- **多头注意力** 把维度拆成 h 份并行，让模型同时学多种关注模式，总成本近似单头。
- 注意力天然无序，**位置编码**补词序：正弦 → 可学习 → RoPE（旋转 Q/K，内积携带相对位置，当前主流）。
- 三种拼法：**Encoder-only 管理解、Decoder-only 管生成、Enc-Dec 管序列到序列**；主流 LLM 是 Decoder-only。
- 注意力是 **O(n²)**：长上下文的优化地图 = 结构近似 + FlashAttention + KV 压缩（MQA/GQA/MLA）+ 位置外推（PI/NTK/YaRN）。
- 窗口是上限不是质量保证：长文档摘要、成本、可靠性要靠切片与 RAG 工程化解决。
- 多头不是越多越好：h 增大则每头 d_k 变小，过多会把表示空间切碎；头数是和 d_model 联动的超参。
- 这套机制直接支撑后续：0.5 LLM 行为、0.7 嵌入、1.1 选型、1.5 上下文管理、3.7/3.7b 推理优化。
