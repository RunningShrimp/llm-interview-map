## 1. 定位

L0 基础层第 1 个锚点，对应大纲核心问题：**向量、矩阵、概率、损失函数分别解决什么？**

掌握档位是「了解-理解」：不要求推导公式，要求对每个概念说清三件事——它解决什么问题、在大模型里出现在哪、在代码里长什么样。

四个问题对应四块内容：

| 问题 | 概念 | 在大模型里的位置 |
|---|---|---|
| 文字怎么变成可计算的数 | 向量 / 矩阵 | Embedding（0.7）、注意力（0.4c） |
| 输出的把握与多样从哪来 | 概率 / 采样 | 解码参数 temperature / top_p（1.1b） |
| 学得好不好谁说了算 | 损失函数 | 预训练、SFT、微调的目标函数 |
| 亿万个参数怎么一起改 | 梯度下降 | 一切训练循环的更新规则 |

应用岗不考证明，但面试会问「为什么文字要转向量」「温度是干什么的」「交叉熵和 MSE 差在哪」。这三个问题都出自本篇。

## 2. 一句话定义

向量（Vector）是给文字或任何对象发的一串有含义的坐标数；矩阵（Matrix）是把这些坐标批量搬运、加工的变换表；概率（Probability）是模型对每个候选输出的把握分；损失函数（Loss Function）是给「错得有多离谱」打分的裁判；梯度下降（Gradient Descent）是沿着扣分下降最快的方向微调参数的更新规则。五者串起来就是 AI 学习的完整闭环：坐标进、概率出、损失打分、梯度改参数。

## 3. 为什么需要

AI 眼里没有文字，只有数字。三个硬前提决定了这五样东西缺一不可：

1. **计算机只会算术**。文字必须先编码成数，且编码要保留语义关系——这就是向量的任务。
2. **输出天然不确定**。同一个问题往往有多个合理答案，「北京明天几点日出」可以答 6:12 也可以答「清晨六点左右」。模型需要用概率表达把握与多样性，而不是给出唯一死答案。
3. **学习需要可优化的目标**。「答得好」必须量化成一个数，优化才有方向——这就是损失函数，配合梯度下降把「变好」变成可执行的机械步骤。

| 没有这套数学 | 有了这套数学 |
|---|---|
| 「开心」和「高兴」是两个不相干的字符串 | 两串距离很近的坐标，语义相似可计算 |
| 模型输出非黑即白的答案 | 每个候选带把握分，可采样、可控制多样性 |
| 「模型答错了」只是一句吐槽 | 一个标量损失，能算出每个参数该怎么改 |
| 改进靠人拍脑袋调规则 | 梯度下降几百万步自动逼近目标 |

一句话：**这套数学是把「智能」翻译成「算术」的桥。**

## 4. 核心原理

### 4.1 向量：文字的坐标

给朋友发奶茶店位置，发的是经度、纬度两个数——一个地点变成一串数字。AI 读文字同理：把每个词变成一串有含义的数（向量）。妙处在距离：**「开心」和「高兴」坐标挨得近，「开心」和「卡车」隔得远**。意思的远近变成了坐标的远近，语义理解就变成了几何计算。

衡量两个向量像不像，常用三种距离：

| 度量 | 直觉 | 特点 | 典型场景 |
|---|---|---|---|
| 欧氏距离（Euclidean） | 两点直线距离 | 对绝对位置敏感，通常先归一化再用 | 聚类、可视化 |
| 点积（Dot Product） | 对应位相乘再求和 | 计算最快，值越大越像 | 注意力打分（0.4c）、召回粗排 |
| 余弦相似度（Cosine Similarity） | 两方向夹角，不管长度 | 只看方向，抗向量长短差异 | 语义检索（0.7、1.4） |

在大模型里的位置：Embedding 层把每个 token 的编号查表变成向量（这就是「文字的坐标」）；整段文本也能压成一个句向量，用于向量检索——0.7 的「语义坐标」就是本节的直接应用。

### 4.2 矩阵：批量执行的变换

矩阵乘向量，本质是对一组数做一次线性加工（旋转、缩放、混合）。矩阵乘矩阵，就是把这个加工批量套在好几组数上。大模型的参数，绝大部分就是一堆这样的矩阵（权重矩阵）：一个 7B 模型，约等于 70 亿个矩阵元素，每个都是训练时被梯度下降微调过的数。

注意力机制完全是矩阵乘法（0.4c 逐项拆）。输入序列 X（n 个 token，每个 d 维）经过三个权重矩阵得到 Q、K、V，再算注意力：

```text
Q = X·W_q        K = X·W_k        V = X·W_v
Attention(Q, K, V) = softmax( Q·K^T / √d_k ) · V
```

每一步的维度变化：

| 对象 | 形状（shape） | 含义 |
|---|---|---|
| X | n × d | n 个 token，每个 d 维向量 |
| W_q / W_k / W_v | d × d_k | 三个可学习的投影矩阵（参数所在） |
| Q、K、V | n × d_k | 查询、索引、内容三套向量 |
| Q·K^T | n × n | 每对 token 之间的相似度打分表 |
| 最终输出 | n × d_v | 每个 token 按相关度加权混合后的新表示 |

面试常说「注意力就是加权的向量混合」，它的数学底子就是：**打分靠点积，加权求和靠矩阵乘法**。

### 4.3 概率：把握度与采样

天气预报说「降雨概率 80%」，不是保证下雨，而是十次里大约八次。模型输出同理：每个候选 token 都带一个把握分。模型内部先给词表上每个词打一个原始分（logit，可正可负的任意实数），再用 softmax 把一排分数压成和为 1 的概率分布：

```text
softmax(z)_i = e^(z_i) / Σ_j e^(z_j)
```

温度（Temperature）在 softmax 里除一个系数 T，控制分布的尖平：

```text
softmax(z / T)_i
```

| 温度 T | 分布形态 | 生成行为 | 适用场景 |
|---|---|---|---|
| T → 0 | 极尖，几乎只剩第一名 | 贪心解码，每次输出一样 | 抽取、分类、代码、SQL |
| T = 0.2–0.5 | 偏尖 | 保守稳定，偶尔微调 | 客服问答、摘要、工单 |
| T = 0.7–1.0 | 适中 | 平衡流畅与稳定 | 通用对话默认档 |
| T > 1.2 | 偏平 | 多样甚至跳脱，低概率词被放大 | 创意写作、头脑风暴 |

两个关键认知：

1. **训练和推理用概率的方式不同**：训练时用交叉熵直接对齐目标分布（见 4.4）；推理时按概率采样（或贪心取最大），「偶尔选低把握的词」就是模型有时惊艳有时胡说的来源之一。
2. **概率不是确定**：模型说 0.9 的把握，仍然有十分之一的可能错。这直接解释幻觉（0.5d）——似真不等于为真。

### 4.4 损失函数：交叉熵 vs MSE

射箭时箭离靶心越远扣分越多。损失函数就是裁判：拿模型输出和标准答案一比，按差多远打一个分。训练的一切目标就是让这个分一路下降（0.3 会看到，降损失的过程就是训练本身）。

两大常用裁判：

| 维度 | MSE（均方误差） | 交叉熵（Cross-Entropy） |
|---|---|---|
| 任务类型 | 回归：预测连续数值 | 分类 / 下一词预测 |
| 模型输出 | 一个实数或实数向量 | 概率分布（softmax 之后） |
| 计算方式 | 预测减真值，平方后取平均 | 真实类别的负对数概率 |
| 惩罚特性 | 错得越离谱罚得越狠（平方放大） | 对「自信地答错」罚得极狠（概率趋 0 时损失趋无穷） |
| 典型场景 | 房价预测、温度预测、打分 | LLM 预训练与 SFT、图像分类 |
| 和输出层搭配 | 线性输出即可 | softmax / sigmoid 输出 |

交叉熵对一个样本的直观形式：

```text
Loss = -log( 模型分给正确答案的概率 )

正确答案概率 0.9 → loss ≈ 0.11（罚得轻）
正确答案概率 0.5 → loss ≈ 0.69
正确答案概率 0.01 → loss ≈ 4.6（罚得重）
```

LLM 用交叉熵而不用 MSE，核心原因有三条：

1. **输出形态匹配**：LLM 的输出就是词表上的概率分布，交叉熵直接度量「预测分布」和「真实分布（真词为 1 其余为 0）」的距离。
2. **梯度性质好**：softmax + 交叉熵组合的梯度形式简洁（预测概率减真实概率），配合 softmax 不易饱和；而 sigmoid/softmax 输出配 MSE，在输出严重错误时梯度反而变小，学习极慢。
3. **罚自信的错误**：MSE 罚「差得远」，交叉熵罚「错得笃定」——语言模型最该避免的是自信地选错词。

### 4.5 梯度下降：蒙眼下山

损失是一个标量，参数有几亿个，怎么改？把损失想成一片山地，高度是损失、位置是参数取值。目标是走到谷底（损失最低）。蒙眼登山者看不见全景，只能用脚感受「哪边下坡更陡」——这个方向的反方向就是负梯度。更新规则一行：

```text
θ_new = θ_old − 学习率 × 损失对 θ 的梯度
```

- **梯度（Gradient）**：损失上升最快的方向；取负号就是下坡方向。
- **学习率（Learning Rate）**：步长。太大，一步跨过谷底来回震荡甚至发散；太小，收敛慢到不可用。
- **批量（Batch）**：每次用一小批数据估梯度（mini-batch），不必全量数据算完才走一步。
- **收敛（Convergence）**：越靠近谷底坡越缓、步子自动变小，损失曲线趋平——训练日志里 loss 不再降，就是「学得差不多了」。

## 5. 架构 / 流程

一次训练迭代中，五个概念按固定顺序接力：

```text
输入：token 序列（比如「今天天气 真」）
        |
        v
[嵌入查表]  token id --> 向量                  <-- 向量
        |   （每个词拿到自己的坐标）
        v
[几十层矩阵变换]  Q/K/V 投影 + 注意力 + 前馈    <-- 矩阵
        |   （向量被反复线性加工、混合信息）
        v
logits：词表上每个词的原始分数（可正可负）
        |
        v
softmax(± 温度) --> 概率分布                    <-- 概率
        |   （"真" 0.62，"的" 0.21，"好" 0.08，...）
        v
与标准答案（"好"）对比 --> 交叉熵损失（一个标量） <-- 损失
        |   （-log(0.08)，罚得不轻）
        v
反向传播：损失对每个参数求梯度（谁该背多大责任）
        |
        v
梯度下降更新：θ <-- θ - 学习率 x 梯度
        |
        v
下一批数据，重复几百万次 --> 损失一路下降 = 学会
```

推理（生成）时走的是同一条流水线的上半段：嵌入 → 矩阵变换 → logits → softmax，然后按概率采样一个词，拼回输入再走一遍——逐字接龙（3.7 讲它为什么慢）。

## 6. 代码 / 工具

### 6.1 numpy 向量运算与相似度

```python
import numpy as np

# 假想的三维语义空间：每个词一个向量
vectors = {
    "开心": np.array([0.9, 0.8, 0.1]),
    "高兴": np.array([0.85, 0.82, 0.12]),
    "卡车": np.array([0.1, 0.2, 0.95]),
}

def cosine_similarity(a: np.ndarray, b: np.ndarray) -> float:
    """余弦相似度：只看方向，不看长度。范围 [-1, 1]。"""
    return float(np.dot(a, b) / (np.linalg.norm(a) * np.linalg.norm(b)))

def euclidean(a: np.ndarray, b: np.ndarray) -> float:
    """欧氏距离：两点直线距离，越小越像。"""
    return float(np.linalg.norm(a - b))

for other in ["高兴", "卡车"]:
    print(f"开心 vs {other}: "
          f"余弦={cosine_similarity(vectors['开心'], vectors[other]):.3f}, "
          f"欧氏={euclidean(vectors['开心'], vectors[other]):.3f}")

# 向量加法： king - man + woman ≈ queen 的经典演示原理
# 语义关系变成坐标运算——方向相同的关系，向量差也相近
rel = vectors["开心"] - vectors["高兴"]   # 同义词之差接近零向量
print("同义词差的模长:", np.linalg.norm(rel))
```

运行可见：「开心-高兴」的余弦相似度接近 1、距离很小；「开心-卡车」两个指标都明显拉开。这就是语义检索按距离排序的数学内核。

### 6.2 softmax、温度与交叉熵

```python
import numpy as np

def softmax(logits: np.ndarray, temperature: float = 1.0) -> np.ndarray:
    """带温度的 softmax。减 max 是数值稳定技巧（防 e 溢出），不改变结果。"""
    z = (logits - logits.max()) / temperature
    e = np.exp(z)
    return e / e.sum()

logits = np.array([2.0, 1.0, 0.5])   # 假设对应 ["好", "的", "真"]

for t in [0.5, 1.0, 2.0]:
    p = softmax(logits, temperature=t)
    print(f"T={t}: " + ", ".join(f"{w}={x:.3f}" for w, x in zip(["好", "的", "真"], p)))

def cross_entropy(p_correct: float) -> float:
    """交叉熵损失：-log(分给正确答案的概率)。"""
    return float(-np.log(p_correct + 1e-12))   # 1e-12 防 log(0)

print("\n交叉熵随正确答案概率的变化:")
for p in [0.9, 0.5, 0.08, 0.01]:
    print(f"  p={p:.2f} -> loss={cross_entropy(p):.2f}")

def mse(pred: np.ndarray, target: np.ndarray) -> float:
    """均方误差：回归任务常用。"""
    return float(np.mean((pred - target) ** 2))

print("\nMSE 示例: 预测 [3.0, 5.0], 真值 [2.5, 4.0] ->", 
      mse(np.array([3.0, 5.0]), np.array([2.5, 4.0])))
```

观察输出：温度越低分布越尖（概率向第一名集中）；正确答案概率从 0.9 掉到 0.01，交叉熵从 0.11 涨到 4.6——错得越笃定罚得越狠。

### 6.3 梯度下降最小演示

```python
import numpy as np

# 一维山谷：损失 f(x) = (x - 3)^2，谷底在 x = 3
def loss(x):        return (x - 3.0) ** 2
def grad(x):        return 2.0 * (x - 3.0)     # 导数 = 梯度的一维版

x = 0.0             # 随机起点（半山腰）
lr = 0.2            # 学习率（步长）

for step in range(12):
    print(f"step {step:2d}: x={x:7.4f}  loss={loss(x):8.4f}")
    x = x - lr * grad(x)                        # 蒙眼下山：朝负梯度挪一步

# 试试 lr=1.1：步子太大，x 会在谷底两侧越荡越远——发散
```

这 12 行就是所有训练循环的骨架：真实训练只是把「一维 x、手写梯度」换成「亿维参数、反向传播自动求梯度」，更新规则一模一样。

## 7. 案例

### 案例 A：语义检索救回关键词搜不到的查询

某电商客服知识库原来用关键词匹配，用户搜「项目延期怎么汇报」，找不到标题为《进度风险沟通指南》的文档——没有一个字相同。把文档和查询都用嵌入模型转成向量、按余弦相似度排序后，「项目延期」和「进度风险」、「怎么汇报」和「沟通」在坐标上靠近，该文档进入 Top-1。内部评估 100 条真实查询，Top-3 命中率从 62% 提到 89%。这正是 0.7「语义坐标」的落地，而数学底座就是 4.1 的向量与相似度。

### 案例 B：一厂两温：同一模型的不同温度档

一家在线教育公司有两个 LLM 场景。工单分类场景用 temperature=0.2：输出稳定，同一条工单两次分类结果一致率接近 100%。灵感写作助手原来用 0.7，用户嫌「写得平淡」，调到 1.0 后候选多样化，编辑采纳率上升约 15%，但胡编概率也变高，于是加了事实校验兜底。结论写进了团队规范：**温度不是「创造力魔法旋钮」，而是「分布尖平旋钮」，按任务选档**（参数细节在 1.1b 展开）。

### 案例 C：从损失曲线反推训练问题

某团队微调一个分类小模型，看到三种曲线：损失上下大幅震荡不收敛——学习率太大，降到 1/10 后平稳；损失降到很低就卡平——学习率偏小或模型容量不足；训练损失一路降到 0.01、验证损失却先降后升——过拟合，正是 0.3 要展开的「背题」信号。会读损失曲线，等于拿到训练的第一只仪表盘。

## 8. 常见坑

1. **把向量当「随便一串数」**。向量每一位都有语义含义，距离才有意义；不理解这点就看不懂检索为什么能工作。对策：始终用「坐标与距离」的直觉检查设计。
2. **余弦相似度前没归一化**。未归一化向量混用点积和余弦，分数不可比。对策：统一归一化后用点积，等价于余弦且更快。
3. **忽视维度匹配**。矩阵乘法形状不匹配直接报错或悄悄错。对策：写代码前先在纸上标 shape（4.2 的维度表就是模板）。
4. **把温度当创造力魔法乱调**。温度只改变分布尖平，过高必然放大低质量候选。对策：按任务选档（见 4.3 表），重要场景配校验。
5. **把概率当确定**。模型输出 0.9 仍可能错，置信度不等于正确性。对策：下游设计按「可能错」来做——校验、兜底、引用来源。
6. **分类任务用 MSE**。概率输出配 MSE 梯度易饱和、学得慢。对策：分类一律交叉熵，回归才用 MSE。
7. **把 logits 叫概率**。softmax 之前是任意实数分数，不是概率。对策：术语上区分 logits 和 probabilities，排查 bug 时少走弯路。
8. **softmax 不做数值稳定处理**。直接 exp 大数会溢出成 inf/nan。对策：先减最大值再 exp（6.2 已演示）。
9. **学习率一刀切**。照抄别人的学习率，震荡或收敛慢。对策：从损失曲线诊断（案例 C），震荡减、卡平增。
10. **只盯损失不看业务指标**。损失降了，业务指标未必好。对策：损失是训练仪表盘，验收仍看任务指标。
11. **混淆温度与 top_p**。两者都控随机性但机制不同：温度改分布形状，top_p 截候选池。对策：一次只调一个，细节在 1.1b。
12. **把「损失降到 0」当目标**。训练集损失趋 0 往往是背题（过拟合）前兆。对策：同时看验证集表现，预告 0.3。

## 10. 小结

- 向量是文字的坐标：**意思近 = 坐标近**，语义计算因此变成几何计算。
- 相似度三件套：**欧氏距离、点积、余弦相似度**；检索场景默认余弦（或归一化后点积）。
- 矩阵是批量变换：LLM 的参数主要就是权重矩阵，注意力全程矩阵乘法。
- 注意力一行公式 **softmax(QK^T/√d)V**：打分靠点积，加权靠矩阵乘（0.4c 逐项拆）。
- 概率是把握度：softmax 把 logits 压成分布，**概率高不等于一定对**。
- 温度 T 控分布尖平：**低温稳、高温散**，按任务选档（1.1b 实操）。
- 损失函数是裁判：**分类用交叉熵、回归用 MSE**；交叉熵罚「自信地错」。
- LLM 选交叉熵的三个理由：输出形态匹配、梯度性质好、惩罚笃定错误。
- 梯度下降一行更新 **θ ← θ − lr·∇L**：学习率是步长，损失曲线是仪表盘。
- 这套闭环（向量→矩阵→概率→损失→梯度）在 0.3 会以 PyTorch 训练循环的形式完整落地。
