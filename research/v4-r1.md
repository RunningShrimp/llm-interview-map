## 1.3 结构化输出与 Function Calling

**锚点关键问题**（rodmap）：如何让 LLM 安全调用工具？｜建议掌握：会用

### 子知识点
- **[继承 n1，本轮大幅补强] Function Calling 工作流与训练原理**｜模型不是执行函数，而是输出结构化调用指令（JSON：工具名+参数）→ 程序拦截执行 → 结果回传；模型如何学会调工具（SFT 数据构造）。｜来源：题库——小林面试笔记《LLM 工具调用面试题》 https://xiaolinnote.com/ai/tools/tools_info.html 、卡码笔记《Function Calling 详解》 https://notes.kamacoder.com/llm/app/function_calling.html ；社区（一手面经）——知乎《美团大模型算法二面：Function Call 三连炮》 https://zhuanlan.zhihu.com/p/1898082753821515885 、牛客《AI 应用开发进阶面》 https://www.nowcoder.com/discuss/908750485325086720 ｜⭐4（v1 结论维持，来源从 2 条增至 6 条）
- **[🆕] FC 调用不稳定与校验/重试兜底**｜FC 幻觉参数、格式错误、调用失败时的 schema 校验、重试、系统设计兜底；权限校验由业务系统负责。｜来源：题库/博客——CSDN《Function Call 不稳定？系统设计才是关键》 https://adg.csdn.net/6953393e5b9f5f31781bea2f.html ；技术博客——matt33《LLM 系列：Function Calling 如何稳定调用工具》（2026-07-09） https://matt33.com/2026/07/09/llm-function-calling/ ｜🆕 建议 ⭐3-4（多来源一致，缺一手面经原贴，置信度中）
- **[🆕] 结构化输出 vs Function Calling vs JSON Mode 选型（含 constrained decoding）**｜三者的能力边界与适用场景；grammar/受限解码强制 JSON 是否取代 FC。｜来源：技术博客（旁证，非题库）——Vellum https://www.vellum.ai/blog/when-should-i-use-function-calling-structured-outputs-or-json-mode 、Agenta 结构化输出指南 https://agenta.ai/blog/the-guide-to-structured-outputs-and-function-calling-with-llms 、Towards Data Science https://towardsdatascience.com/structured-outputs-with-llms-json-mode-function-calling-and-when-to-use-each/ ；社区讨论——Reddit r/LocalLLaMA grammar vs FC 帖｜🆕 建议星级 ⭐2-3（英文教育内容密集但未见专属题库条目，作为 c5 的升级替换口径；c5 原「未经外部检索」状态本轮部分解除——获得选型类旁证，仍无中文题库直接出镜）
