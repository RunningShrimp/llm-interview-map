## 2.2 规划 Planning（薄弱区，本轮重点补强）
- **锚点关键问题**：如何把模糊目标拆成可执行步骤？
- **建议子知识点**：
  1. Plan-and-Execute 两阶段规划 ｜ Planner 先拆子任务+明确依赖生成计划，Executor 逐步执行，解决长任务"跑偏"与上下文膨胀 ｜ 来源：题库 JavaBetter《AI Agent 面试题第一弹：ReAct、Plan-and-Execute》13 题（javabetter.cn/sidebar/itwanger/paicli/paicli-interview-agent-core.html，2025，原文："先让 LLM 拆解成多个子任务并明确依赖关系，生成一份执行计划"）｜ ⭐4
  2. ReWOO（Reasoning WithOut Observation）｜ 规划阶段不看工具观察结果，Planner/Worker/Solver 三模块一次规划+批量执行，省 LLM 调用与 token ｜ 来源：社区 掘金《告别无脑循环：深入解析 ReWOO 与 Plan-and-Execute》（juejin.cn/post/7634383996970516516，2025）+ 官方 IBM《What is ReWOO?》（ibm.com/think/topics/rewoo，2025，均经外部检索，转述）；原论文 arXiv:2305.17559（内置知识标注，未检索核实）｜ ⭐3 🆕
  3. 🆕 重规划（Replanning）机制 ｜ "错误答案通常意味着错误计划"——Verifier 校验失败应回环到 Planner 而非重试 Executor ｜ 来源：官方 Hugging Face agents course 认证项目实践（github.com/yc1838/huggingface-agents-course-final，2025，转述）+ 官方 LangGraph Plan-and-Execute 教程（langchain-ai.github.io/langgraph，内置知识标注常见出处）｜ 🆕
- **机制讲解素材与可引用来源**（任务分解/计划生成/重规划三段式）：
  - 任务分解：Plan-and-Execute 拆解+依赖关系（JavaBetter 原文，见上）；多 Agent 场景下的结构化任务分解见论文 arXiv:2410.02189《Agent-Oriented Planning in Multi-Agent Systems》（论文，2024，经外部检索摘要）。
  - 计划生成：ReWOO 一次规划+并行执行（掘金/IBM，见上）；三范式对比口诀——ReAct 解决单步灵活性、Plan-and-Execute 解决长任务跑偏、Reflection 解决输出质量（题库 小林笔记《三种范式核心区别》xiaolinnote.com/ai/agent/6_three_patterns.html，2025，经外部检索转述）。
  - 重规划：Verifier→Planner 回环（HF 认证项目经验，见上）；Reflection 也可作为重规划触发器（知乎 2026 汇总）。
- **高频面试问法**：
  - 「ReAct 与 Plan-Act（Plan-and-Execute）范式的核心区别？」（IT周瑜《AI Agent 面试题》dadudu.tech，原文，经外部检索转述）
  - 「Plan-and-Execute 怎么解决长任务跑偏？什么场景该用 ReWOO 省 token？」（小林笔记+掘金 ReWOO 文议题，经转述）

## 2.9 Agent 评估与安全
- **锚点关键问题**：如何证明 Agent 可信、可控、可审计？
- **建议子知识点**：
  1. 轨迹级评估（trajectory-first）｜ 只看最终答案会漏掉工具调用错误；指标：task completion / step efficiency / argument correctness / tool correctness / planning quality ｜ 来源：社区 Confident AI《LLM Agent Evaluation Metrics in 2026》（confident-ai.com，2026，经外部检索）+ 官方 LangSmith Run/Trace/Thread 三粒度（v2 已核实）｜ ⭐4
  2. 🆕 复合失败率直觉 ｜ 单步成功率 95% × 8 步 ≈ 端到端仅 ~66%；先建立 baseline 成功率（很多"能用"的 Agent 实际 <60%）｜ 来源：社区 Future AGI《The Definitive Guide to AI Agent Evaluation》（futureagi.substack.com，2026）+ SkillGen 评估框架文（skillgen.io，2026，均经外部检索，转述）｜ 🆕⭐3
  3. 🆕 Agent 专项安全：Prompt Injection / 工具越权 / 沙箱隔离 ｜ Agent 能读私有数据、执行代码、改外部状态，故引入注入与越权新风险；考察已从背诵转向场景追问 ｜ 来源：题库 JavaGuide《LLM/Agent 安全实战》（2025，原文标题问题）+ 牛客《Agent 安全、护栏与权限治理面试问答》（nowcoder.com/discuss/916878391259717632，2025，经外部检索）+ 题库 Feei《AI 安全面试题目库》含 Multi-Agent 方向（feei.cn/sig/aisec，2025，经外部检索）｜ ⭐4 🆕
- **高频面试问法**：
  - 「Agent 相比 Chatbot 增加了哪些安全风险？」（牛客安全面经问答原文，2025）
  - 「Prompt Injection 怎么防？间接注入（经工具/网页内容进来的）怎么防？」（知乎《Agent 的安全防护面试题》议题 + JavaGuide 安全实战，2025）
